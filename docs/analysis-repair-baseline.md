# 有限校验反馈修复对照

日期：2026-10-06。模型为本地配置的 GLM-5.3-Flash，显式 low、JSON mode；提示词版本 2、切分版本 1。实现和评测均保持单章顺序窗口，结构校验不等同语义正确。

## 公开样例

同一三个公开样例分别关闭修复（0）和允许一次修复（1），每组每样例运行一次；默认窗口尺寸，max_requests=2、max_output_tokens=4096、单请求 65 秒、章节 600 秒。两组首次请求完全相同，只有允许的后续修复次数不同。

| 模式 | 样例 | 完整校验 | 归属正确单元 | 修复调用 | 输入 / 输出 token | 耗时 ms |
| --- | --- | --- | --- | --- | --- | --- |
| 关闭 | minimal | 通过 | 1/1 | 0 | 659 / 309 | 9080 |
| 关闭 | ambiguous | 通过 | 1/2 | 0 | 863 / 767 | 10025 |
| 关闭 | quoted | 通过 | 1/1 | 0 | 842 / 526 | 5886 |
| 开启 | minimal | 通过 | 1/1 | 0 | 659 / 298 | 3564 |
| 开启 | ambiguous | 通过 | 1/2 | 0 | 863 / 512 | 6360 |
| 开启 | quoted | 通过 | 1/1 | 0 | 842 / 490 | 5699 |

两组完整成功率及首次成功率均为 3/3，归属均为 3/4，表达类型覆盖均为 157/157 字节，确定归属单元均正确 2/2；关闭组其余两个单元均 ambiguous，开启组均 unknown。三个样例的保存正文与公开快照逐字节相同。

六次调用没有结构或引用失败，因此实际修复成功率没有分母，不能记作 100% 或 0%。两组耗时及输出差异来自独立生成与服务波动，不能归因于修复机制；也不能用语义差异证明修复有效。尚无统计显著性或质量门槛结论。

## 私有首章

使用已授权的《蛊真人》首章快照，保持 1000 字符窗口、128 个目标片段上限、max_requests=8、每请求 16384 输出 token、240 秒请求超时，章节时限显式调为 1200 秒。该配置用于维持此前四窗口对照，不代表默认 24 片段窗口的运行成本。

| --- | --- | --- | --- | --- | --- |
| 关闭 | 通过 / 4/4 | 0 | 26609 / 25116 | 252143 | 2 |
| 开启 | 通过 / 4/4 | 0 | 26669 / 25841 | 259679 | 3 |

两组均覆盖相同 342 个片段，ID、范围及规范化正文 9766 字节完全相同，SHA256 检查和 CLI validate 均通过。关闭组 narration/speech/thought 为 293/44/5，resolved/unknown 为 18/31；开启组为 293/43/6，resolved/unknown 为 29/20。两组只有一个片段的表达类型不同，角色发现和归属亦有差异。

没有完整人工金标准，因此不报告首章归属准确率。两组未触发修复，角色数量和确定归属增多不能解释为修复改善；独立模型生成及其后续角色上下文存在波动。reasoning 明细最后一窗口均缺失，保留 null，不假定为零。

正文、候选及逐调用诊断只保存在被 Git 忽略的 runs 目录，不进入公开样例或报告正文。

## 受控引用错误回放

为验证真实 GLM 是否理解反馈，读取关闭组 minimal 的成功候选，人工删去 characters 声明，保留台词的临时角色引用。首次候选来自本地回放，没有新的远端生成；这是人工注入的引用错误，不计入自然失败率。

程序产生 undeclared_identity，位置为 /segments/1/attribution，附带原输入的可信目标 ID；正式角色上下文仍为空。GLM 接收原窗口、失败候选和问题反馈后，一次远端修复即返回完整有效候选；归属为 1/1 正确，表达类型覆盖 27/27 字节。该调用输入 965、输出 298 token，远端耗时 3766 ms，完整回放 3768 ms。

统计 requests=2、repair_requests=1、repaired_windows=1，其中首次本地回放的 usage 全部 null；因此不能将整个回放的 token 汇总当作已知值，实际新增远端调用只有一次。本例验证反馈协议与真实适配器链路，不代表稳定恢复率。

本轮共 15 次远端调用：公开样例 6 次、私有首章 8 次、受控修复 1 次。自然对照的 14 次生成均通过候选校验，8 个分析运行全部完整成功，没有被隐藏的自然失败或追加重跑。当前证据支持“有限修复机制可工作”，尚不能推断自然失败恢复率或语义准确率提高。

## 验证边界

75 个 workspace 测试和 1 个 doctest 通过；fmt、Clippy、rustdoc 及 OpenSpec 严格校验通过。离线模型测试覆盖语法及结构反馈恢复、引用错误恢复、连续失败、关闭修复、后续窗口预算预留、总章节时限、取消、反馈候选省略、未知合法、旧统计兼容，以及失败状态与人工确认隔离。CLI 本地 HTTP 测试验证两次调用的统计、配置与发布边界。

真实评测使用独立的忽略目录诊断包装器，记录安全逐调用计量，以便失败也计入报告；生产 library 的失败返回仍为错误，不附完整失败统计。读取使用 scripts/evaluate-baseline.py，运行产物在 runs/repair-{off,on}-{sample}-v2；私有逐调用文本没有进入 Git。
