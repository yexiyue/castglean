# 归属规则与独立评测基线

日期：2026-10-06。本报告对应 `attribution-evaluation-baseline`，只建立政策、语料与独立测量，未改变生产提示词版本 5、模型协议、Rust 公共 API 或程序接受条件。

## 规则与复现

规则见 [标注政策 v1](annotation-policy.md)，入口见 [评测用法](attribution-evaluation.md)。40 个原创场景分为开发 20、留出 20，十类各四例，每例最多四个人物。正文、角色表、金标、划分和元数据在调用前保存到 [冻结清单](../evaluations/attribution-v1/freeze.json)。历史六例及历史报告保持为单独回归组。

两后端各运行全套两轮，共 160 次计划章节分析。每轮打乱执行顺序，种子 42，两后端采用相同顺序，每个后端串行，无额外网络重试或后端回退。金标、评测元数据和类别不作为模型输入。通过现有 CLI 重新验证产物，再用最终评分器复算全部结果。

共同预算：窗口 1000 字符 / 8 片段，每章最多 8 请求，每窗口一次修复，请求 120 秒、章节 600 秒；本地输出 2048 token，MiniMax 输出 8192 token。沿用默认切片 160 字符、上下文 3 片段、输入 128000 字节、响应 256000 字节。

本地 17 次失败：截断 6、服务错误 9、修复耗尽 2；MiniMax 4 次均为修复耗尽。失败均未发布目录。已观察本地请求 68 次、输入/输出 62562/48444 token；MiniMax 请求 85 次、输入/输出 69577/77754 token。这只覆盖成功章节收到的响应，包括拒绝后修复的响应；失败章节的完整成本未知，总用量保留 null。

本地章节耗时合计 2678.501 秒，平均 33.481 秒；MiniMax 合计 765.097 秒，平均 9.564 秒。两项都包含失败和修复，不能将成功章节用量与所有章节延迟混为单次模型调用成本。

## 如何解释结果

格式交付只表示正文、引用和完整覆盖有效。联合分数还要求表达类型、归属状态及章内身份一致；角色表指标另行检查没有发言但被提及的人物。不能以对白大致正确替代角色表完整。

新基线与历史六例的数据和身份评分口径不同，不能跨组计算提示词“增幅”。两个后端输出预算和输出协议也不同，本结果只描述这组固定运行条件。

`partial` 是冻结身份对齐规则拒绝某些边的诊断，不自动等于语义错误，也不自动获得正确分。例如 MiniMax 第二轮 `anonymous-04` 使用原文中的“递水的女孩”，v1 允许称呼仅包含“女孩”；`same_name-02` 的老师证据落在另一次“老师周宁”提及，而 v1 提及选定了较早范围。复核已确认这些元数据不足，见 [v2 勘误](attribution-evaluation-errata.md)。v1 的严格分数保持不变，v2 单独冻结，未调用模型，也没有用现有产物重算更高得分。

相反，第一轮 `same_name-04` 生成“小田（第一人）”“小田（第二人）”，后缀没有原文依据，违反称呼规则；第二轮又将明确有限候选判成 unknown。这与上述对齐边界不同，应独立说明。

MiniMax 还遗漏了仅被提及的送信人、乘客等人物；四次失败均为有限修复后仍不能满足目标或身份引用要求。所有失败完整计入，未发布的章节用量未知，不将其成本视作零。输出 token 使用服务返回计数；单独 reasoning token 未提供时保持 null。

Qwen 在留出集中把四个 unknown 表达全部确定给人物（两个场景各两轮），并有两次将有限候选强行确定。`explicit-04` 忽略后置“这是陶宁发出的命令”，新建未知说话者；`anonymous-04` 为两个真实人物生成五个身份；`thought-04` 将思想错误地扩展或改成外部发言。书名、牌面场景也出现额外人物。其 44 个额外身份和 36 个遗漏包含严格对齐拒绝，须结合逐次诊断，不能全视作真实幻觉数量。

上述来源与类型错误在两轮重复出现，说明格式约束和合法引用不足以保证归属。服务错误只记录适配层安全分类，不能凭这些记录进一步断言是网络、显存或模型能力导致。

## 后续决定

下一轮首先使用已勘误冻结的 v2，避免已确认的对齐元数据缺口。根据留出集已观察到的来源错误、无依据命称和角色表问题，建议做可验证原文引文的有限实验，先验证人物锚点及归属提示语，复用固定流程与有限反馈；另行处理本地交付失败，不把引文机制当作服务稳定性修复。

引文存在只能证明文本被引用，不能证明归属推理正确。下一轮必须再次测量类型、归属、角色及交付成本；本轮没有证明引文机制或 Agent 会提高准确率，也没有实现它们。TRNovel 集成仍在独立能力验证之后。

## 验证与产物

27 项 Python 离线评分/运行测试覆盖正确和错误构造、预算、取消、失败分母及版本勘误，已加入 Windows/Linux CI。Rust workspace 89 项测试和 2 项 doctest 通过；两个评测版本的全部金标均通过 Schema 与应用校验。fmt、Clippy（拒绝警告）、rustdoc（拒绝警告）及 OpenSpec 严格校验通过。

完整清单、正文和模型产物位于忽略的 `runs/attribution-v1`。公开报告只保存指标、执行顺序、摘要、安全错误及配置；两端均核对生产代码指纹未变化。v2 是同一组 40 个原创场景的元数据修正版，不是额外模型实验或额外原创场景。
