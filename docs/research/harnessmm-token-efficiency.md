# HarnessMM 调研：减少 agent 的重复推理回调

2026-11-09 修订。论文：[arXiv:2610.32813v2](https://arxiv.org/abs/2610.32813v2)（2026-11-06）；[当前仓库说明](https://github.com/YuhuaJiang2002/HarnessMM)。本地参考克隆 `/Volumes/yexiyue/HarnessMM`，核对提交 `8c4ff0f98332fab2dca5916dee63970d87c554e6`；不同版本和adapter的约束不能混作同一个协议。下述论文结果没有本地复现，不能推算CastGlean的收益。

## 机制及适用边界

HarnessMM将模型已经确定的后续动作、字面量参数、依赖和guard保存为可执行决策图。真实工具结果满足条件时，控制器通过原生工具接口执行既定动作；需要新判断或条件不可求值时回到模型。RSI使用训练反馈搜索提示词、上下文及adapter配置，经验证集选择后冻结，不改变模型权重。

| 机制 | 作用 | 参考实现 |
| --- | --- | --- |
| EDG | 记录已决定的动作、参数、依赖和guard | `integrations/deepseek_harness/cot_jev.mjs` |
| GDR | 根据真实回执判断是否能继续复用 | `sar_v2.mjs` 的 `PersistentBank` |
| CCS | 原生执行并记录被绕过的推理边界 | `sar_v2.mjs` 的 `ExecutableSubdag` |
| RSI | 离线配置搜索、验证选择和冻结 | `harnessmm/learning/` |

可执行参数合法不等于语义正确。论文附录D.2明确区分字面量闭合和语义闭合：guard通过不提供任意任务逐状态正确性的保证。证书证明执行了什么、哪个模型回调没有发生；不能证明被省略请求会如何回答或消耗多少token。

## 源码核对

1. **guard按adapter区分。** 该提交的`receiptGuard`只接受`return_code`、`stdout_contains`、`stdout_equals`；`localGuard`另支持`stderr_empty`和`json_equals`。`PersistentBank.prepare`发现任一候选guard不可求值时整组defer，即使别的候选看似可用；不能把这一策略泛化到所有adapter。receiptGuard拒绝非零退出；localGuard依赖声明的guard、必需字段与原生错误标志，不能泛称所有adapter有同一错误判定。
2. **准入阈值不是通用结论。** `PersistentBank`要求链深至少3、bank最多8192字节；`deterministicAdmission`另有1024 token净节省估计阈值。后者使用先前调用和字节估算，源码注明并非保证上界，不能直接移植为产品限额。
3. **证书有明确范围。** `ExecutableSubdag.observeTool`核对工具名、参数摘要、真实回执及期间没有插入慢速请求；只认证这一执行边界，整任务质量与成本仍需成对实验。
4. **计划历史压缩属于特定实现。** `PersistentBank.compactSession`剥离发送历史中的`<CHISEL_PLAN>`块，并在控制器内存保留/重建bank。不能声称所有路径都不支付计划生成或传输成本。
5. **优化流程有基准适配成本。** learning目录包含按任务族定制的搜索、拟合和验证脚本；不能把RSI理解为无需人工设计、可直接用于小说语义的通用自改进。
6. **示例是合成演示。** `examples/guarded_reuse.mjs`不调用模型；演示通过不证明真实token节省。

## 作者报告的结果（未复现）

- HumanEval/Codex：98个任务，成功率90.82%不变，平均token由66.72k降至47.02k（29.54%）。
- HumanEval/DeepSeek Harness：成功率71.43%→85.71%，token由96.28k降至11.62k（87.93%）；这里DeepSeek是宿主harness名称，actor是Qwen3.5-4B，不能解释为DeepSeek模型自身收益。
- MBPP消融：完整方案比单次图少26.91% token，比保留模型回调少19.52%。集成方案的全部收益不能归因于单一机制。
- 当前仓库/论文v2还包含HarnessMM-V视觉任务实验；“只验证代码类基准”的旧表述已过时，但视觉和代码结果都不建立小说归属准确率。

执行比较应包含作者调用、选择器、结束回复、重试、回退及失败任务；离线训练/配置搜索和验证成本另报。跳过调用次数不能直接换算为实测节省token。收益来自同一任务集的完整执行比较，而非假设被省略请求的成本。

## 对CastGlean的判断

当前实现见[工程助手与专业任务](../knowledge/decisions/professional-ai-tasks.md)。不是所有工具结果都回到模型：章节归属分析的`finish_analysis`已原子声明人物、提交完整分区并校验完成，独立预审也有终态停止；分析完成后预审失败时会校验依赖并复用完成阶段。

本轮验证的优先项：

1. **委派受理后由宿主直接继续。** `check_splitting`/`analyze_chapter`已决定下一任务，不再调用父模型仅生成受理说明；宿主展示真实状态。不得把受理当成领域完成。
2. **分章原子提交。** 模型明确选择最终方案时，一次工具调用完成计算、校验、候选保存与结果引用，减少机械性的提交和结束回合。人工采用保持独立。
3. **批量规则试验。** 模型一次提供若干规则方案，宿主做确定性计算并返回有界摘要，随后由模型选择；不能仅按异常数量自动选最佳，更不能覆盖人工修正。
4. **完整任务成本。** 统一记录主助手、专业子Agent、预审、失败和重试的每次真实请求用量。当前已有失败分母与归属分析trace，但共享消息usage是最近一次请求值，不能当作多轮总量。

暂不把来源摘要当作完整缓存键。原文不变时，用户约束、规则、人工修正、章范围、人物身份、模型或实现仍可能变化；`ProposalContent`含工程/来源引用，不能跨工程原样复用。规则方案可作为建议重算，完整结果复用必须核对全部相关依赖，并允许用户显式要求重新分析。

40轮是归属分析防空转上限，不是正常调用次数。先测实际调用分布与重复步骤；不能用降低上限导致提前失败来声称效率改善。本次实验保持已有防空转与人工权限，不引入通用EDG、任意guard求值或自动提示词优化框架。

## 本次实验状态

已修正笔记并完成四组真实对照，见[工具收敛与效率验证](../desktop-studio/task-efficiency-validation.md)。旧分章工具及兼容路由已删除，正式采用批量只读试算、原子最终候选和直接交接。本轮自然语言全流程token减少33.9%、平均耗时减少46.9%，但收益主要在父Agent侧，分章子Agent自身token基本持平；仅直接交接组未获得总token收益。缓存命中变化导致未缓存输入反而增加，因此不据此推算费用节省。公开AI标签不冒充人工真值，私人小说正文及运行产物不入Git。
