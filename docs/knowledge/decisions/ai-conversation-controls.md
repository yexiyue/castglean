# 会话模型、上下文用量与默认限制

日期：2026-11-07。状态：已实现，宿主测试、类型生成、Clippy 与合成 IPC 浏览器验证通过；真实服务商与原生窗口交互未在本轮验收。适用 Rig 0.46、当前数据库 AI 会话及 React/Tiptap 界面。

## 决定

用户明确要求正常不设置模型上限，并可在对话中查看上下文与切换模型。旧 2000 字输入、8KiB 消息、4096 输出、8 次单轮/64 次累计请求、累计 512KiB 输入、24 次工具/64KiB 结果配额均已取消，统计继续保存。历史不再限制为 256 条或 128KiB；不静默压缩或截断。输入中的原文引用也不再被旧总请求字节数截断。

这些正常会话配额与数据结构保护不同：单条消息文档/助手正文 16MiB、模型历史投影/HTTP 传输 64MiB，以及既有取消、任务/网络超时、工具单次分页、并发和整数边界继续存在；不是模型上下文容量。模型实际窗口、计费与协议约束由服务商决定。

[模型配置](../../../src-tauri/src/llm/types.rs)增加可选 `contextWindow` 与 `maxOutputTokens`，默认分别为未知/不设置。旧配置缺省可读；窗口仅作显示元数据，不用于本地拒绝，输出参数变更推进请求修订并受租约保护。原生 Anthropic 必须有输出参数：Rig 对已知模型提供协议默认，未知模型别名可能需要用户填写；应用不再统一覆盖为 4096。探测请求仍用固定小输出以完成能力测试，与正常对话分开。

## 用量口径与模型切换

依据实际依赖源码及 [Rig 官方迁移说明](https://github.com/0xplaygrounds/rig/blob/main/MIGRATING.md)，`Usage` 缺失与零不同，输入已含缓存，输出已含推理。只保存归一化的 input/output/cached 计数，不存服务商原始响应。

[Output](../../../src-tauri/src/ai/output.rs)每次 completion 后覆盖当前助手的已有 usage JSON，更新版本并通过同一提交游标发布。新请求开始清除旧值。多轮工具循环显示最新请求，不能把各轮相加当作上下文；历史恢复沿用持久值。[消息流](../../../src-tauri/src/ai/stream.rs)在 usage 改变时发送完整消息，避免文本 delta 丢失元数据。

[上下文弹层](../../../src/components/ai-elements/context-usage.tsx)显示上次请求模型、输入/输出/缓存、输入＋输出与窗口比例；只有两项用量及对应修订下的容量都已知才计算百分比。未知显示未知，不拿字符数/累计请求/当前可见分页估算。切换目标模型后，上次请求仍按原模型标记；新的草稿尚未计量，数值不是“下一次请求预测”。

对话内手动选择直接授权后续请求的模型绑定，不再重复勾选。生成中也可预选下一模型，但运行中请求仍持有原绑定；停止后选择不被快照覆盖。后台配置修订变化仍明确确认，不因默认模型或配置发布暗中改变用户选择。草稿与历史不清空。
