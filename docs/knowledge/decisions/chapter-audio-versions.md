# 章节音频的局部重做与版本采用

日期：2026-11-23。适用：当前 CastGlean Tauri 2 桌面宿主与 React 工作台。状态：已实现，宿主、浏览器及 macOS 单章窗口与 Kokoro 实测通过；人工听感单列，见[变更验证记录](../../../openspec/changes/add-chapter-audio-redo-and-adoption/validation.md)。承接[整章生成优先决定](chapter-generation-first.md)中「紧接补齐的单章闭环」。

## 问题

章节音频以任务为中心：一次任务冻结分析版本、来源、模型组合与合成文本语义，冻结输入完全一致时才能续跑。用户修正一处归属或换一个音色后，原任务不能续，只能整章从头合成；失败任务中途改声音同样要全部重做。旧结果虽然保留，但没有办法回到，也没有「采用」的概念。[章节音频工作台决定](chapter-audio-workbench.md)把停顿、播放和导出都绑在单个任务上。

## 决定

- **版本即任务，不另建候选表。** 每次重做都派生一个新任务，沿用的单元作为该任务的已完成单元写入。状态机、进度、取消、续跑、启动恢复和播放计划全部以任务为中心，派生任务原样复用；「同一任务内不得混用不同输入」保持不变，因为派生任务冻结的是新计划。代价是每次派生都会写入一组新的单元行，个人单章规模下可以接受。
- **沿用判定依据原文范围与实际声音。** 来源任务与当前计划的后端、模型、合成文本语义和制作方式一致，且单元的原文范围、实际声音与空白标记完全相同、来源音频文件存在，才沿用。选择原文范围而不是单元序号或片段 id 作为匹配键：来源不可变且切分确定，归属修订或重新分析可能改变片段 id 和数量，但未修改片段的范围不变。目标归属可以不同（例如两个角色绑定同一预置音色），只要实际声音相同。
- **沿用产物是独立副本。** 派生任务目录内为每个沿用单元建立副本（同卷硬链接，失败回退复制），并签发新的媒体身份。任务目录自包含，启动恢复按 `(run_id, index)` 推导路径的逻辑不变；写单元时先写临时文件再改名，不会就地修改被硬链接的旧内容。
- **采用是版本级，至多一个当前采用版本。** 整章生成与按当前计划的局部重做成功后在写事务中复核归属和声音，一致才成为当前采用版本并让原版本让位；同输入重录的结果先待采用，由用户试听后采用或放弃。采用要求版本完整且与当前归属、声音一致。放弃只作用于待采用版本，任何决定都不删除音频。与当前计划不一致的当前采用版本仍是「当前」，但标记为需要重做，导出被拒绝。
- **停顿按锚定边界精确继承。** 派生任务建立时，把来源停顿的锚点（所在单元的结束字节）映射到新计划中结束字节相同的单元；映射成功且仍是安全边界的停顿写入派生任务的修订 1（不可撤销，因为它不是用户的编辑），其余舍弃并计数。这与「新计划不自动转移停顿」不冲突：未经沿用建立的全新任务仍不继承，派生任务只转移边界完全一致的停顿，不做位置推测。
- **发起请求按意图区分。** `chapter_audio_start` 接受续跑、新建（可带沿用来源）与重录三种请求，不保留旧的 `restart` / `resume_run_id` 参数。预检在给出沿用来源时返回可沿用与需重做的单元数及位置，只读、不建立任务。

## 落地中确认的非直观约束

- **SeaORM 从模型转可写对象时，未显式标记的字段不会写库。** 先改模型字段再 `into_active_model()` 不会保存采用状态，必须对可写对象显式 `Set`。现有的终态提交都是逐字段 `Set`，正是这个原因。
- **创建时间只精确到秒。** 同一秒内建立的版本按创建时间排序不稳定，章节状态与版本列表以插入顺序（`rowid`）作为次级排序。v12 → v13 迁移保留 v12 的时间与任务 ID 排序，避免同秒任务在升级时仅因排序变化而被替换。
- **空白单元没有音频文件。** 准备沿用副本时必须跳过空白单元，否则报写入失败。
- **迁移语句要与全新建库语句对齐。** v12 → v13 的迁移最初漏了创建「当前采用版本」的部分唯一索引，由迁移测试发现。
- **放弃正在试听的重录版本时停止播放。** 否则已丢弃的音频会继续播放。

- **打开的编辑器可以随版本失效进入只读。** 编辑器分别呈现只读与保存中。旧版停顿已保存时，编辑器不拦住关闭或发起重做。若用户仍有草稿，保留草稿和显式放弃入口。2026-11-24 在 macOS 原生窗口复现了错误状态拦住重做，修复经真实窗口与浏览器回归。
- **试听目标与采用目标分别表达。** 待采用版本只呈现一个决定入口，原片段与重录片段从同一原文范围定位并分别播放至段末。历史视图的主播放键匹配所看版本，默认播放与导出仍遵循采用状态。

## 验证

宿主：沿用判定、独立副本、启动恢复后的媒体登记、缺文件回退重做、重录的采用生命周期（待采用、采用、放弃、重放、重新采用先前版本、缺文件与未完成版本被拒）、停顿继承与舍弃计数、执行循环只把变化的单元送进引擎并按正文顺序拼接、v11/v12 逐级升级与唯一索引。前端：纯函数单测，以及浏览器夹具下的修正后重做、无可沿用单元、重录后就地决定、版本列表与重新采用。均见[变更验证记录](../../../openspec/changes/add-chapter-audio-redo-and-adoption/validation.md)。

## 未验证边界

主观听感、原生完整中英亮暗矩阵及其它平台未验；合成不保证重录结果与原音频不同；硬链接在 Windows 的行为未实测（失败时回退为复制）；版本删除、清理与磁盘预算、跨版本按单元拼装不在本决定范围内。
