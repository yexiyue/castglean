# 整章生成优先与助手交互方向

日期：2026-11-10。状态：用户已确定产品优先级，尚未实现章节音频。此决定替代“先做助手短试听切片、再做整章生成”的交付顺序；不改变现有人工保护和宿主边界。

## 已决定

下一项产品交付先把已经分析、已有角色声音绑定的一章生成完整音频。宿主按当前采用的分析和来源范围组织合成单元，解析旁白/角色绑定，按顺序调用 TaleChime 并保存结果。生成本身是确定性任务，不增加规划 Agent 或重分析回合作为前置。

最初只用一个已验证的后端/模型组合，支持该模型内的旁白和多角色音色。根据模型限制切分长片段，保留原文范围到实际执行文本及音频的映射；不修改原文，不将 500 字试声接口循环调用直接宣称为可靠章节生产。

已有分析不是保证所有内容都可直接合成：生成前核对覆盖/顺序、采用版本、未知或歧义、缺失绑定、资源和能力。待人工检查不等于必须逐句确认；存在阻塞时集中列出相关位置。未知/缺声只有用户明确选择回退策略后才使用旁白，保留原语义状态；不能默默猜测角色或换声音。

## 交付顺序

| 阶段 | 交付目标 | 完成边界 |
| --- | --- | --- |
| 第一优先：整章生成 | 已分析/已绑定章节 → 生成前检查 → 顺序合成 → 按章连续播放 | 完整覆盖且顺序正确；能看真实进度、取消、失败位置、来源和实际配置；已完成音频持久化，重开不自动重复生成 |
| 紧接补齐：单章闭环 | 失败单元显式重试、修正后按安全单元重做、保留旧结果、显式采用、章节 WAV 导出 | 修改一处归属或声音后能听见对应变化；导出检查缺口/过期，未完成不能假报整章成功 |
| 随后：助手与界面减负 | 同一生成用例接入工具，对话卡呈现进度/试听/生成信息，分歧卡采集决定 | 对话和直接按钮共用状态；不重写生成执行器，不强制用户聊天才能制作 |
| 后续 | 整书批量、暂停/恢复、读音与演绎、其他模型/后端 | 分别建立规格和质量/平台验收，不成为第一章前置 |

第一阶段使用现有工作台中的直接“生成本章”入口、任务状态和章节播放结果，具体名称与布局仍须实操验证；不先实现完整目标推进器、交互协议或全面换布局。底层领域用例可由未来工具复用，不要求第一阶段暴露全部工具。

## 助手长期方向

一个面向用户的制作助手调用领域工具：分歧可确认，生成进度在原工具卡更新，完成后直接播放和查看信息。分析/选角等需要推理的任务可用专业子 Agent；生成/拼接/播放等使用确定性能力。候选采用、保存绑定与实际生成分别表达。相关方案见 [assistant-guided-production](../../../openspec/changes/assistant-guided-production/proposal.md)，该变更排在章节生成之后，不是其前置。

## 交互待验证

用户认为风险主要在操作是否符合习惯；这是产品假设，不是已经完成的可用性结论。用真实整章任务验证：

- 用户能否找到“生成本章”，是否明白生成范围及使用的声音，不必理解任务/子 Agent。
- 缺少绑定或归属有分歧时，能否集中处理或明确回退，处理后回到原章，而不是被迫逐页找设置。
- 生成时是否可以继续阅读/切章，能否找到原任务的进度和取消；切换页面不改目标、不重放任务。
- 完成后能否直接连续听，并从听到的错误定位原文、看到声音与配置；先提供单元范围定位，不承诺字级对齐。
- 中断/失败是否能理解已完成与未完成的范围；后台进度不抢焦点、不刷屏、不伪造百分比。
- 比较直接操作与工具卡：完成步骤、绕路/求助、误操作、能否恢复位置；记录观察后再定布局，不预设所有用户更喜欢对话。

## 实施与验证边界

下一步实施前建立独立章节音频 OpenSpec，明确合成单元、冻结输入、文件发布、取消/重试、恢复和整章完整性；复用现有数据库、任务设施与引擎线程，不另建通用调度框架。第一阶段保留必要可靠性，不先承诺跨进程恢复引擎内部推理或自动重发收费请求。

现有声音绑定/设计/试听真实证据见[验收](../../desktop-studio/voice-binding-acceptance-2026-11-10.md)，不能代替整章正确性和听感验收。角色中心的撤回/忽略待办继续独立跟踪。采用公开短章验证正常、长片段、未知/缺声、失败、中断、重启及人工修正；实际听感、跨片段衔接和操作习惯分别记录。本轮仅更新文档与规划，没有生成实现或新验收结论。
