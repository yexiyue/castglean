# 模型设置与列表容量

日期：2026-11-11。状态：已实现，自动化与合成桌面浏览器验证；真实服务与原生窗口待验。

设置中直接用当前协议、地址及临时凭据查询，不要求先保存连接；已有连接可沿用系统凭据、替换或移除。查询不写入连接，失败保留草稿。连接编辑与列表分开显示，模型低频参数按需展开，测试仍分别保留真实结果。

服务商列表返回的容量不是统一契约。Rig 能解析部分 OpenAI 兼容服务与 Gemini 的容量；缺失时保持未知。新加入的模型可使用返回的上下文或输入上限作为可编辑窗口值；输出能力上限只展示，不自动写入请求参数。Gemini 的输入和输出限制分别定义，不能将两者相加当作已验证窗口。列表不代表模型测试通过。

验证：`llm::tests::listing` 覆盖三协议分页、失败保留与 Gemini 容量；`e2e/settings/llm-settings.spec.mjs` 使用合成 IPC 检查八组中英、亮暗与窗口尺寸，以及新建和已有凭据选择。真实厂商端点、真实凭据库和原生窗口仍需分别验收。实现见 [宿主查询](../../../src-tauri/src/llm/providers.rs)、[设置界面](../../../src/components/settings/llm-settings.tsx) 与 [规格](../../../openspec/specs/llm-connections/spec.md)。

## Magpie 档位（2026-11-11，已实现，可用档位自动化验证）

本机 Magpie `/v1/models` 的模型条目实际提供 `reasoning_levels` 和 `supported_reasoning_levels`：`antigravity/gemini-3.8-flash` 返回 low/medium/high，`codex/gpt-6.1-terra` 返回 low 至 ultra。Rig 列表归一化不保留这些字段；修复前 CastGlean 只对协议与精确模型 ID 查询内置能力目录，因此上述网关模型被误判为未知。Rig 0.46 的通用 Effort 不支持 ultra，不能只放开下拉框或把 ultra 静默映射成其他值。现已从 OpenAI 兼容列表读取明确声明的可编码档位，按协议、端点和模型身份保存；重新获取会更新已有模型，地址或凭据草稿变化清除旧声明，选中的档位失效时提示。运行租约冻结选择，`ultra` 暂不映射。自动化覆盖本地模拟列表、保存重读、请求编码及设置界面；真实 Magpie 模型推理和原生窗口仍待验。

用户决定暂不接入 `ultra`：当前任务使用低档即可，维持现有 Rig 支持范围，不为此维护补丁或专用编码路径。若未来实际任务需要更高档位，或 Rig 原生支持 `ultra`，再评估接入并验证真实请求。

## 连接保存回执（2026-11-14，进行中）

配置原子提交后还有凭据清理与回读，后续错误不能证明保存失败。宿主在提交后立即登记会话内操作回执；相同请求重放仅读取当前配置，复用身份但更改参数会冲突。回执只在进程内保存带随机盐的摘要，不保存凭据原文，数量上限 4096，重启后不可重放；前端在关闭窗口前提示未确认操作。读取连接列表不能验证密钥内容，也不能单独证明未知保存的结果。相关实现和验证边界见 [变更验收记录](../../../openspec/changes/unify-forms-theme-and-interactions/validation.md)。真实原生窗口与凭据库验收仍待完成。
