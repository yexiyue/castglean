# 首次使用引导与常驻说明书分离

日期：2026-11-14。状态：已实现（桌面引导层、设置内使用指南），浏览器预览不弹引导；真实桌面窗口验收已做（2026-11-15，macOS 隔离实例）。

## 背景

原「快速上手」是侧栏底部的常驻目的地，内容是首次使用的三步清单：导入章节、准备声音模型、确认存储位置。步骤状态由「工程有没有章节」「模型是否 Ready」动态打勾，于是导入完成后页面长期停留在侧栏里，已完成的两步变成过期勾选，与用户当前工程无关的说明每次都要被读到。这与 2026-11-14 刚收敛的「侧栏只放目的地」直接冲突：说明书不是目的地。

## 决定

- 删除常驻「快速上手」页面（`/start` 路由、`StartGuide` 组件与侧栏入口），不保留兼容跳转。
- 桌面端本地没有任何工程时，首页出现一次性引导层，只把用户带到「看到章节列表」这一步：没有工程指向新建工程，只有未完成导入的草案时指向继续导入，出现章节即判定引导完成。
- 引导可随时跳过；跳过与完成都由宿主持久化（`app-state.json`，`app_state` 模块），此后不再自动出现。
- 主流程说明移到设置内「使用指南」分区，常驻可复看，与首启状态无关。
- 浏览器预览不弹引导：没有文件选择与模型能力，任何首启引导都是假的。

## 取舍

- 不做引导到模型下载、声音绑定或音频生成：这些步骤跨度和时长不可控，卡在「下载中」不是 onboarding 该解决的问题；它们由模型中心、音色中心和工程内空态就近承担。
- 不用前端 `localStorage` 记录完成标记：项目分层规定前端只持临时 UI 状态，且判定依据必须只有一处。宿主用 `atomic_json` 原子写入应用配置目录，文件缺失或损坏按未完成处理，不阻断启动。
- 引导层与首页常规空态互斥，避免同一区域出现两块说明；跳过后回到常规空态，空态继续承担「还没有工程」的引导职责。

## 验证

- 宿主单测：缺失文件为未完成、写入后重启仍为已完成、损坏文件按未完成恢复。
- 前端单测：`firstRunStep` 按真实工程状态返回 new / draft / done。
- 浏览器回归：引导出现 → 跳过 → 刷新后不再出现；设置内「使用指南」入口可达；侧栏无快速上手入口；128 组页面×主题×语言×运行环境的布局检查包含新增的 `?settings=guide` 分区。
- 真实桌面窗口（macOS，隔离标识符实例、空数据目录）：首启出现引导层 → 点「跳过」→ 引导消失并回到常规空态，`app-state.json` 写入应用配置目录、`app_state_snapshot` 返回已完成；设置内「使用指南」四步与入口可达；亮色中文、暗色英文两套文案正确；侧栏只剩工程、音色中心、模型中心与设置。

## 未验证边界

- 引导随真实导入自动收尾（工程出现章节后写入完成标记）只在宿主命令层与浏览器回归验证，未在真实窗口走完整 TXT 导入到章节列表。
- 多实例并发写同一 `app-state.json` 未查；浏览器预览下宿主状态命令不可用，前端已按未完成处理并因非桌面不呈现引导。
- 引导层与空态的文案在真实用户那里是否成立未经可用性测试。
