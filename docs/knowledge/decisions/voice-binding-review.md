# 声音绑定、选角与会话配置审查

日期：2026-11-10。范围：以 `f4f3cec` 为基线的未提交工作区，覆盖已归档的 `bind-character-voices`、活动的 `restructure-character-center` 与 `session-reasoning-effort`。本记录描述代码审查和自动化验证，不代替活动变更中的原生桌面验收。

## 规范轴

- 角色中心读取失败不能呈现为空目录或保存失败；装载、失败和可用状态分开，失败保留已有草稿并提供重试，旧请求不能覆盖新请求。
- 领域查询和目录装配不归 IPC 适配器所有。`voice_binding/catalog.rs` 统一真实目录投影与解析；`query.rs` 聚合反向引用；`store.rs` 和 `profile.rs` 拥有事务与目标校验；`suggest.rs` 编排冻结/执行，`suggest/publication.rs` 和 `suggest/query.rs` 分别拥有发布与读取。
- 音色身份按字段比较；目录摘要按结构化字段编码，避免对象字段顺序和分隔符碰撞改变身份语义。
- 删除旧示例和旧全局建议界面后同步清理失效翻译；Vite 直接编译 `.po`，不保留重复的 CommonJS 翻译产物。侧栏不向无人读取的 cookie 写入状态。

## 规格轴

- 手动绑定和建议采用共用目录存在性校验；读取失效引用仍保留记录。画像写入也必须核对目标属于本工程且角色已确认。
- 库音色删除确认后重新查询引用；绑定发布和最终检查/删除共用 `VoiceState.binding_changes`。锁不跨确认弹窗，防止等待确认期间新增绑定被删除操作破坏。这是应用进程内的业务协调，不声称阻止用户从文件系统移除资源。
- `cast_voices` 必须出现在工程助手实际工具注册表中，成功受理后立即交接；分章、归属与选角互斥，不能在同一次运行受理两个专业任务。
- 角色别名随输入冻结。证据在受理事务中冻结为原始分析版本的来源摘要和 UTF-8 字节范围；执行在 blocking worker 中验证不可变正文并提取有界样本，不再查询当前归属。重试复制原输入，旧输入缺必要字段诚实失败，不引入兼容层。
- 按运行推理档位同时进入 Rig 原生 wire 默认值和分析 Generation，覆盖普通助手、分章与选角；非法档位进入正常失败收尾并释放执行名额。Retry 从原运行读取配置；Continue 带新用户消息，是新的交互轮次，可采用用户显式选择的新配置，在途执行仍不变。

## 库复用与边界

复用现有 SeaORM 的字段投影、批量查询、排序和单行查询，替代反向引用逐目标查询工程名、读取全部建议再挑选最新，以及绑定行重复读取。复用 Serde 的结构化编码、Tokio 异步互斥和既有 Rig 默认值装配；不引入新依赖、通用仓储 trait、第二套调度器或恢复系统。预置音色存在性仍按已编译目录解析，模型下载就绪单独决定能否试听。

抽象、封装、模块化、信息隐藏通过上述职责和最小重导出落实；没有为了缩短代码而隐藏事务、来源校验或人工采用边界。
