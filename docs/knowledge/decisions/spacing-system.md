# 间距尺寸体系：相对差距阶梯与密度轴分离

2026-11-17。用户确认采用；随 `introduce-spacing-system` change 落地，档位表与角色映射的现行版本见 [DESIGN.md](../../DESIGN.md)「间距档位」。

## 问题

应用全程使用 Tailwind 默认刻度，间距无 token 与角色定义：业务代码半档（`gap-1.5`、`gap-2.5`、`py-0.5` 等）约 30 处与整档混用，相邻档相对差距低于约 25% 感知阈值；同类关系取值不一致（渲染实测顶栏 44px / 侧栏品牌区 48px / fallback header 40px 三种栏高并存，同一顶栏内 Home 按钮 `mx-3` 而新建按钮 `mx-2`）；分组层级几乎全部由边线承担，间距未参与节奏。依据《Refactoring UI》布局与间距章节：不要逐像素试值，阶梯相邻取值差距不低于约 25%。

## 决定与取舍

- **阶梯按相对差距选取，不要求线性倍数。** 初稿提案曾把顶栏从 44px 升到 48px（16 的倍数），用户否决「尺寸体系要线性/16 倍数」的思路：44→56（章节 header）相差 27% 符合阶梯，而 48→56 只差 17% 反而违规。结论：顶栏维持 44，侧栏品牌区 `--app-header-height` 从 3rem 降到 2.75rem 与之平齐。
- **间距轴与控件密度轴分离。** `src/components/ui/` 组件库保持 shadcn 上游内边距与按钮 `h-6/7/8/9` 密度刻度（79 处半档保留）：密度刻度表达单个控件的状态档位，改动会破坏上游兼容；布局间距表达元素之间的关系，才受档位约束。
- **允许档位** 4/8/12/16/24/32px（页面级 48px+），淘汰 `.5` 半档；12px 确认为面板/条带水平内边距的事实标准角色。

## 落地与验证

- 业务代码布局间距半档清零（复核 grep 排除 `src/components/ui/` 后仅剩 `models/model-logo.tsx` 定义层登记例外：CpuIcon 回退与 sm 徽章内衬的 `p-0.5`，属密度轴豁免，归位会造成 sm 图标字形变小一档的视觉回归）；0.5 档其余 12 处逐处判断（光学对齐以渲染为准，如 size-4 图标在 leading-6 文本旁 `mt-1` 恰为完美居中值）；`voice-studio-page.tsx` Link 的登记值 `gap-1.5` 随归位同步为 `gap-1`。
- 定点修复：顶栏 Home/新建按钮边距统一 `mx-2`；检查面板底部 `p-3` 容器内嵌告警条去掉 `px-3` 与 `border-b`（原水平内边距叠成 24px）；fallback header `h-10`→`h-11`。
- 自动化验证与 1024×680 中英亮暗目验见 change tasks.md；`src/components/ui/` 例外不参与检查。

## 重新评估条件

- Tailwind v4 若提供官方语义间距 token 机制且项目引入设计 token 构建步骤，可把档位从约定升级为可检查的 token。
- 若组件库脱离 shadcn 上游自维护，密度刻度可并入统一阶梯重新推导。
