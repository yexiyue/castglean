# 真实章节制作后的流程简化建议

日期：2026-11-13。状态：用户已授权整体简化；已实施直接编辑与当前章声音设置，验证证据见下方关联变更。接续[章节制作规划](chapter-production.md)及[整章生成优先决定](../decisions/chapter-generation-first.md)。

## 当前依据

中文小说导入、真实分析、逐角色绑定、100 单元整章生成、取消/续跑、失败定位、切章后台生成、停顿和 WAV 导出已取得原生证据；用户反馈本次试听可用。[验收记录](../../desktop-studio/chapter-audio-validation.md)保留首章全角百分号失败与队列注册冲突，修复证据分别归对应变更。局部重做与候选采用仍未交付。

## 实际操作中暴露的问题

| 环节 | 观察 | 建议 |
| --- | --- | --- |
| 导入 | 工程名先填，再选文件，再确认编码；同一目标经过多个状态 | 文件名预填工程名，合并为选择来源后的一次明确导入确认；编码与来源确认保留 |
| 处理缺声 | 生成前能列出缺声，但角色中心入口没有直接完成该行阻塞，处理后需要返回原章再检查 | 在原章集中列出缺声目标，可就地选择/试听/绑定；保存后更新同一检查清单并保留原章位置 |
| 确认角色 | 确认候选后仍停留在候选详情，要再点击已确认角色才能进入配音设置 | 已被 2026-11-13 用户要求替代：AI 校验后角色直接可用，不再要求确认；不自动合并同名角色 |
| 音色选择 | 一个角色反复打开弹层，长列表重复模型描述，以技术 ID 为主，缺少搜索 | 按当前可用模型过滤并提供搜索，模型信息集中显示，音色行直接试听/绑定；未提供的声音描述不编造 |
| 模型读取 | 首次角色中心等待完整资源读取，原先每次保存也重复校验 | 保存后的重复盘点已修；继续复用同一资源读取请求，解释实际校验阶段，加载时保留完整校验 |
| 分析反馈 | 原生样本分析耗时较长，0/1、请求数和 token 统计比正在做什么更醒目 | 主要显示真实阶段、目标章和耗时；技术用量放详情，不伪造百分比 |
| 正文层级 | 角色列改善了层级，但纯空白片段也会出现旁白标记，相邻同角色可能被拆成多个块 | 仅在展示层合并相邻同角色、隐藏纯空白角色头；原文字节、复制与引用保持精确 |
| 播放 | 正文播放器与轨道都提供操作；从某片段起播后的总时长会变成剩余区间，容易混淆整章与片段队列 | 统一制作区主要播放器，明确标记播放范围、章内位置和暂停状态，短试听复用单音源 |
| 失败恢复 | 用户看到第几个单元失败，但不能直接理解符号/能力原因；文本语义更新后旧任务不能混合续跑 | 提供可理解的原因、来源定位与下一步动作；保留旧产物，清楚区分继续与生成新版本 |

## 建议实施顺序

1. 先收敛直接操作：当前章生成检查清单、AI 角色直接配音、音色搜索和绑定、保存后就地更新。优先减少跨页往返和重复点击。
2. 再整理工作台：真实阶段信息、角色块空白与相邻合并、统一播放器和范围说明、失败后的明确动作。
3. 将稳定的分析、绑定、生成、播放和导出领域用例接入[助手工具卡方案](../../../openspec/changes/assistant-guided-production/proposal.md)。直接操作和助手共用持久状态，分析校验结果直接可用，人工直接改动保存；助手编排另行实施，不再以逐项身份确认作为前置条件。

局部重做与采用独立跟踪，不用助手编排重新实现生成器。下一项 UI 变更需落实具体 OpenSpec 和任务；本记录不表示完整目标推进器已授权或已交付。

## 自动化边界

原生音色弹层的内部按钮未在本轮可访问性树中完整暴露，键盘焦点与原生辅助功能需专项复验。桌面控制连接超时、截图缩放坐标换算的操作成本应与普通用户的流程问题区分；不能把全部自动化重连和定位耗时归因于产品。

验收按完成步骤、角色重复操作、跨页次数、返回原章位置、保存/试听反馈和可恢复性比较；中英、亮暗、小窗口、鼠标/键盘与单音源互斥继续分别验证。

## 本轮落实

[简化章节流程](../../../openspec/changes/simplify-chapter-workflow/)落实来源优先导入、就地角色/声音、搜索与模型筛选、共享模型订阅、自动保存及撤销、弱化重复角色头、主要播放控制收敛与恢复动作。AI 来源保留 candidate 标记，仅表示来源，不再是生产权限门槛。同来源重分析自动采用无保护差异，人工保护范围保持当前值。来源范围改变时仍保留独立结果，避免覆盖旧范围的人工编辑。自动化、原生与其他平台验收分别记录。
