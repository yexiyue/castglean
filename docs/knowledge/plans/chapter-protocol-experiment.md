# 章节分析协议对照实验

日期：2026-11-08。状态：四组各两轮、8 次正式请求已完成；只验证同一真实章节，不改变正式分析协议或工程数据。

后继状态（2026-11-08）：本文保留调研/早期实验时点。①②③、有限并发、只读 AI 预审与固定评测已在优化工作树实现，ECS 原型位于独立 worktree；当前证据及未验证项见[评测验收](../../desktop-studio/chapter-evaluation-validation.md)。文中的“尚未实现/未接入”仅描述早期时点。

## 问题与分组

①宿主预切片并拥有范围；②短引用和紧凑输出；③显式请求 `reasoning_effort=low`。同一正文整章输入，对照当前锚点协议的默认思考组、仅③组、②③组、①②③组。整章请求与当前自动小窗口任务分别记录，不能将两者差异全部归因于协议。

- 当前锚点协议：直接使用正式 Schema、提示词、锚点生成和校验器。
- ②③：保留模型决定语义边界，缩短范围/字段引用，保留证据范围，省略逐片段文字理由。
- ①②③：按换行、引号、冒号、句末标点及 160 字符上限生成片段；空白附着相邻片段，模型按短 ID 返回类型/归属/证据。程序决定位置但不把引号直接判作发言。
- 紧凑协议省略文字理由是实验变量的一部分，不声称只改 ID 长度。还原时的理由字段明确标为实验标记，不能冒充模型解释；本实验不发布正式标注。

紧凑归属还将角色键数组编码为 narrator/unknown/单角色/多候选，由适配器还原正式状态；所以本轮②是协议简化组合，不是只修改引用长度的单变量实验。

## 方法与接受条件

用户明确授权以当前《吞噬星空》正在分析的同一章实验。只读当前运行的来源绑定，核对完整来源 SHA-256 后截取精确字节范围，冻结章节摘要及配置选择。正文、提示词、原始响应、人物名和逐项审阅只写入 `src-tauri/target/`，不进入 Git。凭据只由 Rust 原有系统凭据入口读取。

每组两轮，第二轮反转顺序；实验请求串行，无修复、网络重试、自动降级或输出 token 上限覆盖，每请求 600 秒超时。整章样本只用于比较该长度，不据此宣称已验证模型 256K 容量。固定 26 个预先审阅单元，包含明确说话人、匿名角色、内心独白、叙述与带引号的非人声；答案在首次模型请求前冻结并记录摘要，不发送给模型。

记录每次耗时、输入/输出/缓存/推理 tokens（缺失保持未知）、响应字节、模型身份、结构校验和完整覆盖、审阅单元类型与归属联合正确数。紧凑输出先还原，再调用正式 `protocol::convert`；无效响应计为未交付，不能只统计成功样本。结构合法不代表全文语义正确；26 项由本次执行者标注，尚未独立人工复核。低思考只证明请求参数，不证明网关或后端实际执行。

保留现有应用活动任务，可能产生服务端并行负载；采样、缓存、服务负载和顺序均限制因果解释。实验使用现有 debug 测试二进制，主要度量远端请求延迟，不能当作本地 CPU 性能基准。

预跑曾误选 120 秒探测传输，修正后另建运行目录并重新冻结输入及程序摘要；预跑与一个被中断请求不纳入正式配对结果，未知用量不计为零。构造约束见[通信经验](../lessons/llm-transport-and-recovery.md#后台实验也必须选中后台-http-客户端)。

### 拒绝与语义问题

- 仅③第一轮：10 处纯空白缺口，共 56 字节；没有观察到这些缺口吞掉正文词句。离线只回填空白后通过原校验。原自动名字匹配 23/26，三处仅为匿名角色名称增加“无名”说明；根据原文及角色区分复核为同一身份，身份对齐后 26/26。此复核没有改冻结答案，原始请求仍记为未交付。
- 仅③第二轮：正文连续覆盖，但一处 `ambiguous` 仅给一个候选，违反宿主至少两个候选的要求，拒绝正确。没有自动把它改成 resolved 或放宽校验。
- ②③第二轮：34 处纯空白缺口，共 204 字节。离线仅回填空白后，通过原校验并达到 26/26；补齐结果单独保存，原始交付仍是失败。没有改变模型请求、重试或将正文空白丢弃。
- ①②③第二轮：结构及完整覆盖通过，但台词内部的一个嵌套称号片段被误标为旁白，使一处检查不符合答案。这是语义错误，不能用“结构合法”掩盖，也未据此修改提示词或答案再计入本轮。

①②③两轮均返回 284 个预切片；第一轮按相邻同类型/同角色键统计可归为 117 组。②③两轮分别返回 123、178 个模型片段。归并只是离线计数，未修改分析结果；预切片偏碎、嵌套引语与输出审阅粒度仍需后续设计。

原任务最后只读观察为 15 个 completed、6 个 pending、持久化状态 running，但当时未发现桌面进程。不能把挂着的 running 总时长作为模型耗时证据；未重启应用或操作原任务。

## 结论与后续候选

2026-11-08 用户决定：选择①宿主预切片＋②紧凑归属输出＋③低思考预算作为正式落地方向。该选择已确认，实现尚未开始；正式接入前需在 OpenSpec 落实证据理由、嵌套引语、片段归并及恢复语义，不把实验占位理由直接写入正式结果。多子任务并发仍属待实验的进一步优化，不因本次选定①②③自动启用。

本章最稳定的原始交付是①②③：两次 73–87 秒，免去模型计算输出坐标，保留严格校验；仍有一次嵌套称号的语义误判。②③能完成同章语义判断，但原始坐标覆盖仅一次通过。单独放大窗口与仅设置 low 均未带来有效整章交付。

后续验证以已选①②③为基础，先补嵌套引语、片段归并和文字理由的审阅需求，再增加同协议的①②/①②③对照，隔离低思考参数；也可独立验证②③的宿主纯空白回填。这些补充实验与并发优化尚未实现，不从一个章节推断全书收益。任何正式边界、恢复或数据格式修改仍先进入对应 OpenSpec。

### 并发子任务的候选方向

当前快捷分析直接进入固定结构化流水线，不依赖工程助手反复规划；`execution.rs` 的窗口依次消费前窗人物候选。工程助手仍是独立的工具循环，工具并发为 1。`jobs/runtime.rs` 允许全局两个运行，但同一连接只准入一个运行；单纯创建更多子运行并不会自动实现同连接并发。

优先比较两项优化：先按连续同类型/同身份的预切片 ID 区间压缩模型输出，再验证 2/3 路有限并发。并发候选采用宿主编排：一次整章人物发现，宿主冻结本章局部身份映射，分派不相交的目标 ID 组；子任务共享完整章上下文及相同角色快照，但只标注各自目标。角色候选仅在本次运行内共享，不能冒充全书已确认身份。新发现和身份冲突返回中央处理，不能按名字自动合并。宿主统一校验、归并和整章发布，只有嵌套引语、未知/冲突等可定位问题进入有界复核。

每个子任务保留输入指纹、结果及取消状态，恢复复用有效子结果；共享连接级请求并发上限和用量记录，不能让子任务绕过全局限制或各自写工程库。总耗时包含人物发现、最慢子任务、汇总与必要复核，不承诺按并发数等比例缩短。多路读全文会增加输入量，缓存命中及服务端并发能力需要实测。

用户随后提出整章由 AI agent 先行预审，再交人工查看；职责、当前限流位置和 rig-ecs/rig-harness 0.46 的接入评估见[运行时与 AI 预审调研](agent-runtime-and-ai-pre-review.md)。AI 预审不改成人工确认状态，尚未正式接入。
