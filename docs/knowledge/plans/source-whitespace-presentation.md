# 分章原文空白呈现调研

日期：2026-11-08。状态：调研已完成，用户已确认并实施；现行规则与验证见[紧凑校对决定](../decisions/source-whitespace-presentation.md)。以下保留当时的候选依据。用户反馈原文空行太多、显示稀疏，希望了解主流处理方式；与已实现的章内虚拟滚动分开记录。

## 当前原因

[原文行](../../../src/components/projects/chapter-splitting-workbench.tsx)对每行都提供正文 padding、行号和操作区；空行也被操作按钮及行高撑开。虚拟化减少了离屏 DOM，却不会减少单个空行的视觉高度；改缓存或 scroll 设置不能解决排版问题。

## 一手依据

- [KOReader 用户指南](https://koreader.rocks/user_guide/)区分原样 TXT 和自动识别布局；后者利用空行、缩进等推断段落/标题，但可能影响 ASCII 图形和依赖空格的排版。不能把自动重排直接用于默认校对视图。
- [KOReader CSS 样式源码](https://github.com/koreader/koreader/blob/master/frontend/ui/data/css_tweaks.lua)提供整行、半行或无段间空白的样式选项。可借鉴将视觉段距与来源字符分离，不必改动原文。
- [calibre 转换指南](https://manual.calibre-ebook.com/conversion.html)明确区分样式级段间距处理与修改内容的空段清理；启发式处理中会把连续空白作为潜在场景分隔保留。可借鉴区分普通段间空白与场景留白；本应用不采用内容转换。
- [W3C CSS Text Level 3](https://www.w3.org/TR/css-text-3/)的 white-space 控制空格/换行保留，不负责理解段落或场景。简单替换为 normal/pre-line 无法同时保证小说排版与原文引用身份。

以上为官方文档与源码抽样，不是所有主流产品统一遵循的标准，也没有进行真实用户对比研究。

## 建议：默认紧凑校对，可切回原样

- 普通单空行用小段距；连续空行合并为一处有限留白，避免空白数量直接放大页面高度。多空行可能表示场景切换，保留可发现的数量/原行号范围，而不是直接消失。12–16px 为应用内待视觉验证的候选值，不是外部规范规定。
- 保留正文内容、段首缩进、章界与原始行号。界面合并的是显示组，不能重编号或调用删除空行命令。复制和 AI 引用按原始文本提取，保留 CRLF、全角空格、NBSP 等；空白节点/显示标记不能混入引用。
- “原样显示”放在稳定的阅读显示入口，偏好属于当前工程临时 UI 状态。诗歌、代码/ASCII 表格和需要检查空白的场景能显式查看原样；不自动把这些段落认定为无意义留白。
- 合并组以来源行范围为身份。目录、问题和行号定位到空白时仍高亮真实目标，跨虚拟块的空白组不能重复显示或跨章节合并；切换显示方式应保持当前阅读锚点。
- 正文优先使用应用正文排版，空白组不套用整行操作栏。压缩前后对比需要验证轻暗主题、小窗口、正文长段及所有空白行，不只看理想样本。

## 实施前需要落入规格的验收点

连续空白跨 30 行块边界、章首/章末空白、首尾全空来源、空白处定位/分卷、压缩/原样切换锚点、鼠标和键盘选择/复制、AI 引用、中文/emoji/CRLF、空格缩进及诗歌/ASCII，均保留正确来源身份。这些候选验收点已落实到[规格任务](../../../openspec/changes/archive/2026-11-08-virtualize-source-reading/tasks.md)与上述决定；本记录不再描述现行实施状态。
