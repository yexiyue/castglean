# 开发构建的模型盘点哈希耗时

日期：2026-11-13。适用：macOS arm64、CastGlean 调试构建、共享 Hub 固定清单。

启动后顶栏长时间停在“读取模型…”，不能据此判定缓存为空。原生进程采样显示 `catalog::list_models → scan_manifest → resource_verified → sha2::sha256::soft` 正在计算权重摘要；目录快照需要等待盘点完成。开发配置此前没有继承 TaleChime workspace 的 `profile.dev.package.sha2`，路径依赖不会传递 profile 配置。

宿主现为 `sha2` 单独启用 `opt-level = 3`；macOS 另启用该版本的 `asm` feature，让 Apple Silicon 使用运行时探测的 SHA 指令（无硬件能力时仍有软件后备）。保留文件大小与 SHA-256 校验，不采用只判断文件存在的替代逻辑。`model_inventory_complete` 日志记录模型数量、就绪数量和耗时，不记录正文或凭据。

本机 Kokoro 固定清单的 121 个文件（约 1.03 GB）经独立 SHA-256 校验全部匹配。只优化软件实现时，原生调试包全目录盘点耗时 65,520–70,053 ms；再启用硬件加速后为 18,454 ms，均为 11 个模型中 6 个就绪，顶栏显示“已就绪 6 个模型”。这仍有明显的首次读取等待，不能称为即时盘点；角色中心独立查询也会重新验证缓存。后续缩短等待需保持缓存变更检测与摘要校验契约。不同运行的系统负载与缓存冷热并未严格控制，数字是本机观测值。

这些是缓存完整性与原生目录读取证据，不代表模型加载、章节生成或人工听感验收。
