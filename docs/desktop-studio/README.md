## 定位

CastGlean 定位为面向个人的桌面有声书生成与收听应用：把用户有权使用的小说生成为可听的多角色版本，动机是收听而非发布（2026-11-02 决策，依据见[调研记录](research.md)）。先在本仓库孵化。分析能力按应用工作流在 Tauri 宿主内重建，成熟后再拆独立包复用。用户围绕小说正文完成分析、检查、选声、生成、试听、修正和导出；模型负责提出建议，程序负责校验，人保留制作决定权。

产品首先帮助用户做好一章，再扩展到连续章节和整书。主要交互采用正文编辑区、上下文检查面板和播放器，暂不采用自由拖拽节点画布。

## 已确定方向

2026-11-08：真实工程使用单一章节工作台与工程 AI 助手，分章/归属作为不同工具与快捷命令，切章保持同一会话和草稿，每次运行固定目标。角色使用实际身份，制作结果尚未接入，详见[决定](../knowledge/decisions/unified-project-assistant.md)与[融合验收](project-assistant-validation.md)。

- 做个人收听工具：生成并收听自己的有声书，成品可导出带走；完整阅读体验由独立项目 TRNovel 承担，CastGlean 不做无音频的阅读器，正文页只是制作与播放的操作画布。
- 功能按[产品企划](product-plan.md#功能模块总览)组织：正文、当前生成任务和试听构成主路径，角色/音色/模型保留稳定管理入口，播放器与导出构成收听闭环；不要求用户在固定三视图之间逐步流转。
- CastGlean 的听书能力成熟后可供 TRNovel 复用（库、导出或服务形态待定），不重复建设阅读功能。
- 桌面框架采用 Tauri 2，利用 Web 排版、交互与音频组件生态；前端已选定 React 19 + TypeScript（2026-11-02 重启时确定），音色试听已使用 WaveSurfer.js，整章播放与映射仍待验证。
- 桌面应用是产品主线；分析能力按应用工作流在 Tauri 宿主内重建，成熟后再拆包复用。应用宿主调用 TaleChime，按实际需求补齐基础库。
- 不再维护独立 `integrations/talechime` 产品；原型已退役，历史证据单独保留。
- 小说正文是主要操作入口；选中内容即可检查归属与演绎、试听音频，并调整声音或后端模型。
- 支持查看音频实际采用的声音、模型、耗时和生成来源；高级信息按需展开。
- 人工参与是正常制作环节。模型分析、朗读规划和音频生成都需要可检查、可修正的交互。

## 本企划提出的实施建议

- 先交付一章的制作闭环，再增加整书批处理和更复杂的工作流。
- 下一阶段先在现有工作台增加“生成本章”、集中阻塞提示、真实任务状态与连续播放；根据实操再决定面板/工具卡布局，不先重写全站。
- 保留候选与人工修正，明确区分历史生成配置和下一次生成配置。
- 单人旁白、单人演绎、多角色演绎逐步提供；不把角色分析作为单音色生成的必要条件。
- 自定义节点、插图、通用插件和多媒体制作暂时后置。

Tauri 2、React 19 + TypeScript、SQLite 工程与音色试听播放器已接入；首个章节生成模型组合、合成单元/音频映射、任务恢复和完整编辑能力仍需规格与验证，详见[待决策项](execution-and-roadmap.md#待决策项)。
