# 桌面技术选型：Tauri 2

决策日期：2026-10-31。状态：已确定采用 Tauri 2；尚未创建桌面工程或验证实际性能。本文确认框架方向，不固定未经验证的组件、版本和安装包指标。

## 决定与理由

CastGlean 使用 Tauri 2 构建桌面应用，以 Web 技术实现正文、检查面板、音频候选和播放器，Rust 宿主管理制作工程与后台任务。核心能力继续保留在独立 Rust 包中，供辅助 CLI 和其他开发者复用。

首要目标是丝滑、好用的有声书制作体验。选择 Tauri 的主要原因是可以利用 Web 的排版、交互与音频组件生态，减少正文操作、波形、播放与候选比较的重复建设，便于持续迭代产品。生态丰富不代表具体组件已选定，也不代表加入组件即可满足体验要求。

当前不并行建设 GPUI Kit、Native Shell（NSH）或其他框架版本。未来仅在实测出现明确且难以解决的限制时重新评估，不预先创建 UI 框架抽象层。

## 实现边界

| 层次 | 责任 |
| --- | --- |
| Web 界面 | 正文呈现、选区与标注、面板、播放器交互、波形与候选比较；维护临时界面状态 |
| Tauri Rust 宿主 | 命令、任务生命周期、工程持久化、修订检查、选角、声音映射、候选采用与导出 |
| CastGlean 核心包 | 不可变来源、角色身份、归属、朗读意图、校验、人工修正保护与分析工作流 |
| TaleChime | 语音资源、模型能力、合成执行、音频和实际进度 |

界面不能直接改写权威工程文件或重复实现核心校验。配置草稿与已生成音频的历史记录分开，采用关系和完成状态由 Rust 侧确认。Tauri 类型、窗口事件和前端 DTO 不进入通用分析核心。

前端框架、TypeScript 状态方案和音频组件在首个真实闭环中选定，不因本决策默认采用 React、某个编辑器或某个波形库。首版原文不可变，优先实现可选择、可标注的阅读区，不提前引入完整富文本编辑系统。

## 流畅性约束

- 模型加载、推理、波形提取和大文件处理不占用界面事件循环。TaleChime 的本地执行模型由宿主管理，不能把线程受限对象直接放入任意异步命令共享。
- 正文按章节加载，选区变化和播放高亮尽量只更新相关区域。虚拟化要同时验证跨段选择、复制、定位和滚动行为，不能只优化可见行数量。
- 浏览器文本位置到核心 UTF-8 字节范围采用显式映射，覆盖中文、emoji、换行和组合字符；显示标记不修改来源正文。
- 任务进度适度合并更新，有序任务流优先使用合适的 Channel；普通事件不承载高吞吐音频。界面重连后从权威快照恢复状态，不依赖通知绝不丢失。
- 音频优先以受控本地资源读取，不将完整 WAV 反复编码为 JSON 传输。波形摘要缓存，候选切换避免重复解析整份音频。
- 播放位置有单一权威来源；波形绘制与正文高亮使用同一时间到来源映射，避免多个播放器时钟漂移。
- 自动跟随播放可关闭；用户主动滚动后不持续抢回视口。选区、焦点和快捷键在面板切换后保持可预测。
- 生成新候选时旧音频继续可用；失败不覆盖满意结果。不同任务的进度不得整页重置用户正在编辑的设置。

“丝滑”以真实使用验证，不以空窗口帧率或框架宣传数字验收。Tauri 使用系统 WebView，字体、媒体格式、焦点和输入法行为需要目标平台实机检查。

## 首个原型验收

使用允许公开的中文长章与本地音频，验证正文、右侧检查面板、底部播放器和后台任务同时运行：

1. 跨段选择并复制，返回正确的原文范围；窗口缩放和字体变化后仍正确。
2. 点击片段立即切换详情，播放定位与高亮一致；只有范围级映射时不伪装成逐字精确。
3. 播放时滚动、拖动面板、切换候选和编辑设置，不出现明显卡顿或焦点丢失。
4. 持续接收后台进度，任务取消或失败后界面仍可操作，旧音频可试听。
5. 关闭重开能恢复采用版本；从实际分发产物验证本地音频读取和资源路径。

先记录交互延迟、帧时间、CPU、内存和实际生成负载下的资源占用，再建立验收预算。不预设 GPU 渲染、WebView 或 Rust 可以自动保证低占用；不将语音推理速度归因于 UI 框架。

## 组件选择与未决事项

- 前端框架和构建工具；按首屏交互、维护成本与组件适配确定。
- 音频播放/波形组件；检查本地大文件、seek、区域选择、候选复用、键盘可访问性和许可要求，复杂多轨编辑仍后置。
- 前后端类型同步方式；传递明确命令和快照，避免前后端各自维护一套权威工程。
- 第一目标平台、语音后端与安装包范围；框架支持的平台不等于应用已验收的平台。
- WebView 运行时准备、媒体资源访问范围、安装和更新；模型权重及原生推理依赖单独验证。

## 2026-11-05 音色试听播放器增量

音色试听选择 WaveSurfer.js 8（本次锁定 8.0.5），视觉与基础控制参考 MIT 许可的 waves-cn Wave Player，按现有 Base UI 控件适配。使用官方 Hover 插件与自定义倍速、音量、键盘进度控件；不保留第三方组件的私有插件复制逻辑。来源许可保存在 `licenses/waves-cn-MIT.txt`。

宿主在 blocking pool 从已发放的媒体身份读取 WAV，最多提取 1024 个单声道显示峰值（多声道取绝对峰值，避免相位抵消），摘要缓存随临时媒体一起释放。前端只接收摘要、时长，通过 `voice-audio` 读取原始 WAV；不在 WebView 解码整份音频或传输完整 PCM。播放器按需加载，播放时钟由唯一媒体元素提供，暂停保留租约，停止或切换先停音频再释放租约。切页继续播放；重启不恢复试听会话。

本次只覆盖音色中心短试听，不表示章节正文定位、长音频、大文件和多轨编辑已验收。验证结果见[音色中心验证](voice-center-validation.md)。

## 辅助分章验证中的运行时边界

本轮使用 Rig 0.46.0 的三协议适配和有界工具循环，graph-flow 0.8.1 仅持有宿主私有外层图检查点。前端 AI SDK UI 使用 Tauri transport/Channel，不增加 HTTP 或 Node 后端。正文解码、regex、JSON 与文件发布放在 blocking worker；LLM 网络复用宿主异步 runtime，不进入语音 engine owner 线程。引入图不代表章节分析必须使用 agent，后续确定性流程仍可单次调用模型。本机桌面主链、故障恢复与容量验证已完成，实际设备数据和其他平台/发布包的未验证边界见[分章验证](chapter-splitting-validation.md)。
