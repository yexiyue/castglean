# 产品企划

日期：2026-10-31。状态：桌面产品目标与范围草案；未实现能力均为规划。

## 要解决的问题

现有 CastGlean 已为小说分析建立原文绑定、稳定身份、校验、人工修正和恢复基础，但普通用户仍需理解命令、配置与输出文件。有声书制作还要求用户判断实际听感、选择声音、比较候选并处理局部失败，单独增加模型输出字段不足以完成这些工作。

产品要让用户随时回答：当前做到哪里；这一段为什么这样读；哪里可以修改；修改影响哪些结果；怎样继续而不丢失满意版本。

## 用户与使用场景

首要用户是**想收听**自己有权使用的小说的听众：把小说生成为可听的多角色有声版本，动机是收听而非发布（2026-11-02 定位决策，依据见[调研记录](research.md#市场需求与竞品2026-11-02)）。用户懂得判断故事与听感，但不要求会 Rust、JSON、模型部署或音频工程。

开发者也是使用者：希望对照声音和后端、检查生成参数与用量、定位失败、复现实验。开发者能力通过同一工程的高级详情提供，不另建一套与普通界面状态脱节的调试工具。

典型任务：

1. 导入一章，选择一个声音，快速生成可试听的初稿。
2. 检查模型识别的主要角色，修正一句台词的归属，并试听角色的真实台词。
3. 将一段过于激烈的表达调得克制，生成新候选并比较前后衔接。
4. 更换模型或音色，保留旧版本，仅重新生成受影响的内容。
5. 中断后重新打开工程，辨认已保存、未完成和需要重做的内容。
6. 通勤路上继续听：应用记住播放位置；或将章节导出为带章节标记的音频，在手机常用播放器里继续。

## 制作方式

| 方式 | 用户目标 | 依赖 |
| --- | --- | --- |
| 单人旁白 | 先听一版自然、连贯的朗读 | 正文与声音，不要求人物表或语义规划 |
| 单人演绎 | 保持一个声音，增加段落表达和篇章起伏 | 独立朗读规划；具体效果受 TTS 能力约束 |
| 多角色演绎 | 角色声音稳定，台词归属可修正 | 角色分析、声音绑定；演绎规划可选 |

这三种方式是产品目标，不要求同时成为首版交付。线上 GLM / MiniMax 是朗读规划的前期验证路径，本地 LLM、训练和蒸馏不作为前置。设置中分别呈现文本分析模型与语音合成模型。

## 产品原则

- 正文、角色、演绎建议与音频之间能互相定位；默认界面保持正文可读。
- 模型输出先校验再采用，结构正确不等于归属和演绎正确。
- 人工检查可以发生在生成之前或之后；允许批量生成初稿，不强制逐句确认。
- 人工修改保护到具体字段和范围，重新分析不静默覆盖。
- 不强行解决歧义。未知归属可以配合显式声音回退策略继续制作。
- 当前音频保留实际生成记录；修改设置只改变下一次任务，不改写历史。
- 用户看到实际重做范围与影响，不承诺任意选区都可独立合成。
- 跨后端共享朗读意图；参数、声音和表达能力按实际模型检查。

## 技术方向

桌面框架采用 Tauri 2，以 Web 界面和组件生态降低正文与音频交互的开发成本，Rust 宿主管理工程和任务。核心拆为独立包供 CLI 和开发者复用。具体前端与音频组件尚未选定，体验通过真实长章、播放与后台负载共同验证，见[技术选型](technology-choice.md)。

## 最小可用闭环

导入本地 UTF-8 章节，确认章节边界，选择一个验证过的后端及声音，生成可播放音频。在正文上定位片段、查看生成来源、调整设置、生成候选、选择满意结果，最后导出章节 WAV。保存工程后可关闭并继续。

首轮可以先用单人旁白验证宿主；随后在同一流程中加入角色分析、归属修正和选声。独立朗读规划按 issue #3 建立契约与小样本评测，再放入可试听流程验证，不要求完成全部规划能力后才开始桌面验证。

这里的局部重做、候选管理与桌面工程恢复都是新增目标，不能将现有章节恢复直接描述为已覆盖。

## 范围控制

| 范围 | 安排 |
| --- | --- |
| 正文定位、播放、设置、候选、导出、工程恢复 | 第一阶段核心 |
| 断点续听、章节播放队列、倍速与带章节标记的导出（如 m4b） | 随第一阶段播放器补齐，属于收听闭环 |
| 角色检查、归属修正、声音绑定、待检查列表 | 在单章闭环上增加 |
| 场景与段落演绎、重分析差异、人工保护 | 在规划契约与听感验证中增加 |
| 连续章节、角色级批量变更、失效与恢复 | 单章能力稳定后推进 |
| 后端切换与候选比较 | 按实际验证的模型能力逐步开放 |
| 一章任意混用不同后端 | 后续验证格式、响度、衔接及执行接口 |
| 任意旧章重分析、身份合并、拆分与撤销 | 补齐独立核心语义后开放 |
| 自由节点画布、公共节点 SDK、通用插件 | 暂不进入交付范围 |
| 插图、视频、配乐、多轨精编、云协作 | 后续独立论证，不作为当前前置 |
| 无音频的沉浸阅读、书架、排版主题、阅读进度同步 | 明确不做：阅读体验由独立项目 TRNovel 承担，CastGlean 只做听书；正文页只是制作与播放的操作画布 |

## 当前基础与缺口

以下依据 2026-10-31 整理后的本地工作区核对，不代表已发布或远端主分支状态。原独立语音联调原型已迁出，历史结果不能算作当前可运行能力。

| 能力 | 已有基础 | 桌面产品仍需补齐 |
| --- | --- | --- |
| 原文与标注 | 正文快照、摘要、UTF-8 范围、引用与覆盖校验 | 编辑区选择映射、播放反向定位 |
| 分析 | 固定窗口、模型适配、有限修复和取消 | 后台任务展示、可读结果与差异预览 |
| 角色与修正 | 稳定身份、归属/别名修正、末章重分析保护 | 可视化操作；完整身份合并、拆分和撤销尚缺 |
| 恢复 | 章节级提交链和恢复，非窗口 checkpoint | 桌面工程、候选文件与任务状态的一致恢复 |
| 语音交接 | 已有分析消费契约；旧原型留下同模型多音色和 WAV 导出的历史经验 | 在桌面宿主实现语音调用、候选、局部重做与后端比较 |
| 朗读规划 | issue #3 已提出独立任务 | 契约、实现、交互与听感验收均待推进 |
| 可观测性 | 分析统计与交接进度；TaleChime 有事件和进度基础 | 统一制作状态、耗时分项和持久化生成记录 |

参见[角色修正](../archive/design/cross-chapter.md)、[运行恢复](../archive/design/run-recovery.md)、[增量交接](../archive/design/incremental-delivery.md)和[历史联调记录](../archive/talechime-prototype/README.md)。已有音频导出或结构交付不代表完整听感验收。

## 产品验收

使用允许公开的短篇夹具做交互验证，再用获授权的真实章节做听感验收，私人文本与输出不入 Git。

- 初次用户无需编辑 JSON 或运行 CLI，即可导入、选声、生成、试听和导出一章。
- 能从正文定位当前音频，并解释它实际采用的声音、模型和配置。
- 修改一段设置后，旧音频仍可播放；新候选失败不会使满意版本丢失。
- 能修正错误归属；后续重分析不覆盖人工确认。
- 能说明修改影响范围，并只重做受影响的执行单元；实际边界按模型与映射决定。
- 中断后能辨认已保存结果与未完成任务；不重复发布音频，不伪造完成。
- 语义正确性、跨段连贯性与听感单独评估，不用格式通过率代替。

完成时间、易用性和质量指标应在首轮用户试用前定义并记录基线，本文不编造目标数字。
