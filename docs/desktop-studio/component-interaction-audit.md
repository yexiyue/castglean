## 动效与组件调研

当前依赖 `tw-animate-css` 和组件状态类；`sidebar.tsx` 动画涉及宽度和位置，`trace.tsx` 动画高度，`progress.tsx` 使用 `transition-all`，部分加载图标没有显式 `motion-reduce`。需要按真实窗口检查性能、焦点与减少动态效果，不能简单全局禁用导致状态无法理解。

[Motion 官方文档](https://motion.dev/docs/react-accessibility)提供 `MotionConfig` 的用户减少动态效果选项；[LazyMotion](https://motion.dev/docs/react-lazy-motion)可按功能加载以控制包体。先选一个有明确收益的布局切换做真实 Tauri spike，测量包体、帧表现、连续切换、减少动态效果以及 WebView 平台差异。简单颜色反馈继续使用语义化 CSS；Motion 未安装、不代表兼容性或收益已验证。

补充核对（2026-11-13）：[官方安装要求](https://motion.dev/docs/react-installation)为 React 18.2 及以上，当前项目 React 19 满足所声明的版本下限，但这不是桌面兼容性验证。[MotionConfig 文档](https://motion.dev/docs/react-motion-config)的 `reducedMotion` 默认值为 `never`；显式设为 `user` 后，位移和布局动画会停用，但透明度及背景色等仍可能运动，CSS 动画也不受该设置管理，故不能把这个配置等同于全产品减少动态效果验收。[LazyMotion 文档](https://motion.dev/docs/react-lazy-motion)说明需配合 `m` 和相应 feature bundle 使用，`strict` 可发现其范围内误用完整 `motion`；同步和异步加载、实际布局功能需求及构建增量仍须项目实测。

Base UI 已在项目中使用，优先核查其对应原语的键盘、受控状态与可组合 API；新增第三方组件须比较维护、许可、离线打包、Tauri 平台和现有组件重叠，记录选择和拒绝理由。无需为独特的正文定位或音轨强行套用不匹配的通用控件。
