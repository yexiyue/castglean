日期：2026-11-09。状态：最新C7紧凑协议单轮三路均交付；当前Agent/ECS请求从C5的7/10降至3/3，累计输入约降89%/94%，联合检查26/26、25/26。当前Agent总耗时364秒略增、ECS91秒降低；C6诊断与所有旧结果保留，不证明运行时胜出或稳定语义收益。实验分支 `codex/chapter-tool-agent-comparison`；原生测试桥位于 `codex/chapter-tool-agent-native-bridge`。不改变应用默认入口，不授予采用、发布或人工确认权限。

## 这次比较什么

两路线均为真实 Agent＋工具＋宿主校验反馈＋有界局部修正：classic 使用现有应用同版本的 rig-agent 0.46，ecs 使用 rig-ecs 0.46。共用同一 Rust 草稿状态、提示词、五个 DynamicTool、原生模型桥、初始片段、规范身份和停止规则。比较器核对数据/逐用例配置、初始输入 hash、实际系统提示 hash 和实际提供工具的 Schema hash。最初方案 C 仅比较两个运行时；用户追加的同章紧凑 JSON 与 low/default 对照见后文，分别列初稿和含预审的完整流程。

“共用”指相同实现：每个 case／路线／任务创建独立草稿与 Agent 历史，不共享结果缓存。实际工具定义按名称排序后核对内容 hash，不以原始 HTTP 字节一致作为门槛；工具顺序、会话编码和内核调度仍属于运行时适配差异，不能只凭墙钟差异归因 ECS 内核性能。

以下至“用户追加”为旧版记录。工具为 read_source、propose_characters、patch_annotations、check_draft、finish_analysis。宿主生成精确 UTF-8 片段，模型引用包含首尾的 pN 区间；草稿分批原子替换连续范围，错误不部分写入。expectedRevision 防陈旧覆盖，operationId 防补丁重复执行；校验反馈给缺失 ID，可局部补齐。首次完成失败和后续修正分别记录，最终聊天文字不算交付。

公开评测固定 known-only：propose_characters 返回身份范围限制，不凭名称合并/编造人物；私人烟测显式允许候选发现。独立预审使用新的 Agent 状态和相同工具，候选只读，以 rN 精确定位建议。首次分析的生成结果也先经过独立预审；此外公共 runner 再用另一进程评测预置植错，二者不混为同一任务或评测答案。

## 冻结预算与诊断

每个评测任务（分析＋生成结果预审）共享最多 16 个模型请求和 300 秒；已知用量累计达到 64000 tokens 后停止新请求，最后一条响应可能使累计超过该阈值。每个独立 Agent 最多 32 个工具准入、3 次失败校验/完成。输出上限为 4096，与显式服务配置的更低上限取小值；请求 low，工具串行，无隐式网络重试。外部植错预审为独立任务，成本单独合并，不伪装免费。未知用量保持未知；本地取消不证明服务端停算。

默认 trace 不含正文、人物名、工具参数或理由；记录真实请求时间/用量、工具名、错误码、修订和问题计数，ECS 另有真实 entity/effect 路径记录。原始 source、请求和结果只在忽略目录。原生桥完整往返 CompletionRequest/CompletionResponse，包括工具调用、结果历史与 call ID，凭据只在原生 Rust 内读取。两个运行时的外部 HTTP 均为同一个非流式完整响应桥；ECS 的流式消费接口缓冲同一完整响应，不把这层接口包装称为原生 SSE 流式验证。

请求耗时包含本地 helper 启动、响应读取与后置校验，不包含前置文件身份校验，不解释为纯服务端推理耗时。坐标/身份/覆盖检查的耗时计在对应工具中，末尾 `validation` span 是交付条件标记，不单独度量这些检查。`toolAudit.rejected` 表示工具已返回业务校验反馈，ECS effect 的成功表示调度执行成功，两者分别记录。

完整交付要求分析和生成结果预审均完成；后者失败时，不把有效但未交付的初稿混入正式准确率。`summarize_tool_phases.py` 另计主分析 finish、生成预审/植错预审的修正成功及各类错误，缺失请求证据保持 unknown。单独的植错预审按自己的分母评分，不改变分析任务的交付状态。方案 C 的草稿与补丁幂等只在当前进程内成立；旧一次请求原型的 SIGKILL 检查点结论不能外推为新的工具循环已支持恢复。

## 评分前发现并修复的问题

- 首次 ECS 冒烟未发远端请求：共用桥拒绝 Streaming 模式。修正为让相同非流式响应可经流式消费 API 还原完整内容。
- 第二次 ECS 冒烟发了请求但工具列表被移除：rig-ecs 根据 ModelSpec.tools=false 清除工具。方案 C 显式声明所需工具能力，实际服务通过经典 Agent 冒烟验证，不借另一目录模型的能力冒充；评分继续检查每个真实请求确实带有五个工具。
- 独立 AI 代码审阅发现 rejected 工具状态不被公共 scorer 接受、开引号前无法表达边界、修正预算多允许一轮，均在正式冻结前修正并补回归。

旧公开 dev-explicit 用作适配冒烟，未计入新留出集。最终两边均完成同一旧样本：3 次分析请求、1 次独立预审请求，工具为 patch/check/finish 加预审 finish。失败冒烟保留为工程诊断，不用于比较模型质量或运行时速度。

### 记录与比较门禁的修正

C1 预跑在两例成对执行后停止：比较器会丢弃独立植错预审进程的初始输入身份，且不一致只是布尔记录，未强制拒比。改变 driver 文件后，既有冻结保护在下一 case 启动前拒绝继续；当前 case 的分析与预审均已结束，没有杀掉在途请求或自动重发未知调用。两路线各保存一例 completed、一例 failed，失败均已发生分析/预审请求；它们只作诊断，不发布为已通过比较门禁的结论。

后继 C2 使用完全相同的冻结 Rust 二进制、提示、工具、模型和预算，仅新增 Python adapter 保留每个任务的 inputHash、adapterInputHash、实际连接配置摘要，并把评分器、实际连接配置、数据、adapter 和比较门禁纳入事前冻结。比较门禁按 case／任务／实际阶段核对身份；未知或冲突拒绝给出可比结论，已执行阶段与因失败而未执行的后继阶段分别记录，不丢弃失败样本。

C2 产物目录为 `plan-c/paired-holdout-c2/`。数据及答案不改，未据结果调整模型提示或工具行为；它后来因下述角色上下文问题在三例成对执行后停止，保留为预跑，不作为最终可比结论。C1/C2 的原始结果和消耗保留，不从实验总支出中隐藏。

C1 预跑共 39 个真实模型请求：classic 输入/输出已知 65064/4807，ECS 60674/5898 tokens；该次各请求用量均已知。它们在 `pre-run-summary.json` 单独记录，不计入 C2 的单次运行速度，也不抹去实际消耗。

### 角色上下文完整性修正与 C3

独立于模型输出的数据审阅确认：同名样本需要 characters.description 中的木匠/医师描述来绑定规范 ID，而旧 Character DTO 只读取 id/name。原始样本虽传给 adapter，描述却在 Rust 反序列化时被丢弃。现已保留可选 description，分析和预审往返回归通过；adapter 拒绝未映射的人物字段，并把实际初始人物上下文 hash 与原始输入核对，丢失字段不允许进入评分。最终门禁也强制核对该 hash。

这次未改变 gold、提示、工具定义或预算；修复的是原本应当可见的输入字段，不能把 C2/C3 的差异仅归因运行时。C2 在三例成对执行后于 case 边界停止，原记录共 classic 23、ECS 22 个模型请求，已知输入/输出分别 71514/6143、68646/5096 tokens，均无未知请求用量，详见各自预跑摘要。C3 使用新的冻结二进制 `frozen-c3/`，协议标识 `chapter-tools-c2-context`；产物为 `plan-c/paired-holdout-c3/`，最终比较以其 `verified-comparison.json` 为准。前三例属于输入/记录修复后的重复执行，其余三例首次执行；本轮不再称六例整体为从未执行的盲测。

独立 AI 数据审阅见 [audit.md](../../evaluations/chapter-tool-agent-v1/audit.md)，未参考模型输出或筛除样本。其提醒的相邻同类段可合并问题已由公共评分规则覆盖：固定单元按每个字节的类型/身份判定，同类同身份段合理合并不会因未复现 gold 分段数量而扣分。标点与空白的语义约定、AI 标注而非人工真值的限制继续保留。

## C3 公开运行结果与拒比结论

### 实验桥的时间边界与后续保护

实际模型 span 累计 classic 529.41 秒、ECS 603.03 秒，小于上述路线墙钟；剩余时间不能归因为 ECS 调度本身。共同原生桥每次请求前后都重新读取配置绑定并对约 221 MiB 的原生测试 helper 计算文件 hash，前置校验发生在模型 span 开始之前；构造边界和文件落盘也占用墙钟。当前 span 未单独量出这部分开销，不据差值推断纯推理速度，更不外推为应用内长期运行客户端的性能。

运行后补充两项无模型回归：driver 在任何付费请求前预检**全部**计划人物字段，遇到 aliases 等不支持字段整轮快速失败；共享 comparator 拒比时仍保存拒比结果并执行强门禁。新 driver 不覆盖 C3 的原冻结身份，旧脚本副本保留于 `frozen-c3/`。尚未实现 aliases 语义支持，因此当前六例数据直接交给新 driver 会在请求前失败；这是显式实验能力限制，不是可直接再次启动的完整评测。
