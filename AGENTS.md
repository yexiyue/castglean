# CastGlean repository guidance

CastGlean is a desktop audiobook production app under development. Its core capabilities live in independent Rust packages for the desktop host, an auxiliary CLI and other developers; the CLI is not a separate product track. Offline validation, bounded chapter analysis, cross-chapter corrections and chapter-level recovery already exist; the desktop app and independent narration planning are not implemented. Tauri 2 is the chosen desktop framework; frontend and audio components are not selected yet. Follow `docs/desktop-studio/technology-choice.md` for UI/runtime boundaries and responsiveness validation. Read `README.md`, `docs/desktop-studio/README.md`, `docs/implementation-roadmap.md`, and `docs/data-format.md` before implementing behavior. `docs/project-plan.md` preserves the earlier library-first plan. Do not describe planned commands or integrations as shipped features.

- Prioritize the desktop app's chapter production loop. Add missing capabilities to the CastGlean analysis libraries or TaleChime only when a concrete app workflow requires them, with relevant library validation before use. Prefer deterministic workflows before optional bounded tool loops.
- Keep CastGlean analysis independent and reusable; keep the CLI a thin adapter over the same workflows. Use explicit host-provided configuration and state, and reuse the host async runtime. The desktop host owns casting, TTS mapping, candidates and exports; it consumes TaleChime without putting backend-specific types in the analysis core. The former standalone `integrations/talechime` prototype is retired; do not recreate it as a parallel product. TRNovel is a possible later consumer, not the first-delivery prerequisite. Follow `docs/implementation-roadmap.md` for implementation order.
- Keep source text immutable. Bind annotations to a source hash and validate UTF-8 byte ranges and references.
- Keep stable character identity separate from names, narration roles and backend-specific voices.
- Preserve human corrections. Model suggestions must pass application validation before commit.
- Keep credentials, model weights, private novel text and run output out of Git.
- Maintain plain versioned JSON and illustrative samples together; the current samples are not a frozen schema.
- Use Mermaid for diagrams. Track implementation status honestly in the README roadmap.
- Follow `docs/brand.md`; final image assets and generation records live under `assets/brand/`.
- Keep workspace tests, formatting, Clippy and rustdoc checks passing. The CLI provides help, version, explicit-file validate, analyze, inspect, correct, run, resume and run-inspect. Correction/state workflows and chapter-level recovery exist; arbitrary earlier-chapter reanalysis, full identity merge/undo and desktop project recovery remain planned. Keep generated schemas and public examples synchronized with draft DTOs.
- Use named module files (`foo.rs`, with `foo/bar.rs` for children). Keep modules private by default and expose intentional APIs through re-exports. Crate directories are `crates/core`, `crates/model`, and `crates/cli`; Cargo package names retain the `castglean-` prefix. See `docs/engineering.md` for module and test conventions.
- Write OpenSpec proposal, design, spec and task content in Chinese. Keep parser-required structural markers and protocol/code identifiers unchanged.
