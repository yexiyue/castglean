# agent-workspace Specification

## Purpose
为现有工程助手建立以任务目标、可信状态、必要回答和可审阅结果为中心的交互契约。用户能够在原文与助手之间持续工作、理解运行目标及恢复动作，并在不重复模型请求、不丢失草稿或人工修正的前提下处理已交付的专业任务。

## Requirements

### Requirement: 对话与专业任务分层展示
系统 SHALL 将普通对话与专业任务区段区分；专业任务默认显示目标、状态、结果摘要和主要动作，工具过程、模型思考与用量按需展开。没有可展示内容的空回复不得占据独立助手行，未经观测的阶段、进度或费用不得伪造。

#### Scenario: 通过快捷入口分析章节
- **WHEN** 用户从当前章快捷入口启动分析且没有父助手工具调用
- **THEN** 显示对应章节的独立任务区段，分析与只读预审可分别查看，不增加用于展示的模型路由或总结调用

#### Scenario: 普通讨论包含读取工具
- **WHEN** 助手仅读取目录或原文并作出解释
- **THEN** 保留自然回复与可展开过程，不将每个工具当作新的专业任务或复制结果主操作

### Requirement: 任务身份与继续尝试稳定
系统 MUST 按稳定调用身份及明确父子/尝试关联组织任务，不能按展示名称合并。挂起后继续可关联原任务，重试保留旧尝试及其结果；分页、快照、重连和乱序通知不得重复区段或将旧失败改为新成功。

#### Scenario: 同名任务与嵌套预审
- **WHEN** 同一会话先后两次分析同章且各有只读预审
- **THEN** 两次专业调用分别存在，各自预审归属正确，未完成或失败的调用不被另一调用成功覆盖

#### Scenario: 回答后新运行及前置历史
- **WHEN** 用户回答已保存的问题形成新运行，随后加载更早历史或重连
- **THEN** 可关联任务延续原分组，保留新尝试关系和旧事实，不复制消息、问题或结果操作

### Requirement: 状态与下一步动作一致
系统 MUST 区分受理中、排队、运行、停止中、等待回答、成功、失败、中断、取消和读取失败。计算完成与结果待采用分别表达；每项恢复动作说明其是在读取已有状态、核对原请求还是创建执行尝试，未知用量保持未知。

#### Scenario: 请求受理未确认
- **WHEN** 启动响应丢失且尚未确认原请求是否接受
- **THEN** 保留输入与原身份并优先提供核对，不能显示普通再次发送；确认未找到后才允许按原身份重试或明确停止恢复

#### Scenario: 显式重试失败的请求
- **WHEN** 用户选择重试失败的执行
- **THEN** 收起上一次执行的失败提示并保留已有内容；新尝试失败时显示本次失败，新尝试成功后不再显示旧提示

#### Scenario: 运行中停止
- **WHEN** 用户明确停止正在执行的任务
- **THEN** 提交一次取消意图，显示停止中并保留内容，在宿主确认本地工作退出后才显示已取消，取消失败提供安全说明

#### Scenario: 查看嵌套子任务
- **WHEN** 用户展开分析任务中的只读预审，而宿主只支持整轮取消/重试
- **THEN** 子任务显示真实状态但没有虚假的独立执行操作，停止/重试由所属根任务唯一承载；普通回复没有专业区段时停止由输入区唯一承载

#### Scenario: 候选已经计算完成
- **WHEN** 专业任务成功但结果仍需领域人工采用
- **THEN** 显示计算完成和待审阅，主要动作进入审阅，不能显示已采用、继续占用任务名额或提供无意义的运行停止按钮

#### Scenario: 状态读取失败
- **WHEN** 最近消息或结果状态读取失败
- **THEN** 保留最后已知内容并说明可能过时，重试读取不触发模型，不能将读取失败当成空历史或执行失败

### Requirement: 问题与回答属于同一任务
系统 SHALL 在所属任务中显示问题、目标和一套主要回答界面；等待时保留普通草稿并收起完整普通输入区，不同时堆叠两个大输入框。回答草稿按会话与中断隔离，提交成功以宿主消费状态为准，界面只显示用户回答而非路由协议数据。

#### Scenario: 离开问题并返回
- **WHEN** 用户填写部分回答后切章、切会话或查看原文，再返回该问题
- **THEN** 在当前应用会话内恢复该问题草稿，其他问题及普通输入草稿不被覆盖；未提交回答不承诺跨进程保存

#### Scenario: 回答提交失败或状态不明
- **WHEN** 回答提交失败或受理结果尚未确认
- **THEN** 保留输入并提供相应核对/恢复动作，不盲目创建新执行，不提前显示已回答

#### Scenario: 同一轮存在多个必要问题
- **WHEN** 一轮挂起包含多项必要问题
- **THEN** 可一次完成并提交该轮必要回答，重复提交不重复消费；已消费、过期或跨会话问题不能应用到其他任务

#### Scenario: 当前不支持的问题形式
- **WHEN** 宿主问题需要界面尚未注册的作答形式
- **THEN** 显示安全摘要及暂不可回答的原因，不执行任意界面描述，也不擅自将其当成普通文字答案提交

### Requirement: 普通输入与冻结运行目标分离
系统 MUST 分别说明下次发送的上下文与已接受任务的固定目标。会话、模型设置、原文引用和草稿保持可辨认；切章不转移已接受目标，配置变化仍遵守宿主确认规则，草稿只在对应请求已确认受理后清理。

#### Scenario: 甲章运行期间浏览乙章
- **WHEN** 用户在甲章启动任务后浏览乙章并填写后续草稿
- **THEN** 原任务仍显示甲章，输入区显示下次发送的上下文，原任务结果操作不得应用到乙章

#### Scenario: 迟到失败到达新会话
- **WHEN** 用户切换会话后原会话的发送或核对结果才返回
- **THEN** 错误、草稿和恢复操作仍归原会话，不清空或污染新会话

### Requirement: 次级信息和可访问操作
系统 SHALL 默认折叠过程与思考，以明确名称、文本状态和可访问控件提供展开、停止、回答、审阅和返回。中英、亮暗、小窗口及键盘/IME 操作保持可达；流更新不抢焦点或用户主动移开的滚动位置。

#### Scenario: 小窗口填写长问题
- **WHEN** 用户在 1024×680 英文深色窗口处理长问题并使用输入法
- **THEN** 问题、错误及提交可达，无页面横向溢出，组合输入不会意外提交，返回原文不丢失草稿和焦点归属

#### Scenario: 阅读历史时后台更新
- **WHEN** 用户主动滚离最新内容后任务继续更新或前置加载历史
- **THEN** 阅读位置保持，提供返回最新或定位任务的入口，状态适度播报而非逐字打断

### Requirement: 展示操作不改变执行生命周期
系统 MUST 将查看、展开、切页、订阅恢复与显式执行操作分开；前者不启动或取消模型，也不构造领域成功状态。示例、宿主不可用、真实空会话与读取失败分别呈现，缺少配置的用户能到达设置并返回原位置。

#### Scenario: 后台完成后返回
- **WHEN** 用户关闭助手面板、切页再返回已完成的后台任务
- **THEN** 只读恢复已保存状态和结果，不重新运行或补发取消，保留可审阅结果

#### Scenario: 缺少模型设置
- **WHEN** 真实工程尚无可用模型
- **THEN** 明确说明启动条件并提供实际可达的服务设置入口，返回后保留会话草稿和触发器焦点，不伪造任务或结果

### Requirement: 直接替换旧交互且保留业务数据
系统 SHALL 以单一新交互替换现有 agent UI；不保留旧消息/任务/问题布局的兼容分支或双版开关。现行 AG-UI 会话与领域数据继续可读，工程原文、人工修正、候选及声音绑定不得因界面更新而删除或转换。

#### Scenario: 更新后打开已有 AG-UI 会话
- **WHEN** 用户打开升级前已保存的现行 AG-UI 会话与结果
- **THEN** 直接用新任务与消息交互显示，继续按宿主权限操作，不要求清库、转换工程或恢复旧 agent 协议
