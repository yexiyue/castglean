## Context

生产仍采用逐窗固定JSON；C7实验验证了紧凑源片、批量原子finish与只读预审能减少调用。此次正式采用现有Rig Agent，保留原事务发布、来源绑定和人工保护，不引入ECS。

## Goals / Non-Goals

正式分析复用C7工具、模型支持的可调思考设置、持久诊断及正式代码评测入口。实验运行器不是产品依赖；不修改私人正文，不自动采用AI预审，不保证AI语义准确率。

## Decisions

- 纯C7草稿核心置于宿主章节模块，原文仅在内存保留；标注绑定UTF8源范围。工具失败原子回滚，旁白/未知/歧义严格分开。
- 使用原生Rig Agent与已租用模型，不通过实验helper。工具尝试与用量进入现有消息/运行台账，另在版本化窗口内容保存脱敏阶段诊断和校验后的分析/审阅边界。
- 完成分析后独立只读AI预审，建议保存供人工判断，不能改变已验证草稿。取消/失败后只复用校验完成的阶段，不恢复进行中的模型请求。身份包含协议、提示词、源、角色和配置。
- C7定位证据为宿主源片来源；reason明确标识来源定位而非模型语义论证。详细判断可通过现有讨论路径询问。
- 已知上下文容量按紧凑协议规划，未知容量不假装8k。无累计token/墙钟实验配额，显式输出设置保留，工具次数和连续验证失败设防止死循环的边界。网络传输保护与用户取消保持。
- 思考能力由供应商模型能力解析，默认最低支持档位；未知能力使用供应商默认值。前端仅显示宿主支持选项；执行冻结配置，不能通过任意供应商参数注入。
- 生产无写入评测入口直接执行同一核心/Agent，固定输入、程序和配置摘要，记录实际调用/用量与失败，AI疑点不称准确率。

## Risks / Trade-offs

供应商能力目录可能滞后，未知模型不猜测档位。源片边界可能不足以表达某些语义切分，应保留人工编辑。多轮比单次JSON可能增加输入成本。已完成分析可恢复不等于进行中工具循环可恢复。

## Migration Plan

新窗口格式与旧JSON隔离，保留旧运行数据。现有首次初稿/重分析候选发布事务不变。通过离线核心、原生运行回归和只读真实模型样本验证后记录接受边界。

## Open Questions

真实桌面跨平台/人工语义准确率需要独立验收，不由自动化通过代替。
