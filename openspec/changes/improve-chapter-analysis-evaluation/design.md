# Design

## Context

既有宿主拥有不可变来源、工程事务及运行租约，分析当前逐窗执行，`analysis_windows` 保存完成步骤。真实实验确认①②③可整章快速交付，也发现嵌套引语误判；单次盲预审命中该问题。需要让新流程与原冻结运行恢复语义兼容，并让两个工作树使用同一客观评测。

## Goals / Non-Goals

**Goals:** Rust 宿主预切片、区间紧凑输出、统一角色快照、有限并发、只读预审、持久步骤和安全 trace；固定公开数据和共享适配器协议；与隔离 ECS 原型比较。

**Non-Goals:** 自动人工确认、静默覆盖修正、复活旧库、默认迁移 ECS、整包引入编码 agent harness、公开私人小说或凭据。

## Decisions

1. 新运行冻结协议版本；旧冻结运行按其既有协议执行，不能恢复时换提示词。新流程模块与原执行器共享最终发布事务，只有完整标注和有效预审后发布。
2. 宿主为片段保留精确 UTF-8 范围、引语层级和外层话语身份。角色发现只声明候选，宿主一次分配稳定 ID 并持久化；已确认身份用短键映射，禁止按显示名自动合并。
3. 标注最多两路并行，读取相同正文/角色快照、只输出各自连续目标区间；以真实完成峰值和限流 trace 验证。全局模型请求槽位与父任务准入分开，取消阻止等待中的新请求。
4. 复用 `analysis_windows` 的版本化 JSON journal，负序号保存人物/预审步骤、非负序号为标注片段组。指纹包含来源、分区、配置、提示词、协议及参数；完成结果复用，失败尝试保留历史；未知在途步骤只有明确继续才能再次请求。
5. 每次请求记录 Span/Usage/错误，不保存请求正文到默认 trace。现有助手消息的用量仍只表示最新请求，不把并发总量冒充上下文占用。预审问题通过宿主诊断入口可查，模型未审阅状态不变。
6. 评分契约见 `docs/desktop-studio/ai-evaluation-contract.md`。固定规范角色 ID 避免名字字符串误配；客观完整性和 gold 评分与 reviewer 自评严格分开。共享适配器保留 live/mock/replay 身份，失败也进入分母。

## Risks / Trade-offs

- 并行增加重复输入及服务负载 → 先固定两路、全局配额，记录真实用量与缓存；后续用同集验证三路。
- 预切片过碎与内层称号误判 → 显式引语层级、允许连续 ID 区间输出并以固定嵌套用例回归。
- 预审延迟和同模型重复偏差 → 仅返回问题建议、记录独立阶段成本，以预置错误检错/误报评估，不能把审阅当 gold。
- 旧步骤协议与新代码不一致 → 输入/步骤指纹包含版本；旧运行保留原路径，不能静默复用不兼容步骤。

## Migration Plan

不改变原文、既有人工版本或数据库表结构。新步骤使用显式 JSON 版本，旧记录可读；实验产物留在忽略目录。启用生产路径前完成受控网络、并发/取消/恢复和固定评测；ECS 原型保持独立分支与证据。
