# Spec Delta

## Purpose

为章节分析与 AI 预审提供可复现、版本化的客观质量和性能对照，使提示词、协议或运行时调整有可追溯证据，避免凭模型自我评价、单次成功或编译通过宣称改进。

## ADDED Requirements

### Requirement: 冻结评测输入与规范身份
评测系统 MUST 冻结来源、答案、数据划分和规范人物身份；开发与留出集分开，适配器不得接收 gold。私人正文和原始响应不得进入版本库。

#### Scenario: 名称相同但身份不同
- **WHEN** 两个人物显示名相同
- **THEN** 按规范身份评分，不通过名称合并提高正确率

#### Scenario: 提示词改动对照
- **WHEN** 比较两次评测
- **THEN** 记录数据、程序、配置及提示词/协议摘要，不同数据或答案的报告不得当作可比回归

### Requirement: 完整交付与客观质量
评测系统 SHALL 先验证完整覆盖、UTF-8、身份、证据和类型约束，再计算固定单元和逐字节质量；失败、缺失用例和未交付必须留在计划分母。

#### Scenario: 有效 JSON 漏掉空白
- **WHEN** 输出可解析但未覆盖完整来源
- **THEN** 计作未有效交付，不仅凭被覆盖片段计算成功率

### Requirement: 预审检错与误报
评测系统 SHALL 用预置已知错误和正确片段分别计算 AI 预审的检出、遗漏及误报，AI 自评不能充当答案。

#### Scenario: 预审未报告错误
- **WHEN** 错误夹具的 AI 预审返回无问题
- **THEN** 计入漏检，不把其“通过”解释为正确
