# 设计：归属规则与独立评测基线

## Context

历史评分仅比较人物显示名，不能区分同名身份，也没有完整记录计划运行的失败分母。生产流程已具备确定性校验和有限修复，本轮仅完善独立判断标准。

## Goals / Non-Goals

目标：冻结四十例原创金标，区分格式交付、语义归属与身份对齐不确定性；保留可重算产物与安全报告。非目标：修改生产提示词、协议、Rust 公共 API、接受条件或加入 Agent、跨章状态和集成。

## Decisions

- 公开语料置于 `evaluations/attribution-v1`，正文、现有 JSON 格式与评测元数据分离；开发、留出各二十例，每类各两例。调用前固定逐文件 SHA-256 与语料版本，缺陷修订必须升级版本。
- 标注政策承认有明确锚点、可追踪的匿名人物；确定归属需要唯一指向，有限候选需要至少两个具体身份，不能限定来源则未知。
- Python 标准库负责语料核对、评分和运行；Rust 测试验证所有金标的 Schema 与应用合同，运行时使用现有 CLI 再验证模型产物。
- 身份匹配边必须同时满足允许称呼相交和证据范围覆盖身份提及。枚举章内最大基数的一对一匹配，再以仅属于一个金标身份的明确称呼匹配数量优先；不使用台词正确率挑映射。同名的等价匹配保留全部解，严格归属得分取下界。搜索超过一万完整解则报告无法可靠对齐，不任选一个映射。
- 用 UTF-8 字节交叠对齐不同切片。表达单元必须所有交叠切片的类型与归属均正确；表达类型按全章字节计算。模型失败仍占计划分母。
- 清单预先写入全部计划运行，随机种子默认 42，逐次保存真实顺序、输入及答案摘要。每个后端串行且不重试网络请求；本地和 MiniMax 各四十例两次，预算采用已有对照值。
- 每次成功运行记录用量；不可知费用字段保留 null，公开汇总区分已观察用量与全部费用未知。运行清单和完整产物放入忽略目录。

## Risks / Trade-offs

短场景只建立可复核基线，不能代表长篇效果。身份证据交叠是评测对齐规则而非生产接受条件，宽证据会产生多解，必须报告上下界。同名无法可靠对齐不能当正常成功。评分工具独立于 Rust 业务，重复检查仅用于保护评测有效性。

## Migration Plan

保持历史六例及评分入口不变。先完成政策、语料与离线反例测试，再冻结并实测。根据留出集错误类型讨论可验证引文，不在本轮根据分数调提示词。

实测复核确认元数据不足后，保留 v1 的全部摘要和 160 次运行；单独创建并冻结 v2 勘误，不用 v1 输出回算 v2 得分，也不追加模型运行。v2 未实测的状态必须明确，下一轮对照在调用前选择新冻结版本。
