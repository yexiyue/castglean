# 技术设计

## Context

动机见 proposal.md。目前 core 是私有模块占位，人工 JSON 未冻结。库接受内存输入，不依赖宿主配置路径或 CLI。

## Goals / Non-Goals

目标：区分可编辑未校验 DTO 与只读已校验结果；在 core 维护原文及引用约束；提供确定性多章校验。

非目标：自动切片、模型、语义准确率承诺、持久化事务、修正引擎、重叠语义台词和外部集成。

## Decisions

- CRLF 与独立 CR 转为 LF，其余 Unicode 和空白保留。导入记录两种摘要；保存后的正文直接检查，不隐式规范化。原始导入摘要在缺少原始字节时只能检查语法。
- 独立 ID、已校验范围与公开草案 DTO 字段。校验器消费角色表及完整章节、快照集合，返回拥有数据的只读结果，避免外部修改破坏约束。
- 证据只在显式提供的集合内解析，缺少跨章证据视为错误，不自动加载文件。
- 归属使用 status 标记枚举：resolved、ambiguous、unknown。歧义至少两个不同有效候选；speech、thought 必须有归属；旁白与引述可省略，已知第一人称叙述者可有确定归属。
- 可选示意声音画像保留，非 unknown 属性和印象要求证据。未知字段拒绝，扩展限角色表、人物、章节、片段的 extensions 对象。
- 仅支持草案格式 1 与规范化 1；Schema 从 DTO 生成检查结构，程序额外验证正文和引用。
- CLI validate 使用 --characters、可重复且顺序配对的 --annotations 与 --source。正文是保存后的快照，只读输入，不匹配或校验失败返回非零。
- JSON 使用调用方读写流；库使用示例和显式 Schema 导出示例独立于凭据和阅读器。

## Risks / Trade-offs

- 完整证据集合要求调用方提供引用章节 → 文档说明并测试缺失章节。
- DTO 可变 → 只读已校验结果维护约束，修改克隆须再验证。
- 样例缺少导入摘要 → 保留原文，补充摘要且继续标为草案。
- Schema 依赖升级可能漂移 → 生成值同步测试与离线校验测试。
- 结构校验不证明语义归属正确 → 文档明确区别。

## Migration Plan

更新草案字段与样例，不修改正文。无已发布协议，不迁移私人数据或修改外部项目。
