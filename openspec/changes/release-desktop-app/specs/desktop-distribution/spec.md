# Spec Delta

## Purpose

让用户从可追溯的发布页获取适合自己设备的桌面安装包，让维护者能够用同一套记录核对构建身份、公开资产、发布内容和实机验收。

## ADDED Requirements

### Requirement: 可追溯的分发版本

每份正式安装包 MUST 关联唯一版本标签、应用与引擎提交、目标架构、构建记录和最终资产摘要。首发 MUST 提供 Apple Silicon 签名公证 DMG 和单一 Windows x64 签名 NSIS 安装器，并注明最低已验证系统以及可选 CUDA 的已验证硬件和驱动要求。

#### Scenario: 构建资料与标签一致

- **WHEN** 发布标签构建成功
- **THEN** 标签、实际应用版本、清单和资产一致，安装包可追溯到实际构建的 CastGlean 与 TaleChime 提交

#### Scenario: 发布输入不完整

- **WHEN** 标签与应用版本不符、实际引擎提交偏离锁定值、必需签名不通过或分发资产缺失
- **THEN** 该版本无法进入公开稳定发布

### Requirement: 候选验证与稳定晋级

稳定版 MUST 在公开前验收草稿中的实际分发资产。晋级 MUST 保持已核对的标签、资产内容和签名。候选版 MUST 具备清晰标识并与稳定更新源隔离。

#### Scenario: 从草稿发布

- **WHEN** 维护者发布已有实机验收记录的草稿
- **THEN** 公开页面提供审核过的同一批资产，匿名下载后的摘要与验收记录一致，稳定更新源指向该稳定版本

#### Scenario: 平台证书尚未配置时构建候选

- **WHEN** 从 `develop` 历史中的候选标签构建 Apple Silicon 和 Windows x64 安装包
- **THEN** 构建允许跳过 Apple Developer ID、公证及 Windows Authenticode，Apple Silicon 应用使用 ad-hoc 签名，全部更新资产仍必须通过候选更新签名及版本校验

#### Scenario: 候选包用于实机验证

- **WHEN** 候选版可下载
- **THEN** 页面标明预发布，普通稳定客户端不会收到该候选的更新提示

#### Scenario: 重试发现资产变化

- **WHEN** 同版本重试生成与已登记资产内容不同的同名文件
- **THEN** 晋级停止，维护者能够定位冲突版本及资产

### Requirement: 用户可理解的版本发布页

每个公开稳定版的 Release MUST 提供版本和渠道、用户可见变更、平台和最低系统要求、安装与升级方式、已知问题、许可和反馈入口。手动安装资产、校验材料与应用更新资产 MUST 可以明确区分。

#### Scenario: 用户首次下载安装

- **WHEN** 用户访问首个稳定版发布页
- **THEN** 用户能找到对应系统和架构的安装文件、校验信息、安装步骤、合成设备支持范围和首次合成所需的模型准备说明

### Requirement: 实际装包验收

稳定版 MUST 在目标平台用将要公开的安装包验证首次启动与单章制作。验收记录 MUST 给出系统、架构、应用版本、安装包摘要、样本与模型，以及每项检查的结果。

#### Scenario: 干净环境完成单章

- **WHEN** 验收人员在声明支持的两种系统上分别从下载的 DMG 和 NSIS 安装包安装，使用干净用户数据目录和公开样章
- **THEN** 应用通过系统分发验证并能启动，可导入 TXT、准备模型、生成与播放、局部重做和采用、关闭重开并导出可读取的 WAV

#### Scenario: Mac 使用系统 GPU 合成

- **WHEN** 用户从 Apple Silicon 安装包启动并准备已支持 Metal 的模型
- **THEN** 应用能使用 Metal 完成一章合成，并提供该模型可用的 CPU 选项，无需另装 GPU 开发工具

#### Scenario: 无 NVIDIA 显卡的 Windows 可完成制作

- **WHEN** 用户在无 NVIDIA 显卡和 CUDA Toolkit 的 x64 Windows 上安装并准备首发模型
- **THEN** 用户可以用 CPU 完成整章生成、播放和导出

#### Scenario: Windows 使用 NVIDIA GPU 合成

- **WHEN** 用户在有已验证的 NVIDIA 显卡及兼容驱动、未安装 CUDA Toolkit 的 Windows x64 上安装应用并在模型中心准备 CUDA 运行库及受支持的模型
- **THEN** 应用通过实际设备探测后开放 CUDA 选项，用户可完成整章生成、播放和 WAV 导出

### Requirement: Windows 按需准备 CUDA

Windows 桌面宿主 MUST 在无 NVIDIA 驱动和 CUDA 运行库时启动并提供模型支持的 CPU 功能。用户明确选择启用 CUDA 后，宿主 MUST 判断模型、GPU、驱动与运行库是否兼容，显示所需运行库的版本和下载大小，并提供可重试的准备流程。运行库 MUST 使用可验证的固定来源和完整性校验，按版本独立安装且仅启用完整验证的版本。

#### Scenario: 驱动或设备不可用

- **WHEN** 用户选择 CUDA，而没有兼容的设备、驱动过旧或实际探测失败
- **THEN** 模型中心显示可操作的原因，缺驱动或驱动过旧时提供 NVIDIA 驱动链接，仍允许使用模型支持的 CPU

#### Scenario: 下载中断或校验失败

- **WHEN** 用户准备运行库时网络中断，或下载内容与固定版本的验证信息不匹配
- **THEN** 应用可继续使用，可信的未完成数据可续传，失败字节不会成为可加载的组件，已有可用运行库得以保留
