# Design

## Context

正文浮条的 `sourceSelection` 当前返回引用文字及行号，`sourceSelectionBookmark` 另有两个端点的行号与 UTF-16 偏移。现有 `chapter_analysis_edit` 要求本章已有当前版本，既有角色操作支持确认、改名、别名和复用。版本发布由宿主负责。有效版本按绝对 UTF-8 范围完整分区，同源分析已支持应用非冲突差异，音频预检使用当前版本和工程绑定。

## Goals / Non-Goals

**Goals**

- 将选区、结构覆盖、人工保护与生成就绪建模为可独立验证的状态。
- 复用现有宿主修订、历史、回执、候选合并和声音绑定边界。

**Non-Goals**

- 引入可编辑正文、可编辑音频片段或第二套人工标注持久化体系。
- 用 TTS、分析模型或后台任务补偿未完成的人工选择。

## Decisions

### 1. 选区浮条冻结来源范围

沿用正文浮条的图标和可访问名称。能确认是当前章的连续原文选区时，从选区浮条打开居中的归属对话框，展示简短原文、片段类型及可搜索工程角色。台词作为初始表单选项，只有显式确认才落盘。新角色在同一表单中创建。切换到旁白即隐藏角色字段。保存时锁定目标，确认或取消后恢复阅读与焦点。

复用并扩展选区坐标逻辑。按原文叶记录取得两个真实端点，反向选择规范化为正序，将行内 UTF-16 偏移映射为绝对 UTF-8 字节范围。折叠的空行允许位于选区中间，前提是宿主能从原文证明跨越的区间完整。保留 DOM 选区或复制文字作为界面预览，宿主以来源 ID、摘要、章范围、绝对字节区间和期望修订校验，不凭预览字符串搜索回填。已有片段内的精确选区和跨片段重标注用同一条写入路径。

### 2. 人工版本沿用完整分区

在归属版本中引入明确的未标注区间。对新格式，类型化表达仅由宿主创建的未标注状态，无人物身份和人工确认；模型仍输出旁白、台词和内心独白。第一次写入按照章范围构造覆盖分区，再按选区切分并赋予人工类型与归属。前后未选中的有声文本保持未标注，纯空白按既有覆盖规则确定性归并。后续改部分范围时，保留区间外原片段内容、证据和保护；被切出的片段证据须与各自范围重新校验。

未标注占位与真正的未知说话人分别统计。采用完整分区是为了沿用既有定位、历史和一条当前版本指针。将缺口标为旁白会造成意外朗读，用未知台词占位则会误报类型及人工审阅状态。

### 3. 归属、角色及首次撤回事务

在宿主增加针对原文范围的人工命令，输入包含工程、章节、来源、期望归属修订与稳定命令 ID。首次预期修订使用无当前版本身份。事务内重放回执、复核来源/章范围与期望修订、验证角色同工程且可用、新建角色（按需）、提交新版本及保护并推进指针。复用版本校验和现有角色名称规则。一次提交覆盖此次新角色和归属，失败全部回滚。无效或已失效的旧版本不作为范围外内容来源，首版提示先恢复有效章版本。

首次标注在同一次事务中写入可撤回的初始状态，以便撤回后没有有效人工标注，同时保持修订单调和历史可查。后续撤回沿用原编辑栈。撤回不删除稳定角色或任何声音与音频。提交失败、回执不明与保存后回读失败复用现有恢复语义。只有字节范围及原决定重新确认后才创建新命令。

### 4. AI 发布与生成共享最新宿主状态

在 AI 发布事务中核对任务冻结的同源归属修订。AI 与人工使用同一版本次序：用户在已保存人工归属后显式发起分析，发布时若同章仍是任务冻结的修订，则按新结果更新归属，无需额外授权。覆盖已有人工内容时，在分析入口说明可能改变归属，并在持久结果提示本次更新了人工归属，可从现有版本历史撤回。发起后已有新版时，晚到结果不得覆盖较新修改；沿用现有拒绝过期发布或同源非冲突补全路径，只有未变更、未标注的范围可补全。来源变化仍遵守既有失效与候选约束。人工提交同样按确认时冻结的修订校验。

对多角色预检和实际启动增加可定位的未标注阻塞。用户可从现有检查弹窗回到对应原文，或在那里确认将本章其余未标注段设为旁白。批量确认前显示作用范围；只为当前版本缺口生成一笔修改，核对锁内修订，不能把未知、歧义或已确定归属一并改成旁白。完整手工版本通过现有音色与资源检查后直接使用。单旁白计划仍与归属版本无关，播放及导出按既有冻结版本语义。

## Risks / Trade-offs

- 浏览器 DOM 与宿主字节边界错位。覆盖正反选区、同一行多角色、折叠空行、分页、混合换行、emoji、组合字符与旧选区，宿主按原文重验。
- 首次写入可能与 AI 发布、切章、角色写入或目录拆合竞争。使用工程事务锁和期望修订，校验后才发布并记录回执。
- 部分归属容易被误判为 AI 已分析或生成就绪。区分无标注、部分标注与归属完整；生成宿主独立校验，不从 UI 标签推断状态。
- 角色列表为空或名称重复。提供同一次确认的角色创建，显示同名候选；新建与复用均显式区分。

## Migration Plan

新读取路径继续接受既有版本和历史数据，旧片段不转换为未标注。只有包含新状态的归属版本使用新增的格式判别，沿用现有 SQLite 版本、历史和回执表。旧客户端若不能识别新格式应拒绝读取或写入该版本；交付时验证旧版本失败行为并记录回退需使用升级前备份，避免逆向改写用户数据。没有新格式数据的老工程可原样打开。更新数据格式文档和 IPC 生成类型。
