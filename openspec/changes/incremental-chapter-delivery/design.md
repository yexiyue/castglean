# Design

## Context

analysis.rs 顺序校验/apply 窗口，角色仅追加、目标范围不重写，最终完整校验才返回。重分析先恢复原人工确认范围。整章消费的完整类型不能代表未完成前缀。

## Goals / Non-Goals

在宿主 runtime 中交付只读稳定前缀，最终仍返回完整结果；不增加模型请求、线程、自动重试或存储提交。CLI/BookRun 继续章节级持久化，实际 TTS 与崩溃后的发布游标恢复后置。

## Decisions

- 新批次包含运行摘要、序号、book/chapter/source 身份、基础修订、连续片段及所需角色定义，不可由外部构造或反序列化成受信任类型。提供独立 JSON Schema，已有失败报告结构保持。
- 宿主每次显式提供新 execution_key（同时代表宿主模型配置/执行身份）。库将该键、输入正文元数据、配置及完整输入角色/标注上下文绑定成摘要；基于摘要隔离旧执行。运行内序号从 1 开始，基础修订与最终正式修订分开。
- 异步 consumer 接收拥有所有权的批次；成功返回才确认交付。消费等待在有界章节时限内并响应取消。明确记录 offered_end，取消/消费失败时它可能超过确认终点，因为回调已发生的副作用不能撤回。宿主须使用运行身份隔离迟到批次，并将接收实现为原子操作。
- 仅当整个待交付前缀的归属、角色证据、画像证据均位于已接受的本章范围或已有输入上下文时发布；后文证据造成延迟，不提前传出未经接受的标注。批次携带必要角色定义，前章证据由宿主与 consumer 共用的已校验输入上下文解析。
- 单一执行逻辑接受可选交付上下文；普通入口不发布，增量入口保留原分析失败与交付进度。书级入口复用相同人工保护和最终 finish，失败不修改宿主状态。回调拒绝作为安全类别，不携带任意宿主错误文本。
- 成功返回是唯一完成确认，没有先发 Finished 的第二渠道。全部范围已送出但最终校验失败仍返回失败，宿主不得 seal。空章没有批次，完整校验成功后返回成功。

## Risks / Trade-offs

- 消费副作用与取消竞态 → 确认进度为下界，保留未确认送出范围；宿主显式失败/停止旧执行。
- 后文证据可延迟至整章 → 保守等待保证可解析性，不承诺每窗立即送出。
- 人工修正可能引用后文 → 恢复保护后检查证据闭合，修正另开 execution_key，不改旧批次。
- 增量完整返回后书级最终操作仍可能失败 → 保留进度并返回书错误，宿主只在整个调用成功后封闭声音计划。

## Migration Plan

纯新增入口与批次格式；旧 JSON 状态及整章调用不迁移。无提示词/分区或默认接受条件变化，已有冻结运行指纹不改变。
