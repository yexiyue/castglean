# Design

## Context

章节音频以「任务」为中心：一次任务冻结分析版本、来源、模型组合与合成文本语义，按顺序合成单元并在全部成功后拼接整章。任务可在冻结输入完全一致时续跑；归属或声音变化后续跑被拒绝，只能从头生成。停顿编排、播放计划和 WAV 导出都归属单个任务，目前没有「版本」概念，也没有采用关系。

相关契约尚未并入主规格，分别位于活动变更 `chapter-audio-generation`、`chapter-audio-workbench` 和 `refine-chapter-audio-workbench` 的增量规格；本变更在其上追加。

## Goals / Non-Goals

### Goals

- 修正归属或音色后，只重新合成输入发生变化的单元，其余单元沿用已落盘音频。
- 失败任务在输入变化后也能沿用仍然一致的单元。
- 保留旧版本并可回到、可试听、可重新采用。
- 同输入重录指定单元，结果先待采用，由用户显式决定。
- 导出只使用当前采用版本。
- 派生版本保留仍可精确锚定的停顿。

### Non-Goals

- 不提供版本删除、清理或磁盘预算管理。
- 不支持跨版本按单元拼装一个采用集合；采用粒度是整个版本。
- 不提供字级对齐、任意选区替换或自动质量判断。
- 不改变全局单活动任务、引擎线程、推理闸门与媒体身份协议。
- 不建设工程侧「音频制作」页或版本对比视图。

## Decisions

### D1：版本即任务，不另建候选表

每次派生都建立一个新的章节音频任务（版本），沿用单元作为该任务的已完成单元写入。原因：现有状态机、进度、取消、续跑、启动恢复、媒体登记和播放计划全部以任务为中心，派生任务可以原样复用；「同一任务内不得混用不同输入」的约束保持不变，因为派生任务冻结的是新计划。代价是每次派生都会写入一组新的单元行，个人单章规模下可以接受。

任务新增种类：`generation`（整章生成）、`redo`（按当前计划局部重做）、`retake`（同输入重录）。

### D2：沿用判定是纯函数，依据原文范围与实际声音

计划单元可沿用来源单元，当且仅当：来源任务与当前计划的后端、模型、合成文本语义和制作方式一致；两者原文范围（起止字节）相同；实际声音相同；空白标记相同；来源单元状态为已完成且音频文件存在（或两者均为空白）。

选择原文范围而不是单元序号或片段 id 作为匹配键：来源不可变且切分确定，同一片段范围必然得到同一组单元范围；归属修订或重新分析可能改变片段 id 和数量，但未修改片段的范围不变。目标归属可以不同（例如两个角色绑定同一预置音色），只要实际声音相同，音频就有效，派生任务记录新目标的身份。

没有单元可沿用（模型组合变化、章节范围变化等）时退化为完整生成，界面不显示重做数量。

### D3：沿用产物是独立副本并签发新媒体身份

派生任务目录下为每个沿用单元建立 `unit-<序号>.wav`：同卷优先硬链接，失败时回退为复制；随后为派生单元签发新的媒体身份。原因：现有启动恢复按 `(run_id, index)` 推导单元文件路径，任务目录自包含可让恢复逻辑不变；写入单元时先写临时文件再改名，不会就地修改被硬链接的旧内容。副本准备先于数据库事务；进程在两者之间退出只会留下没有任务行的文件，不产生可播放的错误事实。

### D4：采用状态由任务行持有，至多一个当前采用版本

任务行新增 `adoption`：`none`（未涉及，含被取代的历史版本与未完成任务）、`adopted`（当前采用）、`pending`（待采用）、`rejected`（已放弃）。部分唯一索引保证每章每种制作方式至多一个 `adopted`。

- 整章生成与局部重做成功时，在写事务内复核冻结计划。仍与当前归属和声音一致时采用，原当前采用版本回到 `none`。已过期的结果保留为历史。
- 重录成功时进入 `pending`，等待显式采用或放弃。默认播放和导出仍指向当前采用版本，试听新版单独指定待采用任务。
- 采用要求版本完整（全部单元已有可读音频或为空白）且与当前归属、声音一致；不满足时返回冲突，当前采用版本不变。
- 放弃只作用于 `pending` 版本，将其置为 `rejected`；不删除文件。
- 采用与放弃是幂等命令，以操作 id 登记命令回执；相同操作重放结果，不同内容复用同一 id 返回冲突。
- 当前版本解析：存在完整可播的 `adopted` 版本时取之；否则回退到最近的、非待采用且非已放弃的完整可播任务（覆盖迁移前已存在但产物缺失的记录）。已放弃版本不作为章节状态展示。

与当前计划不一致的当前采用版本仍是「当前」，但标记为需要重做：导出被拒绝，播放栏把重做作为下一步。

### D5：发起请求按意图区分

`chapter_audio_start` 接收 `ChapterAudioStart`：

- `Resume { run_id }`：续跑同一计划的任务，冻结输入不一致时返回冲突。
- `Fresh { inherit_from }`：按当前计划建立新任务；给出沿用来源时沿用一致单元，来源与当前计划无任何可沿用单元时完整生成。沿用来源与当前计划完全一致且已完整时返回冲突，不建立空任务。
- `Retake { run_id, units }`：对完整且与当前计划一致的版本重录指定有声单元；其余单元全部沿用。

预检 `chapter_audio_check` 增加可选的沿用来源：计划就绪时同时返回可沿用单元数、需重做单元数及重做单元位置，供界面在发起前显示范围。预检只读，不建立任务、不复制文件。

### D6：停顿按锚定边界精确继承

派生任务建立时读取来源任务的停顿编排，把每个停顿的锚点（所在单元的结束字节）映射到派生任务中结束字节相同的单元；映射成功的停顿写入派生任务的编排修订 1（不可撤销，因为它不是用户的编辑），无法映射的停顿舍弃并计数。来源任务的编排不变。沿用来源不可用时（例如来源没有编排）派生任务从空编排开始。

这与「新计划不自动转移停顿」不冲突：未经沿用建立的全新任务仍不继承；派生任务只转移边界完全一致的停顿，不做任何位置推测。

### D7：导出与播放

导出要求任务为当前采用版本且与当前计划一致，并沿用既有的完整性、冻结修订和原子发布检查；历史版本与待采用版本的导出入口不可用并说明原因。播放不限制采用状态，任何版本都可以按任务身份试听，以便比较重录结果。

### D8：工作台入口

- 下一步：当前采用版本与当前计划不一致时，主操作显示「重做 N 段」（N 为预检返回的需重做单元数）；没有可沿用单元时显示「生成新版本」。
- 进度：派生任务进行中只统计实际重做的单元，不把沿用单元计入已完成进度。
- 片段检查器：当前采用版本中已生成的单元提供「重做此段」，发起对该单元的重录。
- 试听比较：待采用版只有一套决定操作。新旧试听按同一原文范围定位，播完对照单元停止。查看历史版时，主播放键指向被查看的版本。
- 版本列表：底部播放栏提供按时间排列的版本列表，标明当前采用与待采用；选择历史版本即查看该版本的单元、停顿和播放，并提供返回当前版本；与当前计划一致的版本可重新采用。
- 待采用决定：最新任务为待采用版本时，播放栏就地显示试听、采用、放弃；不弹窗、不抢焦点、不自动采用。决定入口随状态持久，重启后仍在。
- 派生时舍弃了停顿的情况下，在任务状态旁如实说明舍弃数量。

### D9：数据库 v13

`chapter_audio_runs` 增加 `parent_run_id`（可空）、`inherited_units`、`dropped_pauses`（默认 0）、`kind`（默认 `generation`）与 `adoption`（默认 `none`），并建立当前采用版本的部分唯一索引。迁移时把每章每种制作方式最近一个成功的任务标记为 `adopted`，使其继续作为当前版本；其余保持 `none`。新列都有默认值，既有插入语句不需要改写。

## Risks / Trade-offs

- **采用粒度是版本而非单元。** 用户不能把重录版本的某一个单元与其他版本混搭，只能采用整个版本。重录本身只改变指定单元，因此「采用重录版本」与「只换这一段」在效果上等价；若用户同时修改多处并想分别取舍，需要逐处重录。跨版本拼装留给后续「音频制作」页评估。
- **重录结果可能与原音频相同。** 合成不保证随机性变化；界面不承诺「每次不同」，只提供比较与采用。
- **硬链接依赖同一卷。** 数据目录内的任务目录总在同一卷；硬链接失败时回退为复制，占用额外空间，功能不受影响。
- **迁移标记的当前版本可能缺文件。** 当前版本解析保留回退：采用版本不完整可播时，回退到最近的完整可播任务，不伪造可播放状态。
- **规格同步顺序。** 本变更的 `MODIFIED` 针对尚未并入主规格的需求，归档时必须排在 `chapter-audio-generation`、`chapter-audio-workbench`、`refine-chapter-audio-workbench` 之后。
- **命令入参不兼容。** `chapter_audio_start` 改为按意图区分的请求，前端与测试夹具一并更新，不保留旧参数。

## Migration Plan

- 数据库：v12 → v13 单事务增量，新增列与索引，不改动既有行以外的数据，不移动或删除任何音频文件。
- 既有任务：最近成功任务成为当前采用版本，行为与迁移前「最近可播任务」一致；更早的成功任务保留为历史版本，可查看和重新采用。
- 绑定：重新生成 Specta 绑定，前端一次性切换到新的发起请求，不留兼容分支。
- 文档：同步 `docs/data-format.md`、README 路线图、知识库索引与决定记录。
