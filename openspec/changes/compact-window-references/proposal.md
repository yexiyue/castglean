# 窗口内短引用

## 为什么

本地小说六例原模式五次截断，引文模式六次全部截断。正式片段 ID 含正文摘要，反复返回造成显著的协议负担；先压缩引用，再衡量交付和语义。

## 变更内容

- 输入使用窗口内 s0、s1 片段引用和 c0、c1 已有人物引用。
- 纯转换步骤恢复正式身份、证据及引文引用，再执行现有程序校验；反馈使用同一窗口的短引用。
- 默认与引文提示词版本分别递增至 7、8，生成接口、DTO、最终数据和预算保持不变。
- 离线验证，再运行两个后端原创开发集各二十例、小说补充组各六例，两种证据模式各一次，原计划共 104 次；按用户追加要求，GLM 使用同一语料与预算执行旧、新协议两模式各 26 次，追加 104 次，本轮合计 208 次。冻结答案不变，不使用留出集调参。

## 能力

### 新能力

- `window-reference-transport`：隔离窗口内模型引用与正式领域身份，完整还原及安全拒绝未知引用。

### 修改的能力

无已同步主规格。

## 影响

core 私有协议与窗口执行、提示词版本、测试和 Python 运行版本记录。自定义模型实现须回传本次请求提供的引用，不得假设输入即正式 ID。没有新增 crate、依赖、存储、Agent 或跨章自动合并。
