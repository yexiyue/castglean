# 窗口引用传输

## Purpose

将模型请求内的短引用与正文绑定的正式片段和稳定角色身份隔离，减少重复传输，同时在提交前恢复全部引用并执行原有应用校验，避免压缩协议改变正文坐标、人物命名空间及人工修正。

## ADDED Requirements

### Requirement: 请求内引用

系统 SHALL 向模型提供当前可见片段及已有角色的短引用；首次与修复须共用同一解释范围，短引用仅在当前窗口有效。

#### Scenario: 窗口切换

- **WHEN** 顺序分析进入下一窗口
- **THEN** 引用由当前可见数据重新建立，不携带前一窗口的失败候选或反馈

### Requirement: 提交前完整还原

系统 SHALL 在业务校验之前还原目标、证据、引文和已有角色引用，并保存正式 ID；新角色的临时引用须保持独立命名空间。

#### Scenario: 已有人物与新人物同名短引用

- **WHEN** 模型同时使用 existing c0 与 new c0
- **THEN** 前者指向请求中的已有身份，后者仅指向该响应声明的新身份

#### Scenario: 引文保存

- **WHEN** 引文模式建议通过全部校验
- **THEN** 保存的引文包含正式片段 ID、程序计算的 UTF-8 范围及正文摘要

### Requirement: 未知引用安全拒绝

系统 SHALL 拒绝没有提供、非规范或错误命名空间的短引用，复用有限修复和预算；失败不得应用或发布候选。

#### Scenario: 未知引用

- **WHEN** 候选返回不存在的片段或已有角色短引用
- **THEN** 返回程序生成的安全问题，反馈不得回传任意拒绝值

### Requirement: 行为及数据兼容

系统 SHALL 保持生成方法签名、DTO 字段、最终 JSON、正式身份、正文范围、人工确认和接受条件，记录本轮实际提示词版本。

#### Scenario: 旧产物

- **WHEN** 校验没有短引用的既有正式文档
- **THEN** 继续按原数据与证据规则校验，无需转换或迁移
