# Design

## Context

真实工程由 `ProjectWorkspace` 和 `ImportedWorkspace` 承载；示例工程使用另一套 `ChapterWorkspace` 与静态内容。目录、正文、助手、片段属性和章节音轨已有独立状态及宿主命令。不能以示例静态状态证明真实制作流程可用。现行章节导航要求三个纯图标入口，新方案需修改该要求。

## Goals / Non-Goals

**Goals:** 把完成一章的工作组织为可理解、可返回的连续操作；用共享设计规范约束全产品，保留宿主事实及用户数据安全。

**Non-Goals:** 不把尚未交付的局部重做、批量整书制作或助手自动编排伪装为当前功能；不更改源文件、稳定身份、已有音频或人工保护语义。

## Decisions

### 1. 任务优先的工作台

正文是主要工作面，目录负责选择章节，选中片段后的属性在上下文面板处理，音频区负责进度和播放；助手作为可收起的辅助工作区，不成为分析和生成的唯一入口。分析、声音缺失、生成中、失败和可试听都在当前章明确呈现下一步，操作直接定位到需要处理的位置。相比把所有制作步骤塞进聊天，这样保留可预测的直接操作；相比强制线性向导，允许回看、修正和播放已有内容。

### 2. 共享框架，隔离事实

真实工程和示例共用呈现与交互组件，由不同数据适配器提供事实；示例始终可辨认，示例操作不写真实工程。不能为复用绕过宿主权限、伪造进度或在浏览器假装真实操作成功。工程导航用有文字的可发现入口；窄窗以可访问的展开入口替代常驻文字，而非只靠悬停。

### 3. 视觉方向与设计规范

方向为「安静的制作工作台」：正文和音频是视觉主角，导航、检查器和工具栏形成清晰的背景层次。沿用品牌资产及系统中英文字体，界面主色重新从品牌墨绿和朱红的语义关系出发设计，亮暗分别测量；不把图像品牌色直接当作可用对比度证明。以语义 token 管理颜色、字体、间距、圆角、边线、焦点和状态。列表与分隔线优先于嵌套卡片；样式先通过真实窗口检查再固定数值。

### 4. 分阶段落地和衡量

先完成流程和组件审计，以真实 Tauri 界面为唯一可交互设计载体，按一次实际任务复核工作台，再扩展到首页、导入、角色、音色、模型和设置。每阶段保留行为回归：从导入到播放导出、切章、生成失败恢复、面板收放及键盘操作。设计目标是用户能回答“在哪一章、缺什么、下一步是什么、当前播放什么”；不以点击次数的未测量数字宣称改善。

### 5. 状态所有权与恢复

| 事实 | 所有者 | 界面行为 |
| --- | --- | --- |
| 来源、章节范围和归属版本 | 宿主持久化快照 | 正文展示可变，但选择、复制、引用和定位始终使用来源坐标；来源变化时旧分析只读。 |
| 角色身份、人工保护和声音绑定 | 工程及相应行的宿主修订 | 名称不代表身份；候选来源不禁止制作；提交失败保留目标与草稿，未知结果按原命令身份重试。 |
| 分析与生成 | 各任务冻结目标和输入 | 跨章可见原目标，切换不启动、不取消、不重放；失败保留真实已完成结果，恢复或新建由宿主准入判断。 |
| 播放 | 唯一播放会话及冻结播放计划 | 与当前浏览章、选中片段、生成位置分离；暂停、seek、缺口和结束由真实媒体事实驱动；新完成单元不悄悄加入已有播放队列。 |
| 停顿与导出 | 任务关联的编排修订和导出任务 | 播放和导出使用冻结的相同编排；旧音频保留，过期时标记而不伪装成新结果。 |
| 目录、面板、滚动、助手草稿 | 按工程/章节/会话分别保存的界面状态 | 页面和面板往返保留上下文；隐藏面板不能响应快捷键或持有焦点；失败草稿不能被晚到快照覆盖。 |

生成入口使用宿主检查结果，不缓存为新的权威判断。缺失声音指向当前目标，资源问题指向模型中心并提供返回；恢复后的下一步仍须用户明确发起。成功、部分完成、失败、取消、中断及未知提交不可合并为同一个状态。重新读取、重试原请求和新建版本是不同动作。

### 6. 组件决策和验证

继续使用项目已有 shadcn/Base UI 作为通用交互基线，先核对共享包装的行为和无障碍再扩展。目录树评估 React Aria 与现有虚拟树；面板分隔器评估 react-resizable-panels；正文虚拟化评估 TanStack Virtual；波形沿用现有 WaveSurfer 及宿主摘要作为基线。每项对比必须覆盖现有数据语义、键盘、焦点、包体、许可证、维护和平台；不通过桌面验收前不承诺替换。对话、菜单、表单等现有原语不应因混搭另一库产生不同焦点与状态语言。

Motion 用于需要协调布局或可中断状态过渡的候选场景；简单悬停、焦点和反馈由共享样式处理。先在真实桌面比较带/不带 Motion 的同一面板切换，记录生产构建增量、低配置拖动/滚动、快速切换、屏幕阅读和减少动态效果；如无明确收益保留原语/CSS。无论何种方案，焦点、状态持久化、播放、取消和提交都不能依赖动画结束回调。文档来源和候选细节见[组件审计](../../../docs/desktop-studio/component-interaction-audit.md)。

### 7. 与在途规格的衔接

本变更负责信息架构、交互可发现性和视觉一致性，不替换下列领域契约。实施时逐场景对照并在各自任务中记录验收，存在差异时先修订规格再改界面：

- `chapter-audio-workbench`：保留有界连续阅读、跨块来源选择、音轨缺口、停顿修订和一致的 WAV 导出；不能因为替换虚拟化或分隔器破坏字节坐标和冻结编排。
- `attribution-review-and-playback`：保留归属失效语义、固定播放计划、单音源互斥及共享播放条；音色试听抢占和部分生成试听须保持可解释。
- `introduce-hotkeys`：保留作用域独占、输入法组合和平台修饰键规则；局部目录与音轨键盘行为不能被全局快捷键覆盖，弹窗关闭后恢复原作用域。
- 现行 `chapter-production-workspace`：保留模式切换、检查范围、结构影响和窄窗状态；导航可发现性修改以本变更对应的 MODIFIED requirement 为准，不得因此放弃数据保护和上下文保持。

## Risks / Trade-offs

- [全局重组与在途变更冲突] → 按领域和明确文件分批迁移，对未完成变更逐项核对，不重置已有任务。
- [示例适配遮蔽真实宿主缺陷] → 用真实工程和真实任务验收，浏览器模拟与原生结果分开记录。
- [改变面板导致草稿或焦点丢失] → 保持状态所有权与已有持久化边界，覆盖切章、跨面板、晚到结果和键盘焦点。
- [品牌色在暗色中对比不足] → 分主题验证文本、图标、状态和焦点；最终数值以实测为准。

## Migration Plan

以增量变更替换呈现层，保留宿主接口及数据；每个工作流通过回归后切换。必要时可回退前端提交，不迁移或删除用户数据。规范、主规格与 README 随实际交付同步更新。

拟修改范围（实施前须以真实桌面审计和现有状态契约复核）：

| 区域 | 主要文件 | 目的 |
| --- | --- | --- |
| 设计 token、共享控件 | `src/index.css`、`src/components/ui/` | 统一亮暗主题、交互状态和组件几何；保留既有可访问原语。 |
| 应用与工程导航 | `src/components/library-sidebar.tsx`、`src/components/app-sidebar.tsx`、`src/components/projects/project-workspace.tsx` | 显示目的地名称和上下文，整理工程内返回及窄窗导航。 |
| 导入和工程列表 | `src/routes/new.tsx`、`src/routes/index.tsx` 及其所属组件 | 梳理文件、预览、失败恢复和继续制作。 |
| 章节制作 | `src/components/projects/imported-workspace.tsx`、`chapter-directory.tsx`、`virtual-source-reader.tsx`、`chapter-voice-panel.tsx` | 按任务重组正文、目录、上下文与声音处理，保留原文选择和人工编辑语义。 |
| 生成与播放 | `src/components/projects/chapter-audio-bar.tsx`、`chapter-audio-track.tsx`、`src/hooks/use-chapter-audio.ts`、`use-chapter-player.ts` | 整理阻塞、任务状态、失败恢复及单一播放器，不改变宿主权威和编排。 |
| 角色、声音、模型、设置 | `src/components/projects/character-center.tsx`、`src/components/voices/`、`src/components/models/`、`src/components/settings/` | 覆盖管理、资源准备、返回与失败状态。 |
| 示例及验证 | `src/components/workspace/chapter-workspace.tsx`、`src/routes/project.$id.tsx`、`tests/`、`src/locales/` | 设计隔离的数据适配和共享呈现，验证双语、状态、浏览器与原生行为。 |

不得为了共享示例直接复用模拟宿主结果或删除真实接口。独立 HTML 原型已按用户要求移除；应用内独立静态工作台须移除。实施前先定义示例入口、隔离适配器和不支持操作的真实反馈，再切换入口；不得留指向失效页面的链接，也不得删除用户工程。
