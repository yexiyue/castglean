# Spec Delta

## MODIFIED Requirements

### Requirement: 清晰的状态与依赖失效
系统 SHALL 分开显示未分析、运行阶段、有效初稿、归属未定问题、人工确认和失效原因，角色确认与片段确认分别统计。**待检查口径为异常驱动**：仅归属未定（未知或歧义）且未经人工处理的片段计入待检查列表、正文待处理提示与计数；归属已明确但未逐段确认的片段不催确认，不进入待检查统计。失效版本可查看但不能继续当作当前有效标注修改；分章边界改变后仍保留历史，不自动迁移旧标注到新范围。

#### Scenario: 结构有效且归属全部明确
- **WHEN** 初稿通过范围和引用校验且不存在归属未知或歧义的片段，用户未逐段确认
- **THEN** 不显示任何待检查项或待确认提示，章节视为可进入音频生成

#### Scenario: 结构有效但无人审阅
- **WHEN** 初稿通过范围和引用校验但仍存在未知归属和未审阅片段
- **THEN** 不显示“全部正确”或“人工已确认”；待检查仅统计归属未定且未经人工处理的片段，正文仅对这类片段给出待处理提示；人工处理（改定归属或明确保留）后该项从待检查中移除

#### Scenario: 原文结构变化后重开
- **WHEN** 用户调整章节边界后重开分析工作台
- **THEN** 能看到旧版本及失效原因，并有重新分析入口，不将旧范围归属静默套用到新章
