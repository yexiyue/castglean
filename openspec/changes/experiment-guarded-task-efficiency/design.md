# 实验设计

## 分组
baseline与handoff由Git忽略目录内冻结的旧版可执行程序提供：前者保留旧行为，后者仅在受理后停止父Agent。当前源码完全删除旧工具，不保留兼容路径。正式工具只提供compare_rules批量比较与finish_splitting原子候选提交，成功后直接结束。人工采用不进入模型权限。

atomic与batch都使用新工具、新提示词和直接交接：atomic的compare_rules每次最多一个方案，batch每次最多四个。两组差异由Schema与宿主共同限制。atomic相对handoff是工具与提示词收敛的组合效应，不冒充单函数因果消融。

仅实验选项、计量hook和评测桥为cfg(test)，正常应用使用批量工具与直接交接。共同hook记录规范输入/工具摘要、阶段、时间、服务商用量及未知值，工具/候选仍由原准入与事务决定。确定性继续记录事件与依赖身份，不能声称逐事件节省多少token。不同组允许预期不同的实现摘要，每组版本保持冻结，输入与实际模型配置必须相同。

## 数据与公平性
先使用本地原生HTTP/SSE测试错误、终态和权限。公开分章用例提前冻结预期边界，gold不发给模型；私人章节不臆造人工语义真值，记录覆盖、结构、人工修正保护与待采用状态。四组逐用例轮换顺序、串行请求，程序/驱动/用例/实际配置冻结后不边跑边改。发现实现或测量缺陷可中止修复并注明已消耗成本，不能混合不同版本。

统计完整任务交付、边界评分、每阶段请求数/输入输出及缓存token、失败与回退、耗时和候选数量。未知token不记零；缓存是输入子集。失败纳入分母，同时报告观测成本和成本缺失。不得把更早失败、减少防空转上限或省略人工审阅当作优化。此轮不改章节归属分析的语义预审策略。
