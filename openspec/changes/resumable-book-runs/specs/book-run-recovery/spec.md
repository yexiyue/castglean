# 章节运行恢复

## Purpose

为独立库和命令行提供可验证的有序章节运行恢复，使中断前的完整提交能够稳定复用，并保证正文、人物身份及人工修订在后续分析中保持一致，避免恢复时静默混用输入或配置。

## ADDED Requirements

### Requirement: 冻结运行输入

系统 SHALL 保存完整基础书、规范化正文、有序章节和非秘密分析配置的摘要，恢复前核对配置及协议版本。不同输入或基础修订不得复用旧运行。

#### Scenario: 配置变化
- **WHEN** 恢复方提交的模型、分析预算或协议版本与冻结配置不同
- **THEN** 调用模型前拒绝恢复，原提交保持不变

#### Scenario: 人工基础数据
- **WHEN** 新运行以已人工修正的基础书开始
- **THEN** 基础人物与已保存章节保持原有数据，指纹包含该修订及修正内容

### Requirement: 完整提交驱动恢复

系统 SHALL 仅接受连续且完整校验通过的章节提交，恢复跳过已提交章；缺失、损坏或不一致的正式提交必须停止。未完成暂存不构成提交。

#### Scenario: 提交后退出
- **WHEN** 第一章完整提交后进程退出并恢复两章计划
- **THEN** 第一章不再次调用模型，仅第二章执行，重复恢复不增加提交或调用

#### Scenario: 暂存或损坏
- **WHEN** 存在未发布暂存目录或正式提交摘要错误
- **THEN** 暂存不计入进度，正式提交损坏则拒绝恢复

### Requirement: 串行锁与取消

系统 SHALL 排除同一运行的协作进程并发写入；取消或分析失败不提交当前章，已提交章可继续恢复。

#### Scenario: 同时恢复
- **WHEN** 一个执行句柄持锁，另一进程打开同一运行
- **THEN** 后者返回忙碌错误且不调用模型；持锁进程退出后允许恢复

#### Scenario: 取消模型工作
- **WHEN** 当前章节调用期间取消
- **THEN** 不接受迟到候选，恢复从该章开始，既有提交不变

### Requirement: 通用入口与安全诊断

系统 SHALL 提供独立库和 CLI 的启动、恢复及离线检查入口，诊断不打印凭据、正文或候选；保存成功提交的实际统计，未提交调用成本不得默认为零。

#### Scenario: 无凭据检查
- **WHEN** 无模型配置时检查运行并导出已提交基础书
- **THEN** 返回进度、修订和指纹并校验导出快照，不输出正文内容到终端
