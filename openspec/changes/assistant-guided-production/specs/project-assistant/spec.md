# Spec Delta

## ADDED Requirements

### Requirement: 制作目标与可解释下一步
系统 SHALL 根据明确用户目标读取真实制作状态，展示当前步骤、必要前置和阻塞，在授权范围内顺序推进可用能力。普通讨论不得启动目标；无进展或缺少能力时停止并说明，用户可取消，切章不改变固定目标。

#### Scenario: 请求生成角色短试听
- **WHEN** 用户明确要求用某角色声音生成短试听
- **THEN** 助手检查其有效绑定和资源，已具备条件就执行，缺少声音或存在分歧时展示具体交互，不要求用户自行查找内部任务入口

#### Scenario: 请求尚未具备的整章生成
- **WHEN** 用户要求把整章制作成音频，但整章能力尚未交付
- **THEN** 助手说明阻塞和已完成前置，短试听可作为单独明确操作，不将短音频宣称为章节完成

#### Scenario: 无进展停止
- **WHEN** 连续步骤没有产生新的有效状态且再次遇到相同阻塞
- **THEN** 停止自动推进并展示阻塞及可选操作，不循环请求相同决定或反复调用模型

### Requirement: 跨步骤授权与领域人工决定
系统 MUST 区分目标授权、模型配置确认、资源准备和人工采用；明确授权范围内的必要步骤不逐项重复询问，归属分歧和候选采用继续使用显式领域操作。新增成本或范围超出原授权时先显示变化，不擅自扩展到其他章节或整书。

#### Scenario: 已授权选角后生成短试听
- **WHEN** 用户明确授权为当前角色选角并生成短试听，且已有可用资源
- **THEN** 助手可推进已授权建议及短试听步骤，具体采用绑定仍由用户明确决定，不对每个只读查询重复确认

### Requirement: 工作台渐进呈现
系统 SHALL 让正文、当前目标和下一步成为章节工作台的主要内容，助手可展开为对话或收起为状态入口；保留章节制作、工程角色和制作结果入口及共享资源稳定入口，就地交互与直接页面操作共用领域行为。

#### Scenario: 不打开对话处理工程
- **WHEN** 用户收起助手并直接校对正文或管理角色
- **THEN** 这些操作仍可用，后台状态和待决定数量可见，助手不强制展开或抢夺焦点

## MODIFIED Requirements

### Requirement: 一个助手调用领域能力
系统 SHALL 在同一会话提供检查分章、分析本章快捷入口，并允许助手根据明确用户请求调用工程状态查询、分章、章节分析、选角、已交付的章节音频生成、音色设计和短文本试声能力。需要用户决定时通过有证据的交互卡处理；普通讨论不得直接采用结构候选或覆盖人工归属，播放和查看详情不额外请求模型。

#### Scenario: 自然语言启动归属分析
- **WHEN** 用户要求分析某章人物与台词归属
- **THEN** 助手通过宿主工具绑定该章并执行完整校验流程，工具及结果可审阅；不存在的章节、跨工程引用和重复业务执行被拒绝

#### Scenario: 对话内生成及试听
- **WHEN** 用户明确要求按已选音色生成不超过能力限额的试听文本
- **THEN** 宿主工具受理实际生成任务，对话内展示真实进度和可试听结果，并可展开有效生成信息；输入超限被拒绝或先明确缩小范围

#### Scenario: 接入已经交付的章节生成
- **WHEN** 用户从对话请求生成本章且章节音频能力已交付
- **THEN** 调用与直接生成入口相同的宿主用例，卡片展示其真实阶段和可播放产物，不重复建立执行器或绕过完整性校验

### Requirement: 专业任务与独立子Agent
系统 SHALL 通过同一工程助手与共享执行设施启动分章、章节归属分析和选角建议专业任务，使用任务所需的独立上下文和工具集；快捷任务直接由宿主启动，不为路由或总结增加固定模型回合。确定性生成由宿主任务执行，无需额外子Agent。跨步骤目标可关联多个顺序运行，每个run仍只受理一种专业任务；宿主继续负责校验、恢复与发布，子Agent不拥有人工采用权限。

#### Scenario: 分章任务隔离历史
- **WHEN** 用户在已有工程会话点击检查分章
- **THEN** 分章子Agent仅收到该任务触发消息、冻结上下文和该任务已完成工具事实，不发送无关旧对话；工程会话原历史仍完整可读

#### Scenario: 普通对话委派分析
- **WHEN** 工程助手根据明确请求受理章节分析
- **THEN** 宿主在同一run与稳定助手消息中执行独立的章节归属分析和只读预审，不由工具回调提前发布，不把受理显示为分析完成

#### Scenario: 恢复与评测保留
- **WHEN** 公共执行设施发生变更
- **THEN** 正式AI评测使用同一执行代码并更新实现摘要；失败、未知用量与原领域检查点继续保留，不能把子Agent结束当作任务交付或人工确认

#### Scenario: 自然语言委派分章后重试
- **WHEN** 工程助手通过check_splitting受理分章任务后请求失败，用户显式重试
- **THEN** 使用持久化的完整用户约束直接进入独立分章子Agent，不重新委派、不带父Agent正文；主助手无低层候选工具，专业任务只能生成待人工采用候选，保留失败成本与稳定消息事实

#### Scenario: 同一运行重复委派不同专业任务
- **WHEN** 工程助手在已经受理章节归属分析后再次请求分章，或已经受理分章后再次请求章节归属分析
- **THEN** 拒绝第二个任务并保留失败工具事实，原已受理目标不改变，不返回随后被跳过任务的accepted状态

#### Scenario: 选角建议固定工程目标
- **WHEN** 用户从绑定界面或会话中明确请求 AI 选角建议
- **THEN** 宿主以固定工程目标运行隔离的选角建议任务，模型经原子提交工具产出待采用建议；现有绑定与画像不被自动修改，建议不显示为已绑定或会话结论

#### Scenario: 目标的后续步骤
- **WHEN** 一个已授权目标完成分析，需继续执行选角步骤
- **THEN** 宿主核对已保存结果及依赖后建立关联的新运行，不在原run重复受理第二个专业任务，不重跑已完成分析；遇人工决定时持久化等待并释放执行资源
