# Spec Delta

## Purpose

以同一套不可变来源、草稿工具和校验反馈对照现有 Agent 与 ECS 工具循环，明确区分实际修正收益、语义质量、失败、资源用量和运行时差异，支持可复现的提示词与工具设计评测。

## ADDED Requirements

### Requirement: 共用草稿工具与反馈
两路线 MUST 使用相同提示、工具定义和宿主状态机；工具只修改实验草稿，结构问题返回可定位错误，不得接收 gold、隐式补齐或确认人工状态。

#### Scenario: 部分覆盖修复
- **WHEN** 模型遗漏部分片段并调用校验
- **THEN** 返回缺失 ID，已有合法草稿保留，模型可以局部补齐后再次完成

#### Scenario: 非法批次
- **WHEN** 批次含非法人物或重叠范围
- **THEN** 返回可操作错误且草稿修订不变，不能部分提交


#### Scenario: 同名人物的上下文完整性
- **WHEN** 冻结人物包含用于区分同名身份的 description
- **THEN** 两路线原样保留该字段，输入上下文 hash 与 adapter 原始字段不符时拒绝交付，不靠 ID 字面含义猜测被丢弃的角色信息

### Requirement: 有界真实工具循环
系统 SHALL 使用真实 rig-agent 和 rig-ecs 工具执行路径，统一模型/工具/时间/token/修正预算；取消、失败和预算耗尽有终态，不发生隐式网络重试。

#### Scenario: 校验失败后修正
- **WHEN** 第一轮完成失败且预算仍有余量
- **THEN** 反馈进入下一轮模型历史，只有合法的再次完成能交付

#### Scenario: 取消
- **WHEN** 请求或工具执行期间取消
- **THEN** 停止新增调用，回收本地子进程，保留已完成请求与未知远端用量事实

#### Scenario: 用户显式要求不限制 token 的对照
- **WHEN** 原生实验配置显式启用 unlimitedTokens
- **THEN** 两路线不设置请求输出 token 上限、不执行累计 token 停止阈值，保留实际用量与服务商硬上限事实；默认配置仍保留旧预算，请求/工具/修正/时间限制分别记录

### Requirement: 可观测公平评测
系统 MUST 冻结相同数据、模型、提示、工具Schema、预算和程序身份；报告逐模型/工具 trace、首次提交与修正收益、交付与固定答案质量，失败保留在分母，不能把预审建议当 gold。

#### Scenario: 两路线比较
- **WHEN** 生成同一冻结选择的两路线报告
- **THEN** 核对配置与工具/提示/预算一致，独立列出运行时差异、调用量、耗时和未知费用


### Requirement: 工具协议错误的可修复性
宿主 SHALL 返回可定位的合同错误，新工具版本允许批量人物声明与稀疏片段提交，保留不可变来源、原子修改、身份分离和最终整章完整覆盖约束。

#### Scenario: 无关批次的修订变化
- **WHEN** 陈旧补丁目标未在其基准修订后被修改
- **THEN** 允许安全提交；目标发生过修改、未来修订或局部覆盖跨越已有片段边界时仍拒绝，不吞掉人类修正

#### Scenario: 中途发现重复的工具合同错误
- **WHEN** 用户授权及时修复且实际运行反复出现同类错误
- **THEN** 先复现并修复合同或反馈，再独立冻结新版本快速复验，旧版失败保留且不冒充新版本对照


### Requirement: 可审计的无执行期限及思考配置
显式 unlimitedTime SHALL 在宿主、模型传输、helper、HTTP与外层等待一致取消执行期限；计数预算与清理期限独立记录。思考配置 MUST 记录实际HTTP白名单参数及响应可观察事实，不泄露推理文本、不将缺失或零推理用量当成关闭思考证明。

#### Scenario: 无执行期限对照
- **WHEN** 运行同一修复工具版本的无限时间组
- **THEN** wallMs/requestTimeoutMs为空且所有执行层不另设截止时间，记录实际结束原因和完整耗时，不承诺远端网关不存在限制

#### Scenario: GLM 思考深度
- **WHEN** 对照 low 与 provider-default
- **THEN** low显式发送reasoning_effort，default不发送该字段，核对实际HTTP及推理字段存在性；GLM-5.3-Flash不使用不支持的disabled配置，不凭服务商usage字段0判定未思考
