# 桌面视觉体系

## Purpose

为桌面应用建立统一的主题 token、排版阶梯、状态语言、空状态与浏览器引导规范，使全站界面层级清晰、状态一致、品牌可整体替换，并与浏览器预览/桌面宿主的真实能力边界保持诚实。

## ADDED Requirements

### Requirement: 主题 token 集中且两套主题同名同数

系统 SHALL 将全部主题颜色 token 定义于 `src/index.css` 的 `:root`（浅色）与 `.dark`（暗色），包含背景/卡片/弹出层、主行动、中性文字与边线、success/warning/info 语义色、各 `*-weak` 弱底变体与 `--destructive-foreground`；两套主题 token 名称与数量一致并映射进 Tailwind 主题。组件 SHALL 使用语义 token 类，不得硬编码十六进制色值（品牌图片资产除外）。

#### Scenario: 切换主题不破坏语义
- **WHEN** 用户在设置中切换亮色与暗色主题
- **THEN** 所有页面的状态色、弱底色块与主行动色随 token 生效，无残留另一主题的固定色值

#### Scenario: 新主题落地
- **WHEN** 品牌重做后仅修改 token 色值
- **THEN** 组件无需改动即整体换肤

### Requirement: 四档排版阶梯

页面 SHALL 使用统一排版阶梯：页面标题 `text-lg font-semibold tracking-tight`、区块标题 `text-sm font-medium`、正文 `text-sm`、辅助说明 `text-xs` 配合 muted 前景色；`PageShell` SHALL 将页面描述渲染为可见副标题而非仅屏幕阅读器文本。

#### Scenario: 页面层级可扫读
- **WHEN** 用户打开任一路由页面
- **THEN** 页面标题、区块标题与辅助文字三档在字号或字重上有明确落差，不出现同档竞争

### Requirement: 统一选中与悬停语言

列表类交互面（侧栏导航、桌面标签条、章节/段落/模型/音色列表）SHALL 使用同一状态语言：选中 = 强调底色 + 加重字重，悬停 = 更浅一档底色；进行中状态使用主色徽章，警示/失败使用语义色。Tabs 控件族保留其 pill/line 两种既定变体（同一控件族内部一致，不视作第二套列表选中语言）。每个屏幕 SHALL 至多一个饱和主行动按钮。

#### Scenario: 跨页面状态一致
- **WHEN** 用户在侧栏、章节列表与模型/音色列表之间切换
- **THEN** 三处的选中态视觉语言一致，可凭同一规则识别当前项

#### Scenario: 主行动唯一
- **WHEN** 页面自身提供主行动（如创建、生成、导入）
- **THEN** 该行动是屏幕上唯一饱和主按钮，导航区不出现同级竞争按钮

### Requirement: 空状态与降级态成套呈现

无数据或功能不可用 SHALL 呈现为成套空状态：图标、一句标题、一句说明与至多一个行动入口；空状态对齐方式由组件变体提供，不在使用点堆叠覆盖类名。浏览器预览模式下的页面 SHALL 使用共享引导组件说明当前能力边界并提供示例工程入口，不与真实空目录、宿主不可用、读取失败混淆。

#### Scenario: 首次使用无工程
- **WHEN** 桌面端尚无任何工程
- **THEN** 首页呈现导入引导空状态与单一导入入口，而非空白列表

#### Scenario: 浏览器打开应用
- **WHEN** 用户在浏览器而非桌面宿主中打开应用
- **THEN** 各页显示统一的浏览器引导（示例工程入口 + 桌面端说明），不显示伪造的可用操作或空的真数据列表

### Requirement: 开发预览页不随发布存在

仓库 SHALL NOT 保留与真实页面复制样式的开发预览路由（原 `/design-system`）；组件与状态的视觉验收 SHALL 通过真实页面与文档进行。

#### Scenario: 路由不存在
- **WHEN** 访问 `/design-system`
- **THEN** 返回应用的标准未找到页面
