# Proposal

## Why

Kokoro、IndexTTS 2.5、CosyVoice3 已接入音色中心，但资源准备仍要求用户在外部运行转换脚本，阻断桌面端的一键使用。社区已有可复用产物，需要核验并适配这些资源，将必要转换收敛到 TaleChime 的原生准备流程。

## What Changes

- 为三类后端提供可确认、可取消、可重试的原生资源准备，优先复用经核验的社区文件及共享缓存，只对缺少或不兼容的组件执行必要的 Rust 转换。
- Kokoro 明确保留现有 Candle 声学推理及中文前端，不切换现成 ONNX 声学模型；评估社区 F32 safetensors、官方音色及权重折叠适配，补齐版本化中文前端资源。
- CosyVoice3 复用与既有清单一致的 LLM、Flow、两个 ONNX；对 HiFT、tokenizer、配置单独核验与准备，不降低原有精度要求。
- IndexTTS 对社区转换的张量名、形状、精度和辅助件做完整映射验证；FP16 产物不得通过转回 F32 冒充原始精度，必要组件从固定官方源原生转换。
- 引入固定来源、文件摘要、转换配方版本、输出清单与原子发布；区分下载、转换、校验与就绪，取消/失败不损坏现有可用资源。
- **BREAKING**：这三类模型的准备契约从仅本地转换指引改为原生准备计划；允许重构资源 DTO 和内部布局，不增加旧格式兼容层，已下载原始文件仍按摘要复用。

## Capabilities

### New Capabilities

- `native-model-preparation`：受支持语音模型的固定资源来源、原生适配、分阶段准备、原子发布和可核验的一键就绪。

### Modified Capabilities

无。当前主规格目录为空；进行中的 `complete-voice-center` 包含 `speech-model-availability`，本变更补充资源准备能力，不另建同名能力。实施时需协调其“本地转换指引”分支，本变更取代三类模型仅提供手工指引的交付边界，不代替该变更未完成的设计/播放器验收。

## Impact

- TaleChime：后端资源准备/下载、固定资产配方、必要的模型加载适配与有界转换、公开资源计划/进度类型、测试与准备文档；各模型算法和非目标模型不随意改写。
- CastGlean：模型目录与确认界面、后台准备任务和日志、磁盘需求展示、错误分类、进度快照及 Specta 绑定。Rust 宿主拥有任务，React 只显示应用语义。
- 两仓库实施范围沿用本会话用户授权；本提案位于 CastGlean，TaleChime 修改在其自身仓库交付并记录源码证据。
- 不附带模型权重，不要求终端用户安装 Python、PyTorch、MLX 或调用外部脚本；Python 仅可作为开发环境数值对照。首轮验收 macOS CPU/Metal，不承诺 CUDA、其他平台或应用发布。
