# Design

## Context

输入、会话计数和固定输出限制分散于 Tiptap、服务入口、Ledger、历史投影、HTTP 和 Rig。ai_messages 已有可空 usage JSON，但未发布；LLM 模型仅有身份与名称。Rig 0.46 的 Usage 以 Option 表示服务商是否报告，不能把缺失当零。Anthropic 协议需要 max_tokens，Rig 对已知模型有协议默认；未知别名可能需要显式设置。

## Goals / Non-Goals

Goals：无默认产品配额，真实上下文用量、可选模型容量/输出参数、会话内直接换模型。
Non-Goals：不自动截断或压缩历史、不伪造精确 token、不解除取消/并发/修订/来源校验，不绕过服务商实际窗口和协议要求。

## Decisions

1. Ledger 继续持久计数及防整数溢出，仅移除固定轮次/累计阈值。Rig max_turns 使用 usize::MAX 表达不设正常轮次配额；默认不调用 max_tokens，显式模型参数存在时才设置。正常对话不设字符数、累计输入或工具配额；16MiB 消息文档/64MiB 传输为序列化与内存边界，分页、工具单次范围、超时与取消不变。
2. LlmModel 可选 contextWindow/maxOutputTokens，旧配置缺省 None；窗口是显示元数据，输出参数改变请求修订并受活动租约保护。值须正整数。服务商未给窗口时可手动填写，不猜型号。不将配置窗口作为本地拒绝阈值。
3. 每次 completion outcome 把归一化 input/output/cached tokens 写入当前 assistant 的已有 usage JSON，更新消息版本并经现有流发布。新请求先清除上一请求用量；多工具轮次展示最新请求，不能相加当窗口占用。历史恢复保留信息，缺失显示未知。
4. 会话信息 Popover 展示上次请求输入/输出/缓存、输入+输出的上下文占用；只有两项及对应模型窗口皆已知才显示百分比和进度。切换目标时上次用量仍标记原模型，不能拿新模型窗口套算。请求次数独立标为累计统计，不带 /64。
5. 模型选择允许在活动请求时改变下次选择；活动请求不可被偷偷重绑。用户显式选择等价于后续请求的 confirmRebind，后台变化仍须明确确认，避免默认/快照更新覆盖用户选择。不要求重复勾选；保留工具就绪提示和配置入口。

## Risks / Trade-offs

未知服务商 token/模型容量只能显示未知；协议必须输出参数时遵循 SDK/用户设置，不承诺无限服务商资源。历史结构范围扩大需通过长输入/长历史与旧统计回归。恢复和幂等不能因限制移除被改写。
