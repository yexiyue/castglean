# 设计

## 背景

参见 proposal。当前协议和产物共用正式引用；源片段 ID 和角色 ID 较长，响应对目标、证据、引文及已有身份重复它们。

## 目标与边界

只压缩引用。保留 DTO 字段、表达类型、证据政策及生成接口。截断仍直接失败，无自动重试、窗口调整或预算扩大。保留上一轮未提交的实现与报告。

## 决策

新增私有 references 模块，保存窗口可见片段及只读已有角色的有序正式 ID 列表。输入使用 sN/cN；只接受规范的十进制短引用，按列表还原目标、证据、引文和 existing 引用。new 身份保留响应内 temp_id，其命名空间与 existing 独立。

在解析后、纯校验前解码，未知短引用返回安全问题，不修改注册表。正式反馈仍保留领域引用，对模型反馈时经同一表转成短引用。首次和修复共用一个表；候选保持模型原始短引用，窗口成功后丢弃表。短引用不是全局身份，不能检测一个合法但语义错误的选择。

不缩短最终 ID，不简写 JSON 字段，也不合并片段：这些方案涉及产物兼容或语义边界，先单独衡量短引用的收益。提示词版本为默认 7、引文 8；Schema 和业务接受条件不变。

## 风险与迁移

自定义模型须回传请求 ID，而非构造正式 ID。合法引用仍不保证语义。局部短名在不同窗口重复是设计行为，只在当前窗口解释。最终保存仍是原来的正式引用；既有文档与人工确认无需迁移。

## 验证

离线测试完整还原、多窗口、已有身份/new 同名短引用、证据及引文、反馈一致性、非法/旧正式引用、失败不污染。保存 v7/v8 固定二进制运行开发 20 例及小说六例，两后端、两模式、各一次，原计划共 104 次；按用户追加要求，GLM 使用同一语料与预算执行旧、新协议两模式各 26 次，追加 104 次，本轮合计 208 次；使用已有 v5/v6 开发与小说报告比较，重复次数和运行环境差异须披露，未取得用量保持 null。

GLM 根据用户追加要求纳入对照，使用现有国内 Coding Plan GLM-5.3-Flash 配置（low/json）。旧程序通过二进制摘要匹配历史报告，并复制该报告的版本和源码摘要；公开记录 protocol_reference 的文件摘要与来源方式，不能声称旧程序来自当前源码。新程序仍记录当前源码；全部执行检查固定二进制、工作树协议及冻结答案未变。
