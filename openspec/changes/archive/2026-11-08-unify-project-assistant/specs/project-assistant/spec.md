# Spec Delta

## Purpose

为小说工程提供一个持续的 AI 会话与章节制作环境，使目录结构检查、人物归属分析及人工审阅在同一原文上下文中完成，并保证切章、后台运行和重开不会改变已接受任务的目标或丢失历史。

## ADDED Requirements

### Requirement: 单一章节工作台
系统 SHALL 只提供一套章节目录、正文阅读器和 AI 助手，移除分章与归属页面切换。结构操作、归属审阅与角色管理在同一工程内可达，保持虚拟滚动、精确行号、来源切换与显式章末导航。

#### Scenario: 连续处理不同任务
- **WHEN** 用户从检查分章转为分析当前章
- **THEN** 目录、原文位置和助手会话保持，不需要切换页面或另一个助手

### Requirement: 工程级会话与固定运行上下文
系统 MUST 按工程组织新会话，切章不自动更换会话或草稿。每次发送冻结目标上下文、来源修订与任务意图，后台运行不随视图改变目标。重试复用原任务目标且不隐式重放。

#### Scenario: 分析中切章
- **WHEN** 在甲章启动分析后用户切换乙章
- **THEN** 同一助手继续展示甲章任务，结果属于甲章，可点击定位；乙章不接收甲章结果

### Requirement: 一个助手调用领域能力
系统 SHALL 在同一会话提供检查分章、分析本章快捷入口，并允许助手根据明确用户请求调用分章工具或当前工程的章节分析能力；普通讨论不得直接采用结构候选或覆盖人工归属。

#### Scenario: 自然语言启动归属分析
- **WHEN** 用户要求分析某章人物与台词归属
- **THEN** 助手通过宿主工具绑定该章并执行完整校验流程，工具及结果可审阅；不存在的章节、跨工程引用和重复业务执行被拒绝

### Requirement: 结果与人工审阅
系统 MUST 保留结构候选显式采用、归属初稿与重分析候选、保护冲突和撤回语义。点击正文打开归属检查器，返回助手保留会话与草稿。待检查入口可区分结构问题和归属待审阅，不混淆零问题与已确认。

#### Scenario: 查看结果后继续讨论
- **WHEN** 用户从助手结果打开候选或归属检查器后返回
- **THEN** 会话、消息位置和未发送输入保留，人工结果未经明确操作不会改变

### Requirement: 历史与真实状态
系统 MUST 保留并可读取旧分章及章节会话，不把旧消息拼接伪装成同一新会话。迁移保留工程数据，读取失败、无模型、失效和执行失败明确表达。中英文、亮暗及小窗口保持操作可达。

#### Scenario: 打开历史会话
- **WHEN** 用户选择旧任务会话
- **THEN** 只读展示原记录和结果，继续工作使用统一会话，不因读取启动模型
