# Spec Delta

## Purpose

为章节分析建立可持久继续的审阅和人工修正流程，在正文、角色与待检查问题之间保持稳定导航，保护用户确认的身份和归属，并让重新分析的差异、影响及采用结果明确可查而不增加首次使用的重复操作。

## ADDED Requirements

### Requirement: 首次分析直接形成待确认初稿
系统 SHALL 在首次完整校验成功后自动保存当前章初稿并直接显示可编辑标注，无需先进行一次整章采用。初稿保存、任务完成和人工确认保持独立；片段与候选角色默认未确认，流式文本或窗口产物不能当作有效初稿。

#### Scenario: 首次分析成功
- **WHEN** 该章没有有效分析且完整结果通过校验
- **THEN** 打开正文即可检查与修正已保存初稿，未审阅状态可见，重开工程仍恢复同一初稿

#### Scenario: 两个会话竞争首次发布
- **WHEN** 同一章两个会话基于尚无初稿同时产生完整结果
- **THEN** 仅一个结果成为当前初稿，后到结果作为需审阅候选保留，不覆盖先发布结果或期间人工修改

### Requirement: 原文驱动的归属检查
系统 SHALL 允许从正文片段、待检查列表或角色出现记录定位同一段原文，显示类型、归属状态、候选角色、证据和理由。用户可以确认已有归属、改选角色、保留未知/歧义、修改片段类型或调整片段边界，所有操作保持整章完整分区与不可变原文。

#### Scenario: 修正错误归属
- **WHEN** 用户在正文选中一段台词并指定另一个角色
- **THEN** 修改保存到宿主并回读后显示成功，该范围被人工保护，其他片段及其他章节不被自动修改

#### Scenario: 纠正一个片段中的多人物台词
- **WHEN** 用户按原文边界拆分或合并片段并指定类型/归属
- **THEN** 影响范围预览明确，提交原子校验连续覆盖及 UTF-8 边界，失败保留编辑草稿而不破坏旧结果

#### Scenario: 明确保留未知
- **WHEN** 用户检查证据后决定保留未知归属并确认
- **THEN** 归属仍为未知，审阅状态变为人工确认，界面不强迫选择角色或将未知当成未分析

### Requirement: 稳定角色身份的人工管理
系统 SHALL 允许创建/确认候选角色、为当前候选复用全书已确认角色，并编辑显示名称或有来源依据的别名。确认和复用均显式执行；名称变化不改变角色身份，影响其他章节显示的共享元数据修改须先明确作用范围。

#### Scenario: 确认或复用新人物
- **WHEN** 用户处理新人物候选
- **THEN** 可确认其稳定身份，或显式将当前章相关候选引用改为已有身份；同名提醒不自动触发全书身份合并

#### Scenario: 修改共享角色名称
- **WHEN** 用户修改一个已被多章引用角色的显示名称
- **THEN** 界面展示共享影响范围，确认后更新名称但不改变既有角色 ID、原文证据或各章片段归属

### Requirement: 人工修正与确认保护
系统 MUST 持久化人工修改的范围、字段、确认状态和修订；模型建议、任务恢复或重新分析不得静默覆盖。结构变化涉及受保护范围时必须形成明确冲突，不得因换片段 ID 或划分边界而绕开保护。

#### Scenario: 重分析给出相反归属
- **WHEN** 新建议改变人工确认过的说话人或片段类型
- **THEN** 当前人工结果保持，差异中标明冲突，只有用户逐项明确允许替换才可改变受保护字段

#### Scenario: 新候选跨过人工边界
- **WHEN** 新片段的范围跨越人工拆分、合并或确认的范围
- **THEN** 将整个受影响区间作为边界冲突，不按候选新 ID 自动替换人工结果

### Requirement: 重分析差异审阅与一次提交
系统 SHALL 将已有分析的重分析结果保存为独立候选，提供新增、变化、冲突及不变信息和原文定位。用户可选择变化组后一次应用或放弃；未选变化沿用旧结果，受保护冲突默认不选，应用前再次验证依赖和完整覆盖。

#### Scenario: 应用选中的变化
- **WHEN** 用户选择一组无冲突变化并确认应用
- **THEN** 一次持久化提交更新当前章版本，未选范围和人工保护保持，候选处理结果及回执可查询，重复命令不重复修改

#### Scenario: 审阅期间人工编辑
- **WHEN** 候选展示后当前章人工状态已改变
- **THEN** 旧基础上的采用被拒绝，提示刷新当前状态，不自动用旧候选覆盖新修正

#### Scenario: 放弃新候选
- **WHEN** 用户放弃重分析候选
- **THEN** 当前有效版本和人工修正保持，候选历史和成本记录仍可查看

#### Scenario: 新章节范围的重新分析
- **WHEN** 章节身份保留但来源范围改变，用户重新分析
- **THEN** 合法新结果保存为整章候选且默认不选；用户明确确认整章替换后才发布新范围标注，旧版本及人工记录保留在历史中，不静默迁移

### Requirement: 可撤回的最近修改
系统 SHALL 支持撤回当前章最近一次成功的人工修改或候选应用，恢复相应业务内容并推进新修订；撤回不删除任务历史或改写过去成功事实，也不回退已被其他章节使用的共享角色身份。

#### Scenario: 撤回候选应用
- **WHEN** 用户刚应用候选后执行撤回
- **THEN** 当前章恢复应用前的完整标注和人工状态，修订继续递增，历史候选保留并体现当前未采用状态

#### Scenario: 撤回基础已变化
- **WHEN** 最近修改之后已有其他有效修改，用户重放旧撤回命令
- **THEN** 宿主依据命令身份返回原回执或拒绝版本冲突，不跨过新修改覆盖当前状态

#### Scenario: 旧范围已经失效
- **WHEN** 用户采用新章节范围的整章候选，之前版本绑定的范围已失效
- **THEN** 明确说明旧版本仅保留为历史，不提供将失效范围重新设为当前标注的撤回操作

### Requirement: 清晰的状态与依赖失效
系统 SHALL 分开显示未分析、运行阶段、有效初稿、未审阅问题、人工确认和失效原因，角色确认与片段确认分别统计。失效版本可查看但不能继续当作当前有效标注修改；分章边界改变后仍保留历史，不自动迁移旧标注到新范围。

#### Scenario: 结构有效但无人审阅
- **WHEN** 初稿通过范围和引用校验但仍存在未知归属和未审阅片段
- **THEN** 不显示“全部正确”或“人工已确认”，待检查真实数量与当前范围明确

#### Scenario: 原文结构变化后重开
- **WHEN** 用户调整章节边界后重开分析工作台
- **THEN** 能看到旧版本及失效原因，并有重新分析入口，不将旧范围归属静默套用到新章

### Requirement: 稳定且紧凑的分析工作台
系统 SHALL 在真实工程复用单行章节页头与 Info、可收放面板、内收圆角虚拟目录、对称滚动留白、章内连续阅读和章末显式切章。目录/待检查图标标签共用常驻范围搜索，各自保留查询/滚动；空状态在列表可用区域居中且短窗口动作可达。

#### Scenario: 长目录与检查定位
- **WHEN** 用户在一万章目录中搜索、切换待检查或定位一个问题
- **THEN** 无需逐页翻目录，问题可联动当前章正文和检查器；顶部几何稳定，重开视图不启动模型

#### Scenario: 中英文与小窗口
- **WHEN** 用户切换语言/主题或收窄窗口并打开辅助编辑
- **THEN** 主要操作仍可访问，无横向溢出，图标有可访问名称及向下提示，辅助浮层不挤压正文，关闭恢复焦点

### Requirement: 检查器与助手职责分明
系统 SHALL 默认在右侧显示所选片段检查器，AI 助手作为可切换视图并保留会话/输入状态。显式“分析本章”启动分析；助手建议与业务修正使用相同校验和人工保护，聊天文本本身不具有确认、采用或修改正文的权限。

#### Scenario: 无需聊天即可完成检查
- **WHEN** 用户点击分析本章并逐项修正归属
- **THEN** 可通过正文与检查器完成闭环，不必先发送提示词或重复在聊天中确认保存

#### Scenario: 切换右侧视图
- **WHEN** 用户在检查器和助手之间切换
- **THEN** 选中片段、正文位置、输入草稿和当前执行保持，切换不取消任务、不重新请求模型

### Requirement: 保存、升级与失败保持
系统 MUST 将分析版本、角色、人工修正及命令回执保存到本地宿主存储；当前数据库升级失败保留已有工程和来源，未知版本明确拒绝写入。编辑失败保留草稿和旧已提交结果，成功状态以持久提交为依据，不读取或导入 legacy 分析格式。

#### Scenario: 重启继续人工审阅
- **WHEN** 用户保存修正后关闭并重新打开应用
- **THEN** 恢复相同当前版本、角色身份与确认状态，不因页面刷新丢失人工决定

#### Scenario: 数据库升级或编辑失败
- **WHEN** 新分析存储升级或一次修改事务失败
- **THEN** 原工程、分章、AI 历史和原文保持，显示可操作失败，不清空数据库、不伪造保存成功

### Requirement: 共享 AI Elements 对话交互
系统 SHALL 使用 shadcn/ui Base UI 的 Prompt Input/Input Group 组合与 Trace 活动组件承载共享助手，采用原生受控文本域，保留模型切换、真实用量、来源引用和明确发送/停止。任务阶段、真实工具调用和业务结果引用分别表达，不伪造执行事实或提供未支持的上传操作。

#### Scenario: 输入与工具状态保持
- **WHEN** 用户输入中文、添加原文引用并在检查器与助手间切换，或工具执行结束
- **THEN** 草稿及引用保持，输入法组合不误发送；工具状态由宿主事实更新，可按需展开，分析结果仍通过受控业务引用审阅
