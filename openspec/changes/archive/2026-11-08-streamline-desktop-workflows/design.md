# Design

## Context

上一轮统一了圆角与基础搜索，但页头仍为网站式标题说明，集合的分类和筛选另占多层。用户进一步授权全应用大改。调研 Apple Toolbars、Atlassian Page Header、Carbon UI Shell/2x Grid，采用分工与对齐原则，不照搬特定品牌视觉或 Liquid Glass。

## Goals / Non-Goals

Goals：上下文优先、减少动作与重复说明，紧凑但不压缩可操作范围；保留主题和 10/8/12/16px 圆角。
Non-Goals：不实现未交付的分析/制作、不改变数据和后端、不自动下载/生成/提交编码。

## Decisions

1. PageShell 保留语义 h1/描述，将可视页头改为约 48px 上下文栏；模型/音色用分类取代重复标题，可操作入口在右。描述保留为辅助技术上下文，关键限制仍放字段旁。导航底色与工作表面使用现有 sidebar/card token，内容边距 20px、组间 16px、表单间 12–16px。侧栏宽 208px，贴边且不新增外壳。
2. 集合筛选集中到列表上方，不渲染无任务的空反馈容器。音色批量导出在有选中时显示；全选仍可发现。模型用语义 button 覆盖整行，键盘激活和返回焦点可用；已有准备/验证确认不变。
3. 导入表单备注按需展开，提交后创建宿主草案并立即打开 TXT 选择器，减少一次操作。取消选择保留真实草案；选择失败展示错误且可以重试，不重复创建工程；离页仍释放选择句柄。编码显式确认不变。
4. 音色制作核心名称/引擎并排，输入与候选以分隔和辅助底色区分；增加直接返回音色中心。已就绪不重复资源目录，未就绪仍原地准备；任务、错误、候选始终按事实显示。
5. 上手、首页、设置和工程的间距与标题层级同步收敛。说明文本不承担装饰，通用不可用说明从主操作区降低层级；真实错误与确认不能折叠隐藏。

## Risks / Trade-offs

- 紧凑可能降低可发现性 → 核心入口具名，主要动作保留，真实页面中英亮暗小窗口验证。
- 连续创建/选文件可能中断 → 宿主草案事实保留，取消/失败重新选择不重复创建，测试不把选文件当作导入成功。
- 整行点击可能引入嵌套交互 → 模型行只有一个 button，不把按钮套按钮；资源动作留详情。
- 浏览器不等于原生验收 → 合成 IPC 与真实预览分别验证，系统选择器/WebView 另行验收。
