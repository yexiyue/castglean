# 设计：证据优先归属

## Context

动机见提案。现有 core 编排和有限修复已隔离模型通信，CLI 仅完整发布结果。本地适配器已有有界 HTTP 接收，MiniMax 国内文档提供 Chat Completions；未据此假定其支持严格 Schema。

## Goals / Non-Goals

目标：明确通用归属规则、隔离国内服务配置、提供可复核的同模型前后对照。边界：不改正文、身份或标注协议，不增加 Agent、跨章状态、后端自动回退或语义硬编码。

## Decisions

1. core 提示词版本递增。直接说话引导和明确心理主语可支持 resolved；只知道有多个候选时 ambiguous；无法限定发声来源时 unknown。不得按轮次或姓名距离确认。保留同称呼多身份，禁止编造别名。
2. MiniMax 专用配置和适配器仍在 model crate。共享小型私有 HTTP 接收及响应转换，保留本地 Schema 请求；MiniMax 使用文本 JSON 加应用校验，思考与正文分开，超时与修复仍由 core 管理。替代方案是直接套用本地参数，但厂商没有确认支持这些约束。
3. CLI 新增 minimax 后端，独立 MINIMAX_* 变量，不读取 GLM 凭据。默认模型 M2.5，端点以官方国内地址为准；真实连接验证如发现兼容性差异，在文档记录。密钥不实现 Debug、Serialize，拒绝重定向，诊断不含响应正文。
4. 保存旧版二进制再改提示词，用相同参数和公开输入顺序运行两个版本，记录所有尝试。增加独立场景核查，避免仅在原三个样例上宣布质量提升。对照限定为小样本观察，不做显著性或普遍收益推断。

## Risks / Trade-offs

- 原歧义样例语境不足，其人工答案未必唯一 → 保留历史评分，并明确争议，补充证据明确的独立场景。
- MiniMax 思考消耗输出预算、可能截断 → 独立配置输出上限，截断直接失败，不重复网络请求。
- 提示词增加导致本地上下文压力 → 保持简短规则，沿用有界窗口与输入预算。

## Migration Plan

保持既有配置兼容；本地仍为当前配置默认。提示词版本随统计更新，旧报告保留历史版本。回滚提示词即可恢复旧规则，不修改已有标注。
