## Context

Archify 3.3.1 从 `7df146f2e4cc6b2269e8cef696288cd67fb42cb5` 所在工作区捕获了前端和宿主，结果包含当时的未提交改动。前端范围是根目录 `src/` 的 JS/TS 源文件，Rust 分析以 `src-tauri/` 为 Cargo 根。原始报告位于此次 Codex 可视化目录中的 `architecture-castglean-desktop-20261125-122726/{frontend-diagnosis,rust-diagnosis}/analysis/findings.json`。

| 范围 | 原始发现 |
| --- | --- |
| 前端，235 个文件 | 1 条静态导入环、1 条模块依赖环、5 条集中度、3 条边界泄漏、96 条函数复杂度，共 106 条 |
| Rust 宿主，187 个文件 | 6 条结构依赖环、35 条函数复杂度，共 41 条 |

验收承接 `project-assistant`、`background-ai-execution`、`chapter-production-workspace`、`chapter-attribution-analysis` 和 `character-voice-binding`。工程助手检查点续跑按专门契约验证，专业任务按各自的领域恢复规则验证。

## Goals / Non-Goals

- 让跨功能依赖经过拥有者的公共契约，缩小会话、章节工作台和专业任务中需要一起修改的代码范围。
- 对全部原始发现逐项追踪，并用同口径复测与产品场景验证重构。产品需求与工程数据格式沿用现行规格。

## Decisions

### 按功能所有权划分前端依赖

把 `DelegatedToolContext`、相关类型及 Provider 从委派卡移到独立模块。结果卡、委派卡和子代理消息读取同一契约，子代理消息通过调用方提供的渲染入口组合结果卡。用实际 import 边复核整个强连通分量，覆盖 `agent-result.tsx`、`delegated-tool-card.tsx`、`subagent-messages.tsx`。

章节工作台保留路由装配和共享章节选择。目录与阅读、归属与角色、音频任务与播放、助手会话各自持有其状态与操作。共享的播放会话须继续跨章有效。叶子工具和 IPC 适配由功能消费，跨功能调用只走窄入口，同一功能内部可直接引用。按报告中的 `components`、`hooks`、`lib` 边追溯真实所有权，收拢双向引用与深层导入。仅建立全局 barrel 会把深层耦合变成隐式耦合，因此公共入口按功能定义。

### 同一事务内拆开受理阶段与领域准备

保留一个事务所有者，把 `ai::service::start_inner` 分为请求身份及重放、会话与冻结上下文、继续或重试判定、专业输入准备、运行与消息提交等阶段。用具体的任务输入及结果表达分支，领域模块拥有其版本、审批和资源校验责任。事务提交后再通知，可靠派发由运行时负责。单纯拆函数或给各步骤单独开事务无法体现状态所有权，后者还会引入部分写入风险。

通用中断负责实例归属、消费条件与记录写入。选角审核在同一事务内由上层协调调用领域校验，再经通用接口提交响应，解除 `ai/interrupts.rs` 与选角试听的职责互引。对 `ai`、`engine/catalog`、`jobs/runtime`、`logging/commands`、`voices/studio/media` 的结构环，逐边分辨 `mod`、门面重导出、真正的类型和执行依赖。确认反向职责的边缘模块改为依赖明确的底层所有者。Rust 模块声明产生的剩余环须附证据和可复现范围。

### 拆解复杂度热点并逐条关账

前端先处理 `ImportedWorkspace`（390）、`ChapterAudioTrack`（157）、`ChapterAudioControls`（149）、`useChapterAudio`（118）、`CharacterTargetDetail`（115）、`VirtualSourceReader`（112）。沿状态所有权和工作流程拆分，保留媒体生命期、路由目标及失败状态。

宿主除任务受理（79）外，优先处理 `ProjectDocument::validate_draft`、章节归属校验、分章识别、`assemble_spans` 和人工归属编辑。将领域判定按输入校验、计划构建和原子写入分开，保留现有校验及错误语义。其余复杂度项使用同一判据审查，接受记录须说明为何现有分支属于同一职责，并给出代表性回归证据。

保留原始 147 条的 ID、规则、位置、消息和分析范围，以源码职责和实际依赖边关联新报告中的改名项。每条记录须有修复及验证证据，或有具体的工具误归类及合理依赖证据。确认 `src/lib/bindings.ts` 的 tauri-specta 生成链后，可以在经校正的前端范围把它标记为生成文件，并保留原口径复测以对照这项差异。聚合模块指标须追到实际导入，不能用移动文件、改阈值、抑制规则或隐藏源码充当修复。引入边界检查或配置时，验证违规样例确实会失败。

## Risks / Trade-offs

- 布局和状态拆分可能破坏切章时的播放、选择和晚到任务归属。用跨章播放、助手恢复、候选采用以及小窗口中英亮暗场景验证。
- 拆解受理和审批可能改变写入顺序。覆盖丢失响应、重复派发、过期修订、取消、重启、一次性审批和工具回执重放。
- Archify 静态判定与实际执行存在范围差异。报告对比注明版本、源码范围、配置与解析覆盖，数据和运行语义由项目测试及真实桌面验证。

## Migration Plan

先解决明确依赖环并建立可复测的边界，其后按章节工作台与宿主领域分批切换。涉及内部 IPC 合同的批次同时修改宿主、生成绑定与全部前端消费者，验证后再进入下一批。每批以当前 OpenSpec 和未提交工作为合入基线，按批次回退源码即可撤销内部结构变化。用户工程及已生成文件沿用原持久化格式。
