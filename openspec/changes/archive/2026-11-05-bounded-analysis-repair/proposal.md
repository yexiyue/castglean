# Proposal

## Why

当前单章分析遇到格式或引用错误会直接失败；GLM 的结构化输出约束不能替代应用校验。利用确定性反馈允许模型有限修复，验证恢复收益，同时维持通用库的简单边界。

## What Changes

- 单窗口增加可关闭的有限修复，默认一次；请求共享章节次数和时间预算。
- 建议纯校验返回内部已校验窗口，随后应用，失败候选不进入角色上下文。
- 类型化安全问题信息、修复请求及统计；CLI 增加修复次数和章节时限参数。
- 公开样例和私有首章对照评测，不以结构正确代替语义准确。
- **BREAKING**：未冻结的 AnalysisOptions 增加字段，修复耗尽新增错误；默认行为从失败即停改为允许一次修复。

## Capabilities

### New Capabilities

- `analysis-repair`: 窗口建议校验反馈、有限修复、原子接受、预算与运行统计。

### Modified Capabilities

无；当前主规格目录尚无已归档能力。

## Impact

影响 core 的 analysis 内部模块、公开选项及错误类型、CLI 参数和分析说明。阶段 B 尚未归档的单次模式规格明确以关闭修复为条件，保留旧基线含义。保持 AnalysisModel 单次生成接口、GLM 适配器、正文及标注格式；不增加 crate、Agent 框架或外部集成。
