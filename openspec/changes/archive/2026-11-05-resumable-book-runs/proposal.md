# 提案

## Why

整书快照和人工保护已经可用，但多章任务中断后仍需手工确认已完成章节。先补齐章节级恢复，使已校验提交可复核、可跳过，避免恢复时覆盖修正或混用配置。

## What Changes

- 增加具体 JSON 运行存储：冻结基础书、规范化章节正文、分析配置及协议版本，逐章保存完整提交。
- 恢复时校验摘要、连续提交链、修订及整书不变量；已提交章节不再调用模型，未提交章节重新执行。
- 用操作系统文件锁协调同一运行；库显式接收路径、配置及取消信号，不读取环境文件。
- CLI 增加 run / resume / run-inspect，沿用现有模型装配；计划和完整产物保存在忽略目录。
- 以故障位置测试、离线示例和有限 GLM 验证交付。仅完成 D 的章节级恢复补充，窗口 checkpoint、跨运行缓存、任意旧章重跑和首次发布验收继续后置。

## Capabilities

### New Capabilities

- `book-run-recovery`: 有序章节运行的冻结计划、提交链、取消、恢复和并发保护。

### Modified Capabilities

无；当前主规格目录尚未同步已有变更。

## Impact

core 增加具体运行类型及文件存储，保留三个 crate 与现有模型协议。CLI 复用配置装配。正文、标注及人工修正格式保持不变，运行格式仍为草案。不接入 TRNovel，不增加 Agent 或通用存储接口。
