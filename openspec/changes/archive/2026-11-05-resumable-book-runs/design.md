# 设计

## Context

现有 BookState 已提供纯候选生成与整书校验，CLI publication 仅发布一次性目录。动机见 proposal.md。运行存储放 core 私有 run 模块并有意导出，不复制领域校验，不引入第四个 crate。

## Goals / Non-Goals

目标是单书有序追加章节的恢复闭环。每章独立沿用现有请求、修复与时限预算。已提交章构成唯一权威进度，不额外维护可能落后的活动指针。仅冻结计划内缓存；不做跨运行缓存、窗口恢复、末章重分析计划、任意旧章重跑或发布版本冻结。

## Decisions

1. RunPlan 包含基础 BookDocument、按顺序保存正文及元数据的章节、显式 RunConfig。配置包含非秘密模型标识、端点、推理和输出模式、完整 AnalysisOptions、提示词和切片版本及调用方提供的实现版本标识。SHA-256 覆盖完整计划，所以角色上下文和人工修订自然进入指纹。凭据不序列化，轮换密钥不会失效。恢复须匹配显式配置；修改正文、基础书或配置须创建新运行。
2. 初始 manifest.json 随暂存目录一次改名发布，包含计划及指纹。每章 commits/00000001/commit.json 保存完整书、统计、计划指纹、父提交摘要和序号；单文件内含全部权威状态，目录改名为提交点。文件 sync_all，Unix 同步目录；Windows 不宣称断电事务保证。完整提交后的进程退出不影响恢复；暂存目录不参与进度且不自动删除崩溃遗留物。
3. 读取按编号检查连续链、摘要、计划身份、预期修订、追加动作、旧人物不变及旧章仅重盖共同修订，随后调用 BookState 全量校验。损坏或缺号停止，不把坏提交当未执行章。没有独立进度文件，消除提交与进度更新之间的双写窗口。
4. 运行句柄持有标准库 File::try_lock 排他锁，整个分析及提交期间有效；进程退出自动释放。仅协调遵守协议的进程，本地可信目录；不同运行无全局锁。不会覆盖现有目标。
5. CLI run 读取显式 JSON 计划，使用现有模型配置并核对其非秘密描述；resume 仅读取保存计划，不重新读外部源文件；run-inspect 无模型凭据，显示安全元数据并可导出新的 book.json 快照目录。提供原创两章计划示例与离线库示例。Ctrl+C 不接受迟到候选。

## Risks / Trade-offs

- 完整书快照按章重复存储，成本随书长增加 → 先保证可复核，压缩或增量后置。
- 中断中的网络请求可能已计费 → 恢复可能重复该章请求；仅成功提交统计已知，不将失败成本写零。
- 摘要检测意外损坏，不是防恶意篡改签名 → 明确本地可信目录边界。
- 标准库文件锁要求 Rust 1.89+；实际依赖最低版本尚待首次发布验证 → 当前 Rust 1.98.1 验证，不宣称 MSRV 验收完成。

## Migration Plan

增量新增 API 和 CLI 命令，旧 analyze/correct/inspect 不变。修正后的快照作为新计划基础，保留人工数据；已有运行不会自动吸收外部修改。删除运行由调用方管理，不提供自动清理或覆盖迁移。
