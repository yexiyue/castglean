# Design

## Context

全应用 PageShell 已紧凑化，但分章独立主区仍重复工程名和状态，并用文字按钮收起侧栏。当前窄屏由 CSS 隐藏面板，React 状态/aria 与实际显示可能不同。

## Goals / Non-Goals

Goals：参照用户提供的 zcode 面板开关位置，明确顶栏/面板头分工，减少重复文字与空行。
Non-Goals：不照搬 zcode 产品功能、不复制附件正文、不改变工程或 AI 协议，不强制改造其他工作区。

## Decisions

1. DesktopShell 提供左右两个 DOM 顶栏插槽，分章用 React portal 渲染自己的控件；控件仍归工作区生命周期管理，无全局命令注册或异步清理竞态。左开关在工程标签前，右开关在工具区最右（原生窗口按钮前）。离页即移除。独立测试/嵌入没有插槽时显示约 40px 紧凑栏。
2. 目录/助手用 PanelLeft/PanelRight 系图标，aria 名称稳定、expanded/controls 反映实际显示，tooltip 告知动作和 Mod+B / Mod+Alt+B。输入区不截获快捷键。撤销/更多用图标，继续制作保留短文本；保存状态为具名小图标，错误仍显式显示。
3. 使用 matchMedia 的响应式状态推导实际可见性，窄于 851px 时最多显示一个辅助面板，后打开者优先；收起与恢复始终有入口，宽度/折叠偏好保留在工程临时 workspace 状态。助手一直挂载，目录/阅读与草稿不重置。
4. 三栏统一紧凑头与既有主题；来源选择/行号集中到原文面板头，无候选时不显示单独原文标签行；候选存在时保留原文/审阅切换。目录数值对齐，长标题两行截取且提供完整标题。

## Risks / Trade-offs

Portal 需要同时验证真实 DesktopShell 路由和独立夹具；只检查孤立工作台不足以证明顶栏整合。窄屏/缩放/焦点要按实际面板验证，不能只断言状态；关闭面板不卸载 AI。真实系统 WebView 仍与合成 IPC 浏览器区分。
