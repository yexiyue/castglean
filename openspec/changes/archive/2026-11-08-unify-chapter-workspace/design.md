# Design

## Context

动机见 proposal.md。真实工程路由直接挂载 ImportedWorkspace，示例和 ProjectLibrary 自带 AppSidebar；/new 已有来源时挂载 ChapterSplittingWorkbench。两个工作台均使用 ChapterDirectory、VirtualSourceReader、WorkspaceChromeContext，但拥有不同会话和编辑协议。已有宿主负责结构变更后的分析失效。

## Goals / Non-Goals

**Goals:** 统一导航、模式入口和阅读上下文，复用现有领域工作台，保护会话与人工草稿。

**Non-Goals:** 不合并宿主任务类型、不新增数据迁移、不重写分析与分章领域，不改独立示例音频能力。

## Decisions

1. 新增真实工程 ProjectWorkspace 外壳：原有三图标导航与模式栏；工程角色复用真实 CharacterManager，结果显示尚未交付。示例保留独立布局，不复用其虚假数据。
2. 外壳拥有最新工程快照、当前模式及阅读锚点。两个领域工作台按首次访问挂载后保留，用隐藏容器保持受控草稿与会话；仅活动工作台渲染 portal、注册快捷键和响应选区。隐藏模式不渲染浮层。拒绝切路由卸载方案，因为它会丢未提交输入与选择。
3. 共享原文组件提供带精确字节坐标的原文行；外壳在切换时捕获来源/章/行与视口偏移，目标模式按该锚点定位，原文仍由宿主读取。各模式内部阅读器复用相同组件，不为合并 UI 重写不同的结构编辑/标注渲染。
4. 工程路由接收 mode=split/analysis；初次正常打开默认分析，导入默认分章。/new?draft 复用同一外壳，追加文件明确回到导入表单。路由和工程标签记忆当前模式。
5. 分章回读通过外壳更新分析工作台快照；重新激活分析时重查业务状态。结构编辑浮层/候选采用展示影响说明，不在前端猜测或修改失效标记。

## Risks / Trade-offs

- 两个隐藏领域工作台可能重复响应事件 → 活动标志控制 portal、快捷键、选区及浮层，浏览器验证一次按键只影响当前模式。
- 结构改变使锚点章 ID 消失 → 以相同来源字节范围定位仍存在的章，行号钳制至新章；失效交给宿主。
- 保持挂载增加有限内存 → 只在访问后挂载，继续使用有界虚拟源窗口，不复制全文；会话切换不重发。
- 外层导航占宽 → 固定 64px 三图标侧栏，小窗保持相同入口，目录与检查器互斥收放；验证 1024px 和更窄窗口。

## Migration Plan

无存储迁移；仅前端临时状态与入口变化。回退前端即可，宿主工程和历史不改写；既有 /new 导入入口继续可用。
