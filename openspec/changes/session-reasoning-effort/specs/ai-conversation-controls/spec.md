# Spec Delta

## ADDED Requirements

### Requirement: 按请求推理档位

系统 SHALL 允许工程会话为后续请求选择推理档位，覆盖服务连接中该模型的默认档；未选择时使用模型默认档，行为与现状一致。可选档位 MUST 来自所选模型的推理目录（协议 × 模型），不支持的档位不可提交；档位变化与模型变化共用配置确认机制（未经用户选择的变化须确认后生效）。每次运行 SHALL 冻结创建时的档位，重试与恢复不读取后续修改。

#### Scenario: 选择档位覆盖默认

- **WHEN** 用户在会话工具栏为当前模型选择某一档位并发送
- **THEN** 该请求以所选档位构建，连接配置中的默认档不改变；下一次发送仍使用所选档位直至用户改回「跟随模型默认」

#### Scenario: 未选择时沿用默认

- **WHEN** 会话未选择档位（或选择「跟随模型默认」）
- **THEN** 请求按服务连接中该模型的默认档构建，与档位能力加入前行为一致

#### Scenario: 模型切换后的档位校验

- **WHEN** 用户切换到另一个不支持当前所选档位的模型
- **THEN** 档位选择回落为「跟随模型默认」并提示，不静默提交非法档位；宿主侧收到不支持的档位时按配置不可用失败

#### Scenario: 配置确认涵盖档位

- **WHEN** 会话已绑定的档位与会话工具栏当前选择不一致（非用户主动变更）
- **THEN** 与模型变化同样要求确认后使用，活动请求不受影响

#### Scenario: 运行冻结档位

- **WHEN** 某次运行创建后用户修改档位，随后该运行被重试或恢复
- **THEN** 重试/恢复使用运行创建时冻结的档位，不采用后续修改
