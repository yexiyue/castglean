# Spec Delta

## MODIFIED Requirements

### Requirement: 宿主拥有消息与工具事实
系统 SHALL 保存有序的 AG-UI 消息和结构化工具事实，包含稳定消息/调用身份、子 Agent 归因、参数、结果及完成或中断状态。前端请求即使携带协议消息历史，也仅能提交新增用户输入及宿主明确授权的中断回答，不得覆盖权威 system、assistant 或宿主工具历史；重复快照和增量不得重复生成消息或工具结果。

#### Scenario: 客户端伪造工具成功
- **WHEN** 客户端携带自造工具结果发起继续请求
- **THEN** 宿主拒绝或忽略非授权历史，仅使用自身持久记录；仅已登记的客户端工具或中断允许按其授权流程提交回答

#### Scenario: 工具结果与候选同时发布
- **WHEN** 工具成功产生可审阅候选
- **THEN** 候选与成功工具结果一致提交，不出现成功引用不存在候选的历史

#### Scenario: 历史中保留子 Agent 身份
- **WHEN** 用户重新打开已完成专业任务的会话
- **THEN** 无需重放模型即可从权威记录恢复消息、工具和子 Agent 分组归属

### Requirement: 历史恢复与流订阅分离
系统 SHALL 支持分页读取权威历史及当前执行身份与游标，再无缺口接入后续 AG-UI 事件；传输游标与协议载荷分离，缓冲不可补齐时重新同步权威消息、状态和运行事实。订阅和重连不得启动模型或重放用户命令，终态对未订阅客户端仍可读取。

#### Scenario: 关闭页面期间完成
- **WHEN** 页面解除订阅后后台执行完成，用户再次打开
- **THEN** 直接显示已保存历史和终态，不再次调用模型

#### Scenario: 历史读取与订阅间有更新
- **WHEN** 读取历史后、订阅建立前后台发布新内容
- **THEN** 通过游标补齐或重新同步得到完整有序视图，不丢失或重复内容

#### Scenario: 重连到部分完成的流
- **WHEN** 客户端丢失了活动运行的消息起始事件
- **THEN** 通过完整恢复边界重建客户端所需生命周期和消息状态，不能把缺少前置事件的任意尾部直接当作新运行消费

## ADDED Requirements

### Requirement: 新旧 agent 数据隔离
系统 MUST 将新 agent 记录与旧 agent 协议按版本隔离，不继续、转换或兼容执行旧 agent 任务。旧记录原样保留且不被队列重新领取；用户工程正文、目录、角色身份、人工修正、声音资产和领域候选不因 agent 协议切换被删除或重写。

#### Scenario: 首次打开旧工程
- **WHEN** 新版宿主打开包含旧 agent 记录的工程
- **THEN** 工程内容与人工结果仍可用，新助手创建独立的新会话；旧任务不自动执行，不将旧历史静默显示为空的新历史

#### Scenario: 旧任务继续请求
- **WHEN** 请求引用旧 agent 会话、检查点、运行或队列任务
- **THEN** 明确拒绝旧执行并说明需新建任务，不调用模型、不删除原记录、不把旧运行转换为新运行
