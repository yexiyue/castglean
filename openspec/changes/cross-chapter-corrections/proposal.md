# 跨章身份与人工修正

## 为什么

单章分析已接受已校验前章上下文，但 CLI 无法保存并继续同一本书，人工修正也没有受修订保护的入口。先建立确定性书级最小闭环，避免将语义不稳定包装成通用 Agent。

## 变更内容

- 新增有序的完整书级 JSON 快照与只读状态，复用已有角色表、正文、章节校验；稳定 ID 与姓名分离，别名查询返回多个候选。
- 追加章节、末章重分析与人工归属/别名修正均核对预期修订、纯构造新状态，通过整体校验后才提交。
- 人工修正记录来源摘要、正式引用和修订；重分析只允许最后一章及原切片，保留已确认人物和片段。
- CLI 增加 analyze 的书级上下文/末章重分析选项、correct 与 inspect；将整书聚合文档发布到新目录，不覆盖已有快照。
- 保留单章入口及格式，暂不做任意旧章重跑、身份合并撤销、恢复缓存、并发写入、声音画像、Agent 或 TRNovel 集成。

## 能力

### 新能力

- `book-state`：有序书级状态、身份获知边界、修订与完整快照提交。
- `human-corrections`：基于来源的人工归属和别名修正、可复核记录及重分析保护。

### 修改的能力

无已同步主规格。

## 影响

core 增加具体书级状态与修正模块，analysis 内部共用追加与末章重分析执行；CLI 装配上下文并发布聚合文件。无需新 crate 或依赖，模型接口、默认提示词、最终章节格式与评测答案不变。
