2026-11-18，macOS Apple Silicon，独立应用标识与公开两章工程。使用 GLM Flash 生成计划和建议，使用本机已就绪的 VoxCPM CPU 与 MOSS Nano CPU 生成试听。

原生复测修复了两个问题。模型省略设计引擎时由宿主预选，实际引擎和设备在批准前展示。已持久化的审批由宿主确定挂起，避免 SDK 停止回合被当成用户取消。

原生验证覆盖 macOS Apple Silicon 以及上述已准备的模型。平台及其他模型组合待独立验收。

补充故障验证：

- 在 Qwen CPU 试听进入运行状态后终止隔离进程。重启记录原运行中断，显式重试后列出未完成条目。初版恢复卡缺少助手消息，按钮不可操作。修复为先保存可恢复消息，再创建无旧工具归属的重试卡。对既有隔离记录补齐这一消息后，实测新尝试成功，原尝试仍为中断，建议只发布一次。
- 替代建议发布后重启。旧预览已回收，已入库 WAV 保留。最新预置试听仍可读取，跨工程和跨建议的音频读取均返回未找到。
- 在隔离库向绑定写入注入 SQLite 错误。已保存资产仍可读取，原绑定修订保持；移除注入后重新确认并重放相同请求，只推进一次绑定修订，音色库仍是一份资产。

## 选角工具 Schema 与修复回归

2026-11-18，一次选角运行连续七次把 `voiceCandidates` 填成字符串数组。宿主在参数解码阶段拒绝，每次只返回 `invalid_audition_plan`，且未扣除修复次数。审批和合成均未开始。

沿用[章节归属分析](../../../docs/desktop-studio/chapter-analysis-validation.md)的做法，两个选角工具从同一宿主类型生成展开的候选 Schema，并说明身份字段和合法形态。字符串候选的回执报告具体数组位置和两种引用示例。参数解码与计划校验共享每轮三次的失败上限。

宿主测试 444 项通过，Clippy 与 OpenSpec 严格验证通过。用当前配置的 `minimax-cn/MiniMax-M3.1-Flash` 和合成目录样例测试生产模型适配器，MiniMax 在一次工具调用中提交了库音色和预置音色，宿主校验通过并生成两个审批条目。该用例止于计划构建，耗时约 114 秒。桌面审批、合成与绑定沿用上文的原生验收记录。


## 审批后的生成进度

2026-11-18 查阅 SQLite 审批回执和引擎日志。用户截图对应批次最终发布了建议，其中五条试听可用。审批答复曾以原始对象写入聊天历史，助手也缺少试听状态投影。Rig Recording 覆盖合成回放测试，本次桌面请求依据应用日志和持久记录核对。

助手现按本次批准尝试显示完成数和失败数，完成后显示正在整理选角建议。批准消息保存摘要。受理和生成前复验只检查选中模型或设计资源，仍核对音色目录和角色身份。提出计划时仍需读取目录资源，以预选可用模型。

使用独立 macOS 应用、GLM Flash 和 Kokoro CPU 的公开样本验证部分批准、生成从 0/1 到 1/1、发布建议、播放 1.99 秒音频以及手动采用旁白绑定。审批受理慢的基线中，全量盘点最慢约 56 秒，期间原请求核对可以恢复同一审批。

更新后的原生构建复测单条 Kokoro 试听。批准后 0.68 秒出现 0/1，12.56 秒到 1/1 并进入整理建议。受理和生成前分别盘点一个就绪模型，耗时 581 和 492 毫秒。新会话完成选角路由。原会话在取消归属后首次提交选角文本，GLM Flash 曾调用归属工具，属于本轮观察到的任务路由偏差。

原生复测还发现，审批继续后的结果引用归属于原选角子任务，助手曾只留下批准消息。结果入口现在显示在发起选角的工具消息下。已从该入口打开同一批次的旁白建议。
