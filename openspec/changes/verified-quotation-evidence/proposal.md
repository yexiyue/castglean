# 提案：可验证的原文引文证据

## 为什么

单章结构成功不能说明人物及归属正确。先补跑冻结 v2，再以可复核引文检查证据来源，避免把单章错误传播到跨章节状态。

## 变更内容

- 补跑本地 Qwen 与国内 MiniMax 的冻结 v2 基线，各 40 例、重复两次。
- 增加可选的原文引文分析模式，默认仍为片段证据模式；程序在指定可见片段内唯一定位引文，生成 UTF-8 字节范围并保存受检证据。
- 引文错误使用同一有限修复入口，预算、取消、终止和失败不发布规则不变。
- 新建独立的网上小说测试组：选取维基文库标明公有领域的作品连续片段，记录固定来源、截取和独立编制的金标，冻结后再调用模型。
- 对同一冻结语料、相同预算进行模式对照，分别报告结构交付、语义、身份对齐、成本与延迟，不预设改善。

## 能力

### 新增能力

- `quotation-evidence`：在可见原文内确定性校验引文、保存证据坐标并有限反馈修复。
- `literary-evaluation`：来源明确、独立冻结的真实小说片段评测与分组报告。

### 修改能力

无。现有变更尚未归档到主 specs；默认模式和既有正文、角色、标注格式保持兼容。

## 影响

涉及 core 的建议协议、校验和版本化扩展，CLI 的模式选择，Python 评测工具及公开报告。保持 AnalysisModel::generate、章节顺序执行及单一 workspace；不增加 Agent、数据库、跨章管理或 TRNovel 集成。引文真实不代表支持语义归属。
