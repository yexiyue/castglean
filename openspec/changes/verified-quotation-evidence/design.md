# 设计：原文引文与独立对照

## 背景

参见 proposal.md。当前建议只引用片段 ID，校验无法判断模型是否引用了实际存在的措辞。角色与片段均已有 extensions；默认提示词为版本 5。

## 目标与非目标

目标：精确且可追溯地定位引文，用冻结语料测量严格校验的收益和代价。非目标：引文蕴含判断、按姓名自动合并、Agent、跨章状态及存储层。

## 决策

1. AnalysisOptions 增加 EvidenceMode，默认 segment_ids；CLI 增加 --evidence-mode segment-ids|verified-quotes。实验模式提示词版本 6，默认仍为版本 5，保持可比较的退路。AnalysisModel::generate 不变。
2. 建议增加可选 evidence_quotes，元素为 segment_id 与 quote，原有 evidence_segment_ids 继续用于通用格式。实验模式要求新角色及 resolved/ambiguous 非空引文；unknown 不需要引文。默认模式遇到提供的引文仍检查，不静默把未检数据标成已验证。每条最多 256 个 Unicode 标量、每项最多 8 条，纯空白和重复引文拒绝；引用片段须可见且位于对应证据列表。
3. 私有 quotation 模块只负责原文定位与保存证据验证。逐 UTF-8 字符边界计算所有可能匹配（含重叠），指定片段内恰好一次才接受；不模糊匹配、不规范化、不接受模型坐标。程序生成 byte range、chapter ID、source hash。
4. 受检引文保存在角色与目标片段的 castglean.quotation_evidence 版本 1 扩展内；完整 validate_book 再检查扩展格式、绑定、范围、原文与相关证据列表。应用步骤只消费 ValidatedWindow；失败不污染上下文或发布目录。
5. 缺失、不可见、未找到、重复出现及大小问题提供固定错误码与程序路径，沿用已有次数及请求预算；不回传引文原文作为错误消息。引文真实不证明归属。
6. Python 评测沿用独立章内匹配与完整失败分母。新增真实小说 suite 类型（六个连续片段、三部作品、各两例，全部 supplemental），使用相同 Schema/应用校验、摘要冻结和来源验证；与 40 例开发/留出套件分别评分。真实小说可能已出现在模型训练中，不能当泛化留出集。
7. v2 基线和引文模式各后端 40 例重复两次；真实组各后端各模式六例重复一次。每后端串行、不回退；1000 字符/8 片段、8 请求、1 次修复、120/600 秒、2048/8192 输出 token。基线保留旧二进制和源码摘要，实验独立构建；执行清单记录实际模式、版本和已锁定二进制。

## 风险与权衡

- 引文增加输出长度、截断与失败 → 使用相同预算公开交付率与失败类型，不用增大预算掩盖代价。
- 原文存在但语义无关 → 不把校验标记当语义正确，使用联合归属和身份指标复核。
- 真实小说字形与匿名群体复杂 → 保留源文本、明确标注理由，不把无锚点群体变成人物，也不依据模型结果修订金标。

## 迁移

旧 JSON 和默认调用继续接受。验证过的证据使用已有扩展容器，旧产物无扩展仍有效。实验收益不足时继续使用默认模式，无须迁移原文或人工确认身份。
