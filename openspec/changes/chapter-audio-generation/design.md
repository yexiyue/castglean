# Design

## 上下文

- 采用分析 = `analysis_states.current_version_id` 指向的不可变 `AnalysisVersion`；segment 覆盖整章无遗漏/重叠是存储不变式（`chapter_analysis::validation`），segment `range` 是源文件绝对 UTF-8 字节偏移。
- 声音绑定 = `voice_bindings` 每目标一行，`VoiceRef::Preset{backend,model,voice}` 或 `Library{id}`；`voice: null` 表示解绑。后端此前没有"绑定 → 可合成音色"解析（在前端试听路径），本变更把该解析移入宿主章节音频域。
- 现有短试听（`voices/studio`）：IPC 限 500 字符、累计 30 s/16 MiB PCM、纯内存任务、重启即失，明确不作为章节生成的基础循环；复用的是其底层执行能力（引擎线程、`Engine::load/synthesize`、PCM 收集、watch 取消、WAV 编码、受控媒体协议模式）。
- TaleChime Kokoro：预置 100 中文音色，24 kHz 单声道；后端自动分段 ≤510 字符/段，单次 forward 受 512 音素与 30 s 采样预算约束（约 4.6 字/秒）。库音色克隆 `cloning=false`。

## 目标 / 非目标

目标：一章已分析、已绑定的章节，点"生成本章"后宿主确定性产出整章音频并连续播放；失败/取消/重启不假报成功、不丢已保存单元。

非目标：失败后自动重试（无用户动作）、修正后安全重做、候选采用、WAV 导出、整书队列、多后端混用、读音/演绎参数、进度百分比估算、跨进程恢复引擎内部推理。用户再次点击生成的同指纹断点续跑（D8）在目标内。

## 决策

### D1：合成单元由宿主构建，逐单元调用引擎

一个分析 segment 按句读边界切分为 ≤120 字符的合成单元（单元字节范围精确分区 segment 范围，相邻单元范围连续无重叠；无句读边界时在字符边界硬切；纯空白 segment 产生 `empty` 单元，不合成但保留覆盖映射）。每个单元一次 `Engine::load` 会话内的 `synthesize(text, voice)` 调用。

理由：单元边界即进度、失败定位、持久化与取消粒度，直接满足验收；120 字符位于 Kokoro 单次 forward 预算内（≈26 s @ 4.6 字/秒 < 30 s，音素 ≤512），且"按实际模型限制切分长文本"由宿主显式拥有。不使用 TaleChime plan/spans 多音色路径：它无法提供单元级完成事实，与逐单元持久化/部分完成语义冲突。

### D2：单一就绪预置组合，绑定解析在宿主

生成前收集全部目标（旁白 + 本章 Resolved 角色）的绑定；要求全部为 `Preset` 且指向同一 `(backend, model)`，该组合 `ResourceState::Ready`，且每个音色 id 在该模型 `voice_catalog` 中。库音色、跨后端/跨模型绑定、未就绪资源均列为阻塞（第一阶段不兼容），不回退、不自动换声。设备固定 `Cpu`（已验证组合）；语速/风格用引擎默认。

### D3：任务持久化与运行模型

- 新表 `chapter_audio_runs`（一次生成）与 `chapter_audio_units`（单元，含字节范围、目标、实际音色、状态、媒体 id、时长）；schema v5。
- 启动命令：前置检查 → 无阻塞则在单事务写入 run（queued）与全部 unit（pending/empty）→ 派发到引擎线程（新 `EngineRequest::Chapter` 变体，`spawn_local` 执行，与试听共用 `studio_gate` 串行）→ 返回快照。全局同一时间至多一个活动 run；同章或他章已有活动 run 时拒绝。
- 执行：引擎一次加载，按序合成单元；每单元 PCM 收集（单元级上限 ~180 s/64 MiB，超限即该单元失败）→ 16-bit WAV 临时文件原子落盘 → 事务更新 unit 行与 run 计数 → 发事件。单元间检查取消。
- 取消：DB 先行原子记录 `cancelling`，内存 watch 通知道执行循环；已开始的单元完成合成、落盘并提交后停止，终态 `cancelled`，已完成单元保留。等待引擎闸门时可直接取消；终态不得被迟到的取消或阶段更新覆盖。
- 事件：`chapter-audio-update`（payload=run 视图：状态、阶段、已完成/总单元、失败单元索引、错误）；前端另有快照查询命令，事件丢失以快照兜底，不伪造进度。
- 重启：初始化时把 `queued/running/cancelling` 的 run 标为 `interrupted`，单元状态原样保留；不自动重跑、不恢复在途推理。重新生成由用户显式发起，按 D8 判断续跑或创建新 run。

### D4：产物与播放

- 产物目录：应用数据目录 `chapter-audio/<run_id>/unit-<index>.wav`；全部必要单元成功后按序拼接 `chapter.wav`（同格式 24 kHz 单声道 16-bit；拼接时逐文件流式复制样本，不整章载入内存），记录总时长并发布。
- 媒体访问：新 `chapter-audio` 自定义协议，仅解析数据库签发过的 32-hex 媒体 id（unit 与整章各有 id），启动时从 DB 重建 id → 文件映射，文件缺失则不注册（播放得到明确 404，不伪造可用）。
- 播放：章节音频面板内联播放条（播放/暂停、时间、进度），与现有声音播放器互斥（任一侧开始前停止另一侧）；不做波形图与字级对齐，定位只到单元范围。

### D5：阻塞呈现

阻塞按类型聚合（无分析、未知归属、歧义、缺绑定、音色不兼容、资源未就绪、绑定组合不一致），每条带章内行号、segment id 与目标（角色名）定位信息；前端集中展示并提供"定位到正文行 / 打开角色中心"入口。待检查项（unreviewed）不阻塞生成。

### D6：执行文本规范化（2026-11-11 真实失败案例）

单元送入引擎前经宿主纯函数规范化：单元内换行/全角空格/不间断空格 → 普通空格并压缩连续空白；Kokoro 前端不支持的符号映射到最近支持符号（单引号→双引号、`『』〈〉[]`、`–~` 等），间隔号删除，其余集合外符号清除。只改执行文本，不改原文与单元范围（原文不可变）。实测矩阵与踩坑记录：`docs/knowledge/lessons/kokoro-frontend-text-constraints.md`。理由：Kokoro 前端把单元内换行当音素、把集合外符号当未知词而直接失败，真实章节（段首全角缩进 + CRLF + 单引号）必然触发；映射而不是报错，因为这类符号在中文小说中高频且语义中立。

### D7：失败详情落库（error_detail，schema v6）

`error` 保持宿主稳定失败码（前端文案映射的依据），新增 `error_detail` 列（runs/units）保存引擎/IO 原始信息截断 500 字符，仅诊断用途，不进界面、不进事件；失败同时 `eprintln!` 到进程 stderr。理由：应用尚无日志系统，2026-11-11 真实失败一度只能靠读数据库还原；先保证可诊断，应用级日志系统是独立后续工作。

### D8：同指纹断点续跑（2026-11-11）

再次生成时，若最近一次终态（failed/cancelled/interrupted）任务与当前计划的冻结输入完全一致——分析版本、来源哈希、后端/模型、逐单元（范围、音色、目标列、空白标记）——则复用该任务：失败/未开始单元重置为 pending，已完成单元音频原样保留，`completed_units` 从实际 done 数重计；任何不一致自然回退为全新任务（重分析、改绑定、换模型都会改变指纹，不产生混配音频）。理由：161 单元的长章失败后从头再来不可接受；指纹比对全部用已有持久化字段，不引入新状态。

## 风险与边界

- 真实语速与预算：若个别单元实际音频仍超后端 30 s 预算（超长无标点文本），该单元失败并如实报告；不做自动再切分重试（留待单章闭环阶段）。
- 引擎互斥：章节生成期间拒绝试听/设计/资源准备/验证/设置变更，反向亦然；互斥在引擎线程与命令入口双侧检查。
- 磁盘增长：多个 run 的单元与整章 WAV 会累积；清理规则属后续决策，本阶段仅持久保留。
- 单元间衔接：不在拼接时插入额外静音，句读停顿依赖模型自身；跨单元听感在真实验收中记录，必要时后续调整。
