## Decisions

- 使用共同内容边距和组内间距。以正文、当前阶段、主要结果动作建立顺序，工具细节与元信息使用较低强调度。
- 固定输入操作区，通过分隔线与滚动对话区区别。审批、恢复与其他任务内容保留自然滚动位置，返回审批时聚焦目标。
- 选角候选复用共享 Base UI 折叠和按钮，列表行使用细分隔线。收起时保留可扫描的角色、绑定状态和候选数量。
- 窄窗优先保留输入、发送、停止、模型身份和待确认动作。思考档位的文字可收缩，完整语义由提示和无障碍名称提供。

- 2026-11-27，更新上下文用量、错误提示、活动折叠、模型选择、原文引用、会话列表与审批动作的组件。使用 assistant-ui registry 的展示结构与 Base Nova 控件。模型搜索和历史搜索用共享 Combobox，接项目配置与宿主会话列表。用量图表只在宿主用量与窗口容量均已知时渲染。
- 任务和结果使用平面行，只有列表分隔、引用定位和输入控件需要边线。活动折叠承载用户可见摘要，进行中继续用 Thinking Indicator。选角进度和回复结果沿用 AG-UI 的挂载身份。审批字段、提交回执与结果采用走原宿主路径。

- 视觉优先级复核将卡片用于可审阅的领域结果与待确认表单，用标题、状态、数据和操作明确阅读顺序。普通消息和活动提示留在会话表面。归属把查看原文放在首位，候选采用与放弃保持就地可用。
- 展开的选角任务先呈现待确认表单，过程步骤跟在后面。未勾选项显示试听文本摘要，选中的可用项展开编辑，取消选择保留该文本草稿。

- 选角设计在所属回复下按角色展开。手动生成的草稿、宿主进度与候选按工程、建议运行及目标隔离，在当前桌面会话内重开可读回。已批准的设计试听按宿主结果引用读取，入库与绑定继续由宿主确认。
- 采用 assistant-ui Media Player 的就地播放模式和 Run Activity 将决策留在可见区的做法。通用媒体播放器接收 URL；本项目继续使用本地音频租约和共享单音源控制器。角色中心作为独立管理入口，相关草稿校验和保存绑定能力共用。
