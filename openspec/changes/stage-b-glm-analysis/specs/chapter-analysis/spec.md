# Spec Delta

## Purpose

提供独立于模型厂商和消费方的单章小说分析能力。程序维护不可变正文、完整分区与稳定引用，模型提供角色和归属建议，经应用校验后形成候选结果，供库使用方或 CLI 显式保存。

## ADDED Requirements

### Requirement: 解析诊断分类
系统 SHALL 区分 JSON 语法错误和合法 JSON 的建议结构错误，并保留现有业务引用校验；错误 SHALL 不包含原始输出、字段值或私人正文。

#### Scenario: 合法 JSON 但缺失字段
- **WHEN** 响应可解析为 JSON 但缺少必须建议字段
- **THEN** 返回建议结构错误，而非 JSON 语法错误

### Requirement: 程序负责原文分区
系统 SHALL 按版本化确定性规则分配片段 ID 和 UTF-8 范围，完整保留正文及空白。模型 SHALL 只引用片段，不返回正文修改或正式坐标。

#### Scenario: Unicode 与重复台词
- **WHEN** 正文含中文、emoji、空行和重复台词
- **THEN** 片段按序重建完整正文，ID 唯一且重复执行一致

### Requirement: 单次联合建议与顺序上下文
系统 SHALL 在关闭校验反馈修复的单次模式中，每个目标窗口一次获取角色和归属建议，附带相邻片段与已接受角色。系统 SHALL 拒绝重复、遗漏或非目标片段标注，以及不存在的角色和证据引用。

#### Scenario: 后续窗口引用已发现角色
- **WHEN** 首个窗口发现角色且建议通过校验
- **THEN** 后续窗口可引用程序分配的正式角色 ID，同名角色不自动合并

#### Scenario: 建议引用错误
- **WHEN** 关闭校验反馈修复时，模型遗漏目标片段或引用不存在的证据
- **THEN** 分析失败，不返回可保存结果

### Requirement: 未知与正式结果边界
系统 SHALL 保留未知、歧义及未人工确认状态，分配正式角色 ID 后通过阶段 A 的完整校验。已有已校验上下文 SHALL 显式提供，现有角色信息及人工确认 SHALL 保留，重复分析已有章节 SHALL 拒绝。

#### Scenario: 无法确定发言者
- **WHEN** 模型返回未知发言者
- **THEN** 结果保留 unknown，不新造旁白角色替代

#### Scenario: 已有证据上下文
- **WHEN** 调用方提供已校验书籍及一个新的章节
- **THEN** 候选书籍保留已有角色与章节内容，统一修订引用后整体校验，输入对象不变

### Requirement: 有限执行与取消
系统 SHALL 限制目标窗口、请求数、单请求输入字节、输出 token 和响应字节，处理超时、取消、截断与无效 JSON。关闭校验反馈修复时无自动重试，失败 SHALL 不提交或发布部分产物。

#### Scenario: 取消后响应迟到
- **WHEN** 请求中取消分析，随后模型完成
- **THEN** 调用返回取消错误，不接受迟到结果

#### Scenario: 请求预算不足
- **WHEN** 所需窗口超过请求预算
- **THEN** 在模型调用前失败

### Requirement: 基线可测
系统 SHALL 用可公开中文样例记录归属正确率、已确定结果准确率、未知或歧义比例、请求数、可用 token 和耗时，区分确定性替身检查与真实模型质量。

#### Scenario: 真实分析基线
- **WHEN** 使用 GLM 分析公开样例
- **THEN** 保存不含密钥的基线报告，语义错误如实计入而非作为结构校验成功
